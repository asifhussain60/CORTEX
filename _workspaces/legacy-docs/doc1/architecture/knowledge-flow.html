🎯 Flow Stages Explained

🚪 Entry: Request Classification

Components: User Request → Intent Classifier → MasterOrchestrator

Purpose: Route incoming requests to appropriate orchestrators using pattern matching, LLM classification, or capability mapping.

  • Pattern-based: Regex match on keywords (e.g., "implement" → TDD-Master)
  • LLM-based: Fuzzy intent classification when patterns fail
  • Capability-based: Search for orchestrators with matching capabilities
📚 Governance Loading & Merging

Components: GovernanceMerger → 4 Tiers → Rule Merger

Purpose: Load and merge governance rules from all 4 tiers with conflict resolution.

🔥 Tier 0: CORTEX_CORE

Source: cortex-brain/tier0/governance/core-rules.yaml

Content: 19 immutable SKULL rules

Precedence: HIGHEST - wins all conflicts

Examples: CORE-001 (incremental execution), CORE-019 (TDD enforcement)

📋 Tier 1: BUSINESS_TIER_0

Source: cortex-brain/tier1/tracking/

Content: Active epic, AC-INDEX, progress tracking

Precedence: HIGH - provides current context

Examples: Current sprint requirements, acceptance criteria

🏗️ Tier 2: COMPANY_PRACTICES

Source: cortex-brain/tier2/

Content: Engineering standards, quality gates

Precedence: MEDIUM - enforces company policies

Examples: PEP8, SOLID principles, code review checklists

🧠 Tier 3: KNOWLEDGE_PRACTICES

Source: cortex-brain/tier3/

Content: Learned patterns, performance insights

Precedence: LOW - suggests optimizations

Examples: "UserAuth took 2.3x longer than estimated"

Conflict Resolution Logic
if TIER0.rule conflicts with TIER1/2/3.rule:
    return TIER0.rule  # SKULL always wins

if TIER1.requirement conflicts with TIER2.standard:
    merge both, prioritize TIER1 for scope, TIER2 for quality

if TIER3.suggestion conflicts with TIER2.standard:
    return TIER2.standard  # Enforced > Suggested
✅ Validation & Planning

Components: Request Validator → Planning Orchestrator → TodoManager

Purpose: Ensure request is safe, break it down into tasks, persist state.

Validation Checks:

  • SKULL Compliance: Does request violate any CORE rules?
  • Security Approval: Does request require elevated privileges? (AC-SECURITY-005)
  • Path Sandboxing: Are all file paths within allowed directories? (AC-SECURITY-006)
  • Token Budget: Will operation exceed token limits? (CORE-001)

Planning Breakdown:

  • Generate AC-IDs: Assign acceptance criteria identifiers
  • Dependency Resolution: Topological sort of tasks
  • Effort Estimation: Use Tier 3 insights for time estimates
  • Todo Creation: Persist to progress-tracker.json

🧪 TDD-Master Workflow (Knowledge Injection)

Components: TDD-Master → RED → GREEN → REFACTOR → Best Practice Injector

Purpose: Generate code using test-driven development with best practice injection at refactor phase.

Phase 1: RED - Write Failing Test

Knowledge Source: Tier 1 (Business requirements)

  • Load AC-ID acceptance criteria from AC-INDEX.yaml
  • Generate test case that validates AC-ID requirements
  • Run test → expect failure (no implementation yet)

Phase 2: GREEN - Minimal Implementation

Knowledge Source: None (minimal code to pass)

  • Write simplest code that makes test pass
  • No optimization, no best practices yet
  • Run test → expect success

Phase 3: REFACTOR - Apply Best Practices

Knowledge Source: Tier 2 (Engineering standards) + Tier 3 (Learned patterns)

  • Tier 2 Injection: PEP8 formatting, SOLID principles, design patterns
  • Tier 3 Suggestions: "Similar function in src/utils/auth.py has better error handling"
  • Apply refactorings while keeping tests green
  • Generate evidence bundle (test results, coverage, audit logs)
Best Practice Injection Example
# GREEN Phase (minimal):
def authenticate(username, password):
    if username == "admin" and password == "pass":
        return True
    return False

# REFACTOR Phase (Tier 2 standards applied):
from typing import Optional
from src.models.user import User
from src.security.hash import verify_password

def authenticate(username: str, password: str) -> Optional[User]:
    """
    Authenticate user with username and password.
    
    Args:
        username: User's unique identifier
        password: Plaintext password to verify
    
    Returns:
        User object if authenticated, None otherwise
    
    Raises:
        ValidationError: If username/password format invalid
    """
    user = UserRepository.find_by_username(username)
    if not user:
        return None
    
    if not verify_password(password, user.password_hash):
        return None
    
    return user
🔐 Evidence, Audit, State

Components: Evidence Bundle → EnhancedAuditLogger → State Manager → Response

Purpose: Generate proof of completion, log to audit trail, persist state, return to user.

Evidence Bundle Contents:

  • Test Results: All test runs with pass/fail status
  • Coverage Reports: Line/branch coverage percentages
  • Audit Logs: Correlation ID tracking entire operation
  • Git Diffs: Files changed, lines added/removed
  • Performance Metrics: Execution time, token usage

Audit Trail (Hash Chain):

Each operation generates a hash chain entry for tamper detection:

Entry N:
  timestamp: 2026-01-10T16:30:45Z
  correlation_id: a1b2c3d4-...
  ac_id: AC-TDD-001
  operation: "TDD cycle complete"
  previous_hash: "0x9f8e7d..."
  current_hash: sha256(entry_data + previous_hash)

State Persistence:

  • progress-tracker.json: Active todo, phase status, completed ACs
  • governance.db: SQLite with WAL mode for concurrent access
  • Atomic Updates: Write to temp file, validate, atomic rename
