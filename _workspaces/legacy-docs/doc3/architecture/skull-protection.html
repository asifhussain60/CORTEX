CORTEX-5.0: REFACTOR Task Enforcement

📋 Sub-Plan 07: REFACTOR Task Enforcement is a planned enhancement for CORTEX-5.0 that extends SKULL protection with mandatory final cleanup phases in all plans.
🚀 New Rule
REFACTOR Task Enforcement
Rule: Every planning manifest MUST include a final REFACTOR phase (typically Phase 12) that enforces SKULL whole-file cleanup rules. This prevents half-implemented changes, dead code accumulation, and ensures every plan completes with a clean codebase state.

Enforcement Scope:
  • Dead code removal (orphaned functions, unused imports)
  • Duplicate elimination (merge redundant implementations)
  • Comment cleanup (remove TODO/FIXME markers)
  • Test coverage validation (≥80% for modified files)
  • Documentation sync (update docstrings, READMEs)
  • Git checkpoint creation (final commit with cleanup summary)

Acceptance Criteria: REFACTOR phase must be present in acceptance-criteria.yaml as final_refactor_required: true. Plans without this flag will fail validation.

Status: ⏸️ BLOCKED - Waiting for Gate 1 (≥50% test coverage)
Status: Planned

Benefits

  • Zero Technical Debt: Every plan ends with a clean state—no leftover scaffolding or debug code
  • Enforced Hygiene: Automated whole-file cleanup eliminates manual review burden
  • Predictable Completion: Plans have clear Definition of Done with measurable cleanup criteria
  • Integration with CI/CD: REFACTOR phase can trigger automated quality gates before merge
