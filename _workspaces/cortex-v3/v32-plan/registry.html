Current State Diagnosis

The cortex-registry currently contains 802 YAMLs across 23 top-level directories, exhibiting multiple sprawl patterns that compromise governance and discovery.

Directory Breakdown (Top 10)

  • planning/ — 200 YAMLs (largest, no expiry policy)
  • knowledge/ — 174 YAMLs
  • workflows/ — 143 YAMLs
  • company/ — 67 YAMLs
  • governance/ — 54 YAMLs
  • core/ — 41 YAMLs
  • templates/ — 35 YAMLs
  • patterns/ — 24 YAMLs
  • config/ — 13 YAMLs
  • 13 additional directories (< 10 YAMLs each)

Critical Sprawl Symptoms

  1. Template duplication: Templates exist in 4 locations — artifacts/templates/, metrics/dashboards/templates/, templates/, workflows/templates/
  2. Governance fragmentation: Rules and policies scattered across governance/, rules/, and core/
  3. Phase directory duplication: Phases in .archive/cortex-master-v1/phases/, artifacts/templates/phases/, planning/phases/
  4. Loose files at registry root: cortex-master-v2.yaml and yaml-reader.html violate namespace conventions
  5. Missing metadata: 90% of YAMLs lack schema_version and namespace fields
  6. No TTL on planning YAMLs: 200 completed plans never archived — no cleanup mechanism

Registry Taxonomy Guidance

A 5-rule governance model that prevents sprawl while preserving all existing work.

Rule 1: Taxonomy Freeze

No new top-level directories without a new ADR. The current 23 directories are consolidated to 8 canonical namespaces. Any write operation attempting to create a top-level directory outside these 8 will fail with a governance error.

Rule 2: Schema-First YAML Creation

Every new YAML must declare two required fields:

schema_version: "1.0" namespace: company|governance|knowledge|planning|workflows|config|specs|_archive

The CORTEX registry_manager.py MCP tool validates these fields before any write operation. YAMLs without front-matter fields are flagged as UNREGISTERED on next convergence gate run.

Rule 3: No Loose Files at Registry Root

The registry root may only contain a README.md and the cortex-master-v2.yaml index file. No other YAMLs, HTML files, or text files are permitted.

Rule 4: TTL Policy (Time-to-Live)

Every YAML in planning/ must declare one of:

status: ACTIVE # no TTL, reviewed quarterly status: COMPLETED # auto-archived 30 days after completion_date expires_after: "2026-06-30" # auto-archived on date

During convergence gate, any planning/ YAML with status: COMPLETED and completion_date older than 30 days is automatically moved to _archive/.

Rule 5: Duplicate Detection on Write

Before any new YAML is written, CORTEX checks if a YAML with the same (namespace + entity_type + entity_name) already exists. If yes, the write is rejected and the path to the existing file is returned. This prevents accidental creation of near-duplicate plans.

8 Canonical Namespaces

This appendix proposes consolidating 23 top-level directories into 8 clearer namespaces, each with explicit scope and ownership.

  1. company/ — External-facing registry (repos/, domains/, infrastructure/, dashboards/). Absorbs: existing company/.
  2. governance/ — All rules and policies (core-rules, skull-rules, compliance, security, gates, audit-checklists). Absorbs: governance/ + rules/ + core/ (merge all three).
  3. knowledge/ — Domain knowledge base (domains, archetypes, best-practices, glossary, sdlc, security, testing-validation). Absorbs: existing knowledge/ (unchanged).
  4. planning/ — Decisions, phases, roadmaps (with TTL enforcement). Absorbs: existing planning/ (add TTL).
  5. workflows/ — All workflow templates (templates/, patterns/, components/). Absorbs: workflows/ + artifacts/ + templates/ + metrics/dashboards/templates/ (merge all 4 template locations).
  6. config/ — System configuration (system config, memory, metrics, cowork-setup). Absorbs: config/ + memory/ + metrics/ + cowork-setup/.
  7. specs/ — Formal specifications (HTML view specs, theme specs, schema definitions). Absorbs: specs/ + html-views/.
  8. _archive/ — Read-only versioned history (completed plans auto-moved by TTL). Absorbs: .archive/ (renamed with underscore for sort-to-top visibility).

TTL Policy in Practice

The TTL enforcement mechanism ensures the 200 planning YAMLs remain curated and live.

Example 1: Active Plan (No Expiry)

schema_version: "1.0" namespace: planning status: ACTIVE entity_type: architecture-plan entity_name: cortex-v3.2-unified-plan reviewed_at: "2026-03-27"

Action: No expiry. Plan remains visible and is reviewed quarterly during convergence gates.

Example 2: Completed Plan (Auto-Archive in 30 Days)

schema_version: "1.0" namespace: planning status: COMPLETED completion_date: "2026-02-15" entity_type: migration-plan entity_name: python-to-mcp-migration # → auto-archived to _archive/ on 2026-03-17 by convergence gate

Action: On convergence gate (after 2026-03-17), this YAML is automatically moved to _archive/planning/. Logged in sweep-log.yaml.

Example 3: Expiry Date Plan

schema_version: "1.0" namespace: planning status: ACTIVE expires_after: "2026-06-30" entity_type: roadmap entity_name: q2-2026-roadmap

Action: Plan is visible until 2026-06-30. On convergence gate after that date, it is auto-archived.

Running the TTL Sweep

# Dry-run first: python scripts/run_registry_sweep.py --ttl-archive --dry-run # Execute: python scripts/run_registry_sweep.py --ttl-archive

All archived files are logged to _archive/sweep-log.yaml with timestamp and reason (completed or expired).

Implementation Plan

This appendix can be rolled out in four phases without deleting any existing YAMLs.

Phase 1 (P3, Week 1): Tag Existing YAMLs

# Dry-run: python scripts/tag_existing_yamls.py --add-namespace --dry-run # Execute: python scripts/tag_existing_yamls.py --add-namespace # Commit: git commit -m "chore: add schema_version + namespace to all registry YAMLs"

Expected impact: ~802 files tagged with required front-matter fields. No deletions.

Phase 2 (P3, Week 2): Merge Duplicate Directories

  • Merge governance/ + rules/ + core/ → new consolidated governance/ directory
  • Merge artifacts/templates/ + metrics/dashboards/templates/ + templates/ → workflows/templates/
  • Rename .archive/ → _archive/ (for top-level sort visibility)
  • Update all namespace references in cortex-master-v2.yaml

Phase 3 (P3, Week 3): Enable Enforcement

  • Update registry_manager.py with namespace validation (reject writes to non-canonical directories)
  • Add convergence gate step: run_registry_sweep.py --validate-namespaces
  • Enable duplicate detection on write (reject if entity already exists)

Phase 4 (Ongoing): TTL Sweep in Convergence Gate

  • Every convergence gate run executes run_registry_sweep.py --ttl-archive
  • Archived files logged with timestamp and reason to _archive/sweep-log.yaml
  • No manual cleanup required

Risk Mitigation

No YAML is deleted — only re-tagged and re-organized. All existing functionality is preserved. Dry-run flags allow safe validation before execution. Phases are sequential to allow rollback at each stage.
