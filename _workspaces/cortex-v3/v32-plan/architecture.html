4-Layer Architecture Stack

The v3.2.0 architecture is organized into four distinct layers, each with clear responsibilities and interfaces. These layers work together through the MCP protocol, creating a clean separation of concerns.

The Four Layers (Bottom to Top)

  • Layer 4 — Foundation: Python Orchestrators (381 files) — stateful TDD engine with state machines, RCA SQLite persistence, WorkflowComposer, and SKULL/CORE enforcement. PERMANENTLY KEPT. Never deprecated.
  • Layer 3 — Tools: MCP Tool Layer (74 files / 35 logical tools) — the bridge between stateless agents and stateful orchestrators. Thin Python wrappers that expose orchestrator logic via the MCP protocol.
  • Layer 2 — Intelligence: Agent Layer (.github/agents/*.agent.md) — conversational, stateless, markdown-defined agents. 10+ agents post-Phase 2. Handle intent routing, response formatting, and delegation coordination.
  • Layer 1 — Surface: Claude Code CLI + VS Code Extension — user-facing interfaces. Two primary surfaces in v3.2.0, providing a unified entry point for all CORTEX operations.

The Core Rule

Agents NEVER bypass the MCP layer to call orchestrators directly. All communication flows through the MCP protocol, maintaining isolation and enabling consistent audit trails, state validation, and DoR enforcement at every interaction.

Architecture-1

Agent + Engine Complement Pattern

The core architectural insight of v3.2.0: agents and Python MCP tools are complements, not competitors. They excel at different things and work together seamlessly.

What Each Layer Does

Agents (Stateless): They handle conversation flow, intent interpretation, response formatting, and delegation routing. Written as markdown files, they define how the system talks to users and decides which operations to invoke.

Python MCP Tools (Stateful): They execute the actual work — maintaining TDD state machines, persisting RCA investigations to SQLite, composing multi-step workflows via WorkflowComposer, and enforcing SKULL/CORE compliance checks. This is where the real engineering lives.

The Right Model vs. The Wrong Model

Wrong Approach (v3.1 thinking): "Replace Python with agents." Try to move everything to markdown and let agents do all the work. This loses state, fails to enforce compliance, and breaks audit trails.

Right Approach (v3.2): "Agents route; Python executes stateful operations." Agents decide what to do and how to present results. Python handles state, persistence, and enforcement. Clean separation of concerns.

Code That Stays Python Forever

  • audit_orchestrator.py — RCA + SQLite persistence
  • approval_gate.py — DoR enforcement and state management
  • autonomous_plan_executor.py — multi-step workflow coordination
  • challenge_engine_plugins.py — behavioral validation
  • All files in strategies/ directory — domain-specific orchestration logic
Architecture-2

LENS Intelligence Pipeline

Every request flows through a 4-stage diamond called LENS. This pipeline synthesizes context, validates intent, applies intelligence analyzers, and dispatches execution—all while enforcing DoR gates at critical junctures.

The Four Stages

  • Stage 0 (Hidden): Context Synthesis — load prior session data, synthesize current request, token-optimize to ≤2000 tokens to fit Claude's context window.
  • Stage 1: Interaction + DoR (InteractionOrchestrator) — comprehend the request and validate DoR compliance. If DoR < 100%, block and escalate to user.
  • Stage 2: Intent Routing (IntentRouter → 34 intent types) — classify the request. Confidence ≥0.85 = direct route. 0.60–0.84 = route + clarification. <0.60 = ask user to rephrase.
  • Stage 3: Intelligence (LENS — Language, Examination, Navigation, Synthesis) — apply 8 specialized analyzers auto-selected based on intent type. Each produces structured insights.
  • Stage 4: Execution — domain orchestrator via WorkflowComposer templates. Execute the plan and collect evidence.

Post-Phase 2 Evolution

IntentRouter and response formatting steps become agent-defined, routing to cortex-code.agent.md, cortex-orchestrate.agent.md, cortex-diagnose.agent.md, etc. The execution layer remains Python, preserving state and compliance enforcement.

Confidence-Based Routing Logic

The IntentRouter assigns a confidence score (0–1) to each classified intent:

  • Confidence ≥ 0.85: Direct route to the intent's orchestrator.
  • Confidence 0.60–0.84: Route the intent + request clarification from the user to refine understanding.
  • Confidence < 0.60: Ask the user to rephrase their request in clearer terms.
