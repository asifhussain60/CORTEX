CORTEX Cohesiveness Audit Prompt
Objective

To ensure that the CORTEX system functions as a single integrated brain where all orchestrators and components operate cohesively and deliver maximum value on internal CORTEX tasks as well as on production development repositories. The prompt instructs CORTEX to systematically audit orchestrator interactions, verify contracts, and test end‑to‑end workflows across the environment.

Instructions to CORTEX

Load and Validate the Wiring Contract

Use the Git‑backed registry file (__wiring_contract__.yaml) to load the list of active orchestrators. Each orchestrator must have a unique priority, declared capabilities and dependencies. Check for duplicates, missing registrations or incorrect priority ranges (1‑199). Confirm that deprecated orchestrators are disabled after their sunset date.

Ensure that each orchestrator implements the OrchestratorBaseProtocol and exposes required methods (execute, can_handle, validate, health_check). Report any contract violations or missing methods.

Evaluate Orchestrator Cohesion and Dependencies

Iterate through all core, domain, support, super and infrastructure orchestrators (21 active in total). For each orchestrator:

Verify that the declared capabilities in the registry align with its purpose (e.g., TDDOrchestrator handles IMPLEMENT/FIX and enforces the RED→GREEN→REFACTOR cycle; RefactoringOrchestrator should improve existing code).

Confirm that dependencies listed in the registry (such as EnforcementOrchestrator and LENSSynthesis for TDD) are registered and healthy.

Check that priorities reflect the execution order described in the hierarchy (Master=10, IntentRouter=20, etc.). Flag any priority conflicts or missing orchestrators.

Examine Cross‑Orchestrator Communication Patterns

Review the context object passed through orchestrators, ensuring required keys are present and that orchestrators append rather than overwrite context fields.

Test the sequential pipeline (RequestRephrase→IntentRouter→Master→Target orchestrator→Enforcement→Interaction) with representative requests for each intent (IMPLEMENT, FIX, ANALYZE, PLAN, REFRACTOR, AUDIT, etc.) to ensure smooth hand‑offs and that the correct orchestrator is invoked.

Evaluate parallel fan patterns within LENSSynthesis and other orchestrators to ensure sub‑analyzers run asynchronously and time‑outs do not block the pipeline.

Check conditional routing thresholds on IntentRouter (confidence >0.85 direct, 0.60–0.85 with clarification, <0.60 to ConversationOrchestrator) to ensure that requests are correctly routed.

Run Holistic Validation and Governance Checks

Before executing any tier‑0 intent (IMPLEMENT/FIX/REFACTOR/AUDIT), run the Holistic Validation Gate as described in the MasterOrchestrator responsibilities. This gate includes registry consistency, context pre‑warming, dependency analysis, regression risk, architecture drift, challenge gate and CORTEX self‑analysis. Confirm that results are logged and that FAIL/WARN/BLOCK outcomes behave correctly.

Verify that governance rules (CORE‑008 for TDD, etc.) are enforced. For example, ensure that TDDOrchestrator always creates a failing test before implementation and that tests are present before committing.

Health and Performance Monitoring

Query each orchestrator’s health endpoint and confirm status, uptime, request counts and latency metrics. Ensure that circuit‑breaker logic is in place to handle failures and that degraded or fallback modes engage appropriately.

Compare observed latencies to the expected targets for core, domain, support and super orchestrators. Identify bottlenecks or orchestrators operating outside of their performance envelopes.

Integration with Production Development Repositories

Use CORTEX’s LENS and UnifiedAnalysis capabilities to analyze current production dev repositories (the user’s codebase). Confirm that orchestrators can clone, analyze and refactor code, generate tests, and commit changes through the standard pipeline.

For each orchestrator, perform at least one representative task on the production dev repo (e.g., TDD implements a missing feature with tests; RefactoringOrchestrator cleans up legacy code; PlanningOrchestrator produces a roadmap). Check that outputs are consistent with internal guidelines and that cross‑orchestrator calls (e.g., TDD requesting LENS analysis) succeed.

Report Findings and Recommendations

Summarize any discrepancies, broken interactions, missing registrations or performance issues.

Provide actionable recommendations to maximize internal cohesion (e.g., adjusting priorities, refining dependency declarations, adding tests for new orchestrators, updating wiring contract).

Highlight any areas where orchestrator capabilities do not fully leverage other CORTEX components and propose ways to improve synergy.

Notes

Treat this audit as a self‑analysis of CORTEX. Do not execute destructive operations on the production dev repo; use safe, isolated branches.

Document all assumptions, tests performed and results in the audit report. Include timestamps and context IDs for traceability.

This prompt aims to ensure that CORTEX systematically checks all orchestrators, their contracts, interactions and dependencies to operate cohesively as a unified brain and to maximize its capabilities on real‑world codebases.
