### 3. **VENDOR DETECTION - CONFIDENCE SCORING ALGORITHM**

The VendorDetector needs **intelligent confidence scoring**:

```python
def calculate_confidence(
    self,
    sdk_detected: bool,
    api_key_found: bool,
    config_references: int,
    file_count: int
) -> float:
    """
    Calculate vendor integration confidence (0.0-1.0).
    
    Scoring:
    - SDK import + API key = 0.95 (definitive)
    - SDK import only = 0.75 (probable)
    - API key pattern only = 0.60 (possible - could be test data)
    - Config references only = 0.40 (uncertain)
    - Multiple files = +0.05 per file (max +0.15)
    """
    score = 0.0
    
    if sdk_detected and api_key_found:
        score = 0.95
    elif sdk_detected:
        score = 0.75
    elif api_key_found:
        score = 0.60
    elif config_references > 0:
        score = 0.40
    
    # Bonus for multiple files (higher confidence)
    file_bonus = min(file_count * 0.05, 0.15)
    score = min(score + file_bonus, 1.0)
    
    return score
```

class LaunchDarklyAnalyzer:
    """
    Specialized analyzer for LaunchDarkly feature flags.
    
    Extracts:
    - All feature flag keys used in code
    - Flag evaluation contexts
    - User targeting rules (if accessible)
    - Environment-specific flags
    """
    
    def extract_feature_flags(self, repo_path: Path) -> Dict[str, Any]:
        """
        Extract all LaunchDarkly feature flags from code.
        
        Patterns:
        - Python: client.variation("flag-key", user, default)
        - C#: _ldClient.BoolVariation("flag-key", user, false)
        - JavaScript: ldClient.variation("flag-key", user, false)
        """
        flags_found = []
        
        patterns = [
            r'\.variation\(["\']([a-z0-9-]+)["\']',  # Python/JS
            r'\.BoolVariation\(["\']([a-z0-9-]+)["\']',  # C#
            r'\.JsonVariation\(["\']([a-z0-9-]+)["\']',  # C#
        ]
        
        for py_file in repo_path.rglob("*.py"):
            content = py_file.read_text()
            for pattern in patterns:
                matches = re.findall(pattern, content)
                for match in matches:
                    flags_found.append({
                        "flag_key": match,
                        "file": str(py_file),
                        "line": self._find_line_number(content, match)
                    })
        
        return {
            "total_flags": len(flags_found),
            "unique_flags": len(set(f["flag_key"] for f in flags_found)),
            "flags": flags_found
        }

## ⚠️ CHALLENGE (MANDATORY)

**User's Approach:** "Make LENS dynamic and allow internet access to gather more info"

**Identified Weaknesses:**

1. **Unbounded Discovery Surface** - "Detect anything" without constraints leads to noise, false positives overwhelming true signals (signal-to-noise ratio collapse)

2. **Internet Access Security Gap** - Generic "go to secure sites" without strict domain allowlist, SSL pinning, and content validation opens SSRF attack vector

3. **Pattern Reliability Crisis** - Dynamic detection without confidence thresholds means unvalidated patterns treated same as battle-tested patterns (garbage in, garbage out)

**Counter-Proposal:** **Tiered Intelligence Architecture with Graduated Trust**

```
Tier 1: Known Patterns (Hardcoded, 99% confidence)
  → LaunchDarkly, Stripe, Auth0, SQL Server, etc.
  → Ship with CORTEX, battle-tested

Tier 2: Learned Patterns (Dynamic, 70-95% confidence)
  → Detected in 3+ repos, manually reviewed, promoted
  → Stored in company/domains/learned-patterns.yaml

Tier 3: Candidate Patterns (Unknown, <70% confidence)
  → First-time detection, quarantined for review
  → Flagged in dashboard, requires human approval

External Knowledge: Verified Sources Only
  → Allowlist: github.com/*/README, pypi.org/pypi/{pkg}/json, npmjs.com/package/{pkg}
  → SSL pinning, 5-second timeout, 7-day cache
```

**Why Counter is Superior:**

- **Weakness 1 → Strength:** Tiered architecture prevents noise explosion - only high-confidence patterns surface automatically, unknowns quarantined
  
- **Weakness 2 → Strength:** Explicit allowlist (GitHub READMEs, PyPI/NPM APIs only) + SSL pinning eliminates SSRF risk, all requests audited

- **Weakness 3 → Strength:** Confidence scoring + manual promotion prevents false positives from polluting domain knowledge, graduated trust model

## ✅ Enhanced LENS Dynamic Intelligence Architecture

### Core Enhancement: 3-Tier Pattern Discovery System

**Tier 1: Hardcoded Known Patterns (Ship with CORTEX)**
- Battle-tested vendor patterns (LaunchDarkly, Stripe, Auth0, Twilio, SendGrid, Okta, DataDog, New Relic)
- Database patterns (SQL Server, PostgreSQL, Oracle, MySQL, MongoDB, Redis)
- Framework patterns (.NET, Spring Boot, Django, Flask, Express, React, Angular, Vue)
- Confidence: 99%+ (pre-validated)

**Tier 2: Learned Patterns (Company-Specific)**
- Dynamically discovered across 3+ repository scans
- Manually reviewed and promoted by users
- Stored in `company/domains/learned-patterns.yaml`
- Versioned with confidence scores and discovery metadata
- Confidence: 70-95% (validated by repetition + human approval)

**Tier 3: Candidate Patterns (Quarantine)**
- First-time detections, unknown vendors/frameworks
- Flagged in dashboard with "Review Pattern" button
- Requires human approval to promote to Tier 2
- Confidence: <70% (unvalidated, may be false positive)

### External Knowledge Integration (Secure)

**Allowlisted Domains Only (Hardcoded, No Arbitrary URLs):**

1. **GitHub** - README.md, documentation files
   - Pattern: `https://raw.githubusercontent.com/{org}/{repo}/main/README.md`
   - Use case: Vendor SDK documentation, integration guides
   
2. **PyPI** - Package metadata API
   - Pattern: `https://pypi.org/pypi/{package}/json`
   - Use case: Python package versions, dependencies, homepage URLs
   
3. **NPM** - Package metadata API
   - Pattern: `https://registry.npmjs.org/{package}`
   - Use case: JavaScript package info, maintainers, keywords
   
4. **NuGet** - Package API
   - Pattern: `https://api.nuget.org/v3-flatcontainer/{package}/index.json`
   - Use case: .NET package versions, release dates

**Security Enforcement:**
- SSL certificate pinning for all domains
- 5-second timeout per request
- Circuit breaker: 3 failures → disable domain for 10 minutes
- Rate limit: 10 requests/minute per domain
- 7-day cache (Redis/file-based)
- Content-hash verification for cached responses
- No repository code sent to external APIs (only package names, versions)

---

### Plugin Architecture for Extensibility

**PatternDetectorPlugin Interface:**
- Standardized interface for new pattern detectors
- Plugins registered in `cortex/brain/discovery/pattern_registry.py`
- Each plugin declares: supported file types, confidence threshold, external APIs needed
- Hot-reload capability (no CORTEX restart required)

**Plugin Security:**
- Plugins must be signed (SHA-256 signature verification)
- Sandboxed execution (no file system write access outside temp/)
- Capability-based permissions (declare required APIs in manifest)
- Resource limits (1GB memory, 30-second timeout per scan)

**Built-In Plugin Examples:**
- `CloudProviderDetector` - Detects AWS, Azure, GCP SDKs
- `MessageQueueDetector` - RabbitMQ, Kafka, SQS, Service Bus
- `CacheLayerDetector` - Redis, Memcached, Elasticache
- `LoggingFrameworkDetector` - Serilog, log4net, Python logging, Winston
- `TestFrameworkDetector` - pytest, Jest, xUnit, NUnit, Mocha

### Intelligent Unknown Pattern Handling

**Discovery Flow:**
```
1. LENS scans repository
2. Detects unknown import: "from acmecorp_sdk import Client"
3. Pattern not in Tier 1 (known) or Tier 2 (learned)
4. → Quarantine to Tier 3 (candidate)
5. → Extract metadata: import statement, file paths, frequency
6. → Research: Search PyPI for "acmecorp-sdk" (if Python)
7. → Cache result: "acmecorp-sdk - Internal company library"
8. → Flag in dashboard: "Unknown vendor: acmecorp-sdk (confidence: 45%)"
9. → User reviews → Promotes to Tier 2 or dismisses as false positive
```

**False Positive Suppression:**
- Common variable names filtered ("client", "service", "manager" alone = not vendors)
- Standard library imports ignored (Python stdlib, .NET BCL)
- Test mocks excluded (Mock, Fake, Stub patterns)
- Minimum import frequency threshold (must appear in 3+ files)

### Data Contract (LENSDashboardSchema)

```python
# cortex/lens/schemas/dashboard_schema.py

from pydantic import BaseModel, Field
from typing import Optional, List, Dict
from enum import Enum

class TabVisibility(str, Enum):
    ALWAYS = "always"
    CONDITIONAL = "conditional"
    HIDDEN = "hidden"

class UseCaseSchema(BaseModel):
    id: str
    title: str
    description: str
    business_value: str
    actors: List[str]
    source_files: List[str]
    confidence: float = Field(ge=0.0, le=1.0)

class VendorSchema(BaseModel):
    name: str
    category: str
    confidence: float
    usage_count: int
    files: List[str]
    integration_pattern: str
    warnings: List[str] = []

class PatternSchema(BaseModel):
    name: str
    tier: str  # "known", "learned", "candidate"
    instances: int
    confidence: float
    locations: List[str]

class LENSDashboardSchema(BaseModel):
    """Master schema for dashboard generation."""
    project_name: str
    generated_at: str
    
    # Tab visibility configuration
    tab_config: Dict[str, TabVisibility] = {}
    
    # Overview data
    overview: Optional[Dict] = None
    
    # Use Cases (NEW)
    use_cases: Optional[List[UseCaseSchema]] = None
    
    # Vendor Intelligence (NEW)
    vendors: Optional[List[VendorSchema]] = None
    
    # Pattern Discovery (NEW)
    patterns: Optional[List[PatternSchema]] = None
    
    # Existing tabs
    dependencies: Optional[Dict] = None
    security: Optional[Dict] = None
    quality: Optional[Dict] = None
    testing: Optional[Dict] = None
    architecture: Optional[Dict] = None
    vulnerabilities: Optional[Dict] = None
    timeline: Optional[Dict] = None
    impact: Optional[Dict] = None
    techstack: Optional[Dict] = None
```
