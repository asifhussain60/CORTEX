**Weaknesses:**

| # | Weakness | Impact |
|---|----------|--------|
| 1 | **No fail-safe for infinite crawler generation** — Self-learning system without bounded complexity could generate 100+ crawlers for polyglot repos, exhausting resources | System hangs, OOM errors, hours-long scans, unusable for real repos |
| 2 | **Domain YAML generation without schema validation** — Dynamic YAML without strict schema enforcement creates unparseable files, breaks dashboard rendering | Silent failures, corrupted dashboards, no error visibility until deploy |
| 3 | **Missing evidence chain for self-learning decisions** — AI-generated crawlers without audit trail means no reproducibility, debugging nightmare, CORE-027 violation | Can't explain why crawler was created, can't debug failures, breaks governance |
| 4 | **No incremental learning persistence** — Each onboarding starts from scratch instead of caching learned patterns across repos | Wasteful re-analysis, slow performance, no organizational knowledge accumulation |

**Counter-Proposal:**

1. **Capability Discovery Framework (CDF)**
   - Phase 1: Fingerprint repo (languages, frameworks, build tools)
   - Phase 2: Match fingerprints to capability matrix (existing 9 analyzers)
   - Phase 3: Identify gaps → generate crawler spec (not code)
   - Phase 4: Validate spec → generate crawler from template

2. **Domain YAML Schema Enforcement**
   - JSON Schema validation before write
   - Pydantic models for type safety
   - Template inheritance (base → enhanced)
   - Rollback on validation failure

3. **Evidence-Based Learning (CORE-027 Compliant)**
   - Each crawler generation creates audit record
   - Decision tree logged (fingerprint → gap → crawler)
   - Hash-chain for traceability
   - Test coverage requirement (TDD gate)

4. **Organizational Learning Cache**
   - SQLite registry: `learned_patterns.db`
   - Schema: `(repo_fingerprint, capability_gap, crawler_spec, success_rate)`
   - Reuse successful patterns across repos
   - Prune failures after 3 attempts

**Why Superior:**

| Schema chaos | Pydantic validation + JSON Schema = guaranteed parseable YAML |
| No audit trail | Full CORE-027 evidence bundle with decision provenance |
