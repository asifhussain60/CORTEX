“Dedicated workflow template per orchestrator” — the right shape

Your requirement is good, but the key is: orchestrators should not implement the workflow. They should implement only the domain-specific steps.

So the model should be:

Kernel Workflow Runtime (Python): executes a WorkflowPlan

Each orchestrator provides:

capabilities

inputs schema

step handlers (pure functions where possible)

Workflow YAML decides:

what steps run

which gates apply

which artifacts must be produced

That’s how you get: uniformity + flexibility without overengineering.
