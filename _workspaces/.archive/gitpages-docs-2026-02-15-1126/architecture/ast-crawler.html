AST Crawler & Knowledge Graph

Automated code analysis, knowledge extraction, and intelligent filtering

🎯 Purpose & Scope

What is the AST Crawler?

The AST (Abstract Syntax Tree) Crawler is a Phase 3 orchestrator that analyzes source code by parsing it into a structured tree format. It extracts business logic, domain models, function signatures, and relationships to build a queryable knowledge graph of your codebase.

Phase 3 Implementation

Planned for Weeks 5-6 (2026-02-10 to 2026-02-21). Requires Phase 1 (audit/state) and Phase 2 (orchestration core) to be complete first. Status: 🔒 Blocked by Phase 2.

Key Capabilities:

  • Parse Python/C#/TypeScript code into AST nodes (classes, functions, variables)
  • Extract relationships (inherits_from, calls, imports, depends_on)
  • Build knowledge graph for semantic queries ("Show all functions calling authenticate()")
  • Filter noise (keep business logic, remove boilerplate)
  • Question suspicious patterns (high complexity, missing tests, unclear names)

🔬 How AST Parsing Works

From Source Code to Structured Knowledge

Python's built-in ast module converts source code into a tree structure where each node represents a language construct (class, function, assignment, etc.). CORTEX walks this tree to extract meaningful business entities.

Input: Python Source Code

class UserManager:
    """Manages user authentication"""
    
    def __init__(self, db_connection):
        self.db = db_connection
    
    def authenticate(self, username: str, 
                     password: str) -> bool:
        """Verify user credentials"""
        user = self.db.query(User)\\
            .filter_by(username=username)\\
            .first()
        
        if not user:
            return False
        
        return user.verify_password(password)

⚙️ Crawling Process (5 Steps)

File Discovery

Scan workspace for source files (.py, .cs, .ts). Respects .gitignore and excludes venv/, node_modules/, generated files. Prioritizes src/ directory. 

# Discovered files (example)
src/auth/user_manager.py
src/models/user.py
src/database/connection.py
tests/test_user_manager.py  # Excluded (not business logic)

AST Parsing

Parse each file using language-specific parser (Python: ast, C#: Roslyn, TypeScript: ts-morph). Extract classes, functions, imports, decorators, type hints, docstrings. 

import ast

with open("src/auth/user_manager.py") as f:
    tree = ast.parse(f.read())

for node in ast.walk(tree):
    if isinstance(node, ast.ClassDef):
        extract_class(node)
    elif isinstance(node, ast.FunctionDef):
        extract_function(node)

Relationship Extraction

Identify connections between entities: inheritance, function calls, imports, dependencies. Build graph edges for semantic queries.

Relationship Type Example Graph Edge
Inheritance class Admin(User) Admin → INHERITS → User
Function Call user.verify_password() authenticate() → CALLS → verify_password()
Import from models import User user_manager.py → IMPORTS → User
Dependency self.db = db_connection UserManager → DEPENDS_ON → db_connection

Knowledge Filtering

Apply filters to keep valuable patterns and remove noise. Ensures knowledge graph stays focused on business logic.

✅ KEEP (Signal)
  • Domain models (User, Order, Payment)
  • Business rules (calculate_discount, validate_email)
  • API endpoints, controllers
  • Functions with complexity 1-10
  • Code with >=80% test coverage
❌ REMOVE (Noise)
  • Framework boilerplate (__init__.py)
  • Generated code (migrations, ORM models)
  • Third-party libraries
  • Utility functions (str.format, len())
  • Transitive dependencies (3+ levels)

Knowledge Graph Storage

Store extracted knowledge in graph database (Neo4j) or JSON structure. Enable semantic queries like "Find all functions that call database" or "Show untested code". 

# Example: Neo4j Cypher query
MATCH (f:Function)-[:CALLS]->(db:Function {name: 'query'})
WHERE NOT (f)-[:HAS_TEST]->(:Test)
RETURN f.name AS untested_db_callers

🔍 Knowledge Filtering Rules

Filtering Decision Matrix

Filter Category Criteria Action Rationale
Business Logic Domain models, validation, rules ✅ KEEP Core business knowledge

High Complexity Cyclomatic complexity > 20 ⚠️ FLAG Refactoring candidate
Missing Tests Coverage < 80% ⚠️ FLAG Route to TDD-Master
Well-Documented Docstring with examples ✅ KEEP High-value knowledge
Unclear Names Variables: x, temp, data ⚠️ QUESTION Code smell
Dead Code No references found ❌ FLAG for Vacuum Cleanup candidate

❓ Knowledge Questioning System

When Patterns Seem Suspicious

The crawler doesn't just accept all code as truth. When it detects anti-patterns or risks, it flags them for human review or routes to Investigation orchestrator.

Detection Rules

⚠️ Complexity Alert 
Function: calculate_shipping_cost()
Location: src/orders/shipping.py:45

Branches: 15 different code paths

🔍 Investigation Triggered:

🔍 Investigation Triggered:
