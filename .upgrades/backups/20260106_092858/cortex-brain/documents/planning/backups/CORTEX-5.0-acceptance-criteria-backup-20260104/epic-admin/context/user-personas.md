# CORTEX User Personas - Detailed Definitions

**Version:** 1.0  
**Date:** 2026-01-04  
**Purpose:** Define user personas for targeted onboarding and communication

---

## 🎯 Persona Overview

CORTEX serves three primary user personas, each with distinct goals, communication preferences, and success metrics. Understanding these personas ensures we deliver relevant, valuable experiences for all users.

---

## 👔 Persona 1: Senior Leadership / Business Owners

### Profile
- **Roles:** CTO, VP Engineering, Director of Engineering, CEO, Business Owner
- **Team Size:** Manages 20-200+ engineers
- **Focus:** Strategic planning, ROI, competitive advantage
- **Time Constraints:** Extremely limited, needs quick wins

### Goals & Motivations
**Primary Goals:**
- Improve team productivity and velocity
- Reduce time-to-market for new features
- Increase code quality and reduce defects
- Lower operational costs
- Maintain competitive advantage

**Key Questions:**
- "What's the ROI?"
- "How does this scale across the organization?"
- "What are the risks?"
- "How long until we see results?"
- "What does success look like?"

### Pain Points
- Unpredictable delivery timelines
- High defect rates reaching production
- Difficulty scaling engineering teams
- Technical debt accumulation
- Limited visibility into development progress
- High cost of quality issues

### Success Metrics
- **Velocity:** Sprint velocity increase (target: 25-35%)
- **Quality:** Defect reduction (target: 40-60%)
- **Cost:** Development cost per feature (target: 20-30% reduction)
- **Time:** Time-to-market reduction (target: 30-40%)
- **Predictability:** Estimation accuracy improvement (target: 40%+)

### Communication Preferences
- **Tone:** Professional, polished, business-focused
- **Language:** Business metrics, outcomes, strategic value
- **Format:** Executive summaries, dashboards, ROI calculators
- **Length:** Concise (2-3 minutes to understand value)
- **Visuals:** Charts, graphs, before/after comparisons

### Content Needs
1. **Executive Overview** (5 min)
   - Clear value proposition
   - Key capabilities in business terms
   - ROI highlights
   
2. **ROI Calculator** (Interactive)
   - Input: Team size, project count
   - Output: Time saved, cost reduction
   
3. **Case Studies** (10 min)
   - Real-world success stories
   - Quantifiable improvements
   - Similar organization profiles
   
4. **Strategic Planning** (5 min)
   - Implementation roadmap
   - Change management approach
   - Risk mitigation strategies

### Example Onboarding Flow
```
1. Welcome & Value Prop (2 min)
2. ROI Calculator (3 min) ← Interactive
3. Case Study Review (5 min)
4. Q&A: Scaling & Implementation (5 min)
5. Next Steps: Pilot Program (2 min)

Total: ~17 minutes
```

### Key Messages
- **ROI:** "Reduce development costs by 20-30% while improving quality"
- **Speed:** "Deliver features 30-40% faster without sacrificing quality"
- **Quality:** "Cut production defects by 40-60% through TDD enforcement"
- **Scale:** "Proven to scale from 5-person teams to 200+ engineers"
- **Risk:** "Low-risk pilot program with measurable results in 30 days"

### Follow-Up Topics
- Strategic roadmap and phased rollout
- Enterprise licensing and support
- Integration with existing DevOps pipeline
- Training and change management
- Success measurement and reporting

## 📊 Persona 2: Product Owners

### Profile
- **Roles:** Product Owner, Scrum Master, Agile Coach, Product Manager
- **Team Size:** Owns 1-3 development teams (5-25 people)
- **Focus:** Sprint planning, backlog management, delivery predictability
- **Time Constraints:** Busy but engaged, needs workflow integration

### Goals & Motivations
**Primary Goals:**
- Increase sprint velocity and predictability
- Improve user story breakdown and estimation
- Reduce technical surprises and blockers
- Enhance visibility into progress
- Deliver high-quality features consistently

**Key Questions:**
- "How does this fit into our sprint workflow?"
- "Can it integrate with Azure DevOps?"
- "How will it help with planning and estimation?"
- "What metrics will improve?"
- "How does the team adopt this?"

### Pain Points
- Poor estimation accuracy
- Surprises late in sprint
- Difficulty breaking down large stories
- Limited visibility into progress
- Technical debt blocking features
- Manual status tracking and reporting
- Quality issues delaying releases

### Success Metrics
- **Velocity:** Sprint velocity increase (target: 25-35%)
- **Predictability:** Estimation accuracy (target: 40% improvement)
- **Quality:** Story acceptance rate (target: 95%+)
- **Visibility:** Real-time progress tracking
- **Technical Debt:** Reduction in tech debt stories (target: 50%)

### Communication Preferences
- **Tone:** Collaborative, empowering, workflow-focused
- **Language:** Agile terminology (stories, sprints, velocity, backlogs)
- **Format:** Workflow diagrams, demos, step-by-step guides
- **Length:** Moderate (10-15 minutes for complete understanding)
- **Visuals:** Sprint boards, burndown charts, progress dashboards

### Content Needs
1. **PO Overview** (5 min)
   - CORTEX in agile workflow
   - Key capabilities for POs
   - Team impact
   
2. **Planning Demo** (15 min)
   - Story breakdown automation
   - Task dependency mapping
   - Progress visualization
   
3. **ADO Integration** (10 min)
   - Setup walkthrough
   - Bidirectional sync
   - Work item management
   
4. **Metrics Dashboard** (10 min)
   - Velocity tracking
   - Quality metrics
   - Team capacity

### Example Onboarding Flow
```
1. Welcome & Agile Integration (3 min)
2. Planning System Demo (12 min) ← Hands-on
3. ADO Integration Setup (8 min)
4. Metrics Dashboard Tour (7 min)
5. Sprint Integration Guide (5 min)
6. Q&A & Next Steps (5 min)

Total: ~40 minutes
```

### Key Messages
- **Velocity:** "Increase sprint velocity by 25-35% with automated planning"
- **Predictability:** "Improve estimation accuracy by 40% with intelligent task breakdown"
- **Quality:** "Reduce defects by 60% through TDD enforcement"
- **Visibility:** "Real-time progress tracking and burndown visualization"
- **Integration:** "Seamless bidirectional sync with Azure DevOps"

### Follow-Up Topics
- Advanced planning techniques
- ADO workflow customization
- Team adoption strategies
- Metrics interpretation and reporting
- Sprint retrospective insights

## 💻 Persona 3: Developers

### Profile
- **Roles:** Software Engineer, Developer, Senior Developer, Tech Lead
- **Team Size:** Individual contributor or team of 5-15
- **Focus:** Code quality, productivity, automation, technical excellence
- **Time Constraints:** Moderate, willing to invest in tools that save time

### Goals & Motivations
**Primary Goals:**
- Write high-quality code faster
- Automate repetitive tasks
- Improve testing and coverage
- Reduce debugging time
- Learn best practices
- Stay in flow state longer

**Key Questions:**
- "How do I use this in my daily workflow?"
- "What commands are available?"
- "How does TDD enforcement work?"
- "Can it help me debug complex issues?"
- "How does it integrate with my tools?"
- "What's the learning curve?"

### Pain Points
- Manual test writing takes too long
- Debugging complex issues is time-consuming
- Code quality inconsistencies
- Repetitive refactoring tasks
- Context switching destroys productivity
- Difficulty maintaining test coverage
- Technical debt accumulation

### Success Metrics
- **Productivity:** Lines of quality code per day (target: 30% increase)
- **Quality:** Test coverage (target: >80%)
- **Debugging:** Time to resolve bugs (target: 40% reduction)
- **Technical Debt:** Code quality metrics improvement
- **Flow:** Uninterrupted coding time (target: longer sessions)

### Communication Preferences
- **Tone:** Technical, detailed, example-rich
- **Language:** Code, commands, technical terminology
- **Format:** Code examples, demos, hands-on tutorials
- **Length:** Detailed (20-30 minutes for thorough understanding)
- **Visuals:** Code snippets, terminal outputs, architecture diagrams

### Content Needs
1. **Developer Overview** (5 min)
   - Architecture and capabilities
   - Core orchestrators
   - Integration points
   
2. **TDD Demo** (20 min)
   - RED → GREEN → REFACTOR
   - Test generation
   - Coverage tracking
   
3. **Autonomous Ops** (15 min)
   - Planning, vacuum, cleanup
   - Investigation workflows
   - Maintenance pipeline
   
4. **Debugging Demo** (15 min)
   - Root cause analysis
   - Fix recommendations
   - Validation
   
5. **Refactoring Guide** (10 min)
   - SKULL rules
   - Code quality analysis
   - Whole-file cleanup

### Example Onboarding Flow
```
1. Welcome & Architecture (3 min)
2. Command Overview (5 min)
3. TDD Hands-On Lab (15 min) ← Interactive
4. Planning Demo (10 min)
5. Debugging Walkthrough (12 min)
6. Autonomous Operations (10 min)
7. Integration Guide (5 min)
8. Q&A & Resources (5 min)

Total: ~65 minutes
```

### Key Messages
- **TDD:** "Enforce test-first development with automatic test generation"
- **Quality:** "SKULL rules ensure whole-file quality on every change"
- **Productivity:** "Autonomous operations handle cleanup, maintenance, investigation"
- **Debugging:** "Root cause analysis with fix recommendations and validation"
- **Context:** "Cross-session memory maintains context across work sessions"

### Follow-Up Topics
- Advanced TDD techniques
- Complex debugging scenarios
- Refactoring best practices
- CI/CD integration
- Custom orchestrator configuration
- Knowledge graph and context system
- Performance optimization tips

## 🔄 Cross-Persona Insights

### Common Ground
All personas value:
- **Time Savings** - Different aspects, same core value
- **Quality Improvement** - From different perspectives
- **Predictability** - Planning, delivery, or code behavior
- **Visibility** - Into progress, quality, or system behavior

### Divergent Needs
- **Leadership:** Strategic, high-level, business-focused
- **Product Owners:** Workflow, team, delivery-focused
- **Developers:** Technical, code, tool-focused

### Communication Strategy
- **Start with value** relevant to persona
- **Use appropriate vocabulary** for audience
- **Provide depth** matching engagement level
- **Link to resources** for further learning
- **Measure engagement** and iterate

## 🎨 Design Implications

### Content Creation
- Create 3 versions of every key concept
- Use persona-appropriate examples
- Adjust depth and technicality
- Match vocabulary to audience

### Navigation
- Persona selection on first visit
- Role-based content filtering
- Easy switching between views
- Progress tracking per persona

### Measurement
- Track completion by persona
- Measure satisfaction per persona
- Identify drop-off points
- A/B test persona-specific content

## ✅ Validation Checklist

For each piece of content, ask:
- [ ] Is the value proposition clear for this persona?
- [ ] Is the language appropriate?
- [ ] Is the depth right (not too shallow/deep)?
- [ ] Are examples relevant to this persona?
- [ ] Is the time investment reasonable?
- [ ] Does it lead to clear next steps?
- [ ] Can we measure engagement?
