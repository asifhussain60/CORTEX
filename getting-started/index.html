Prerequisites

Before installing CORTEX, ensure you have the following tools and access configured:

Required Software

  • Visual Studio Code
    Version 1.85 or higher (NOT Visual Studio IDE)
  • GitHub Copilot Chat Extension
    Active GitHub Copilot subscription required ($10-20/month)
  • Python 3.8+
    With pip package manager
  • Git
    For version control

Optional (Enhanced Features)

  • Azure DevOps Access
    For ADO planning operations
  • .NET SDK
    For sample app development
  • Node.js
    For documentation server
Tip: Verify your GitHub Copilot subscription is active in VS Code. Open the Command Palette (Ctrl+Shift+P / Cmd+Shift+P) and run "GitHub Copilot: Check Status".

  • Phase 12 Goal: Native extensions for VS Code + Visual Studio IDE (2019/2022)
  • Timeline: 2 weeks (December 29, 2025 - January 12, 2026)
  • Future: Both IDEs will have first-class CORTEX support with marketplace installation
For now: Use VS Code for CORTEX. If you develop .NET projects in Visual Studio, you can use VS Code with the C# Dev Kit extension while waiting for the Visual Studio extension.

Installation

Clone the CORTEX repository and install Python dependencies. Choose your preferred shell:

Windows (PowerShell) 

# Navigate to your projects directory
cd D:\PROJECTS

# Clone the repository
git clone https://github.com/asifhussain60/CORTEX.git

# Enter the CORTEX directory
cd CORTEX

# Install Python dependencies
pip install -r requirements.txt

# Verify installation
python -c "import yaml, pytest; print('✓ Dependencies installed')"

Linux / macOS (Bash) 

# Navigate to your projects directory
cd ~/projects

# Clone the repository
git clone https://github.com/asifhussain60/CORTEX.git

# Enter the CORTEX directory
cd CORTEX

# (Optional) Create virtual environment
python3 -m venv venv
source venv/bin/activate

# Install Python dependencies
pip install -r requirements.txt

# Verify installation
python -c "import yaml, pytest; print('✓ Dependencies installed')"
Success Indicator: You should see "✓ Dependencies installed" without any import errors. If you encounter issues, ensure Python 3.8+ and pip are in your PATH.

Open in VS Code 

# Open CORTEX in VS Code
code .
Note: If code command is not found, open VS Code manually and use File → Open Folder to select the CORTEX directory.

Configuration

Configure CORTEX for your environment and preferences:

Create Configuration File

CORTEX uses cortex.config.json for customization. Create it from the template: 

# Windows
Copy-Item cortex.config.template.json cortex.config.json

# Linux/macOS
cp cortex.config.template.json cortex.config.json

Key Configuration Options 

{
  "brain": {
    "tier0_path": "cortex-brain/tier0",  // Governance rules
    "tier1_path": "cortex-brain/tier1",  // Working memory
    "tier2_path": "cortex-brain/tier2",  // Knowledge graph
    "tier3_path": "cortex-brain/tier3"   // Dev context
  },
  "orchestrators": {
    "planning_enabled": true,             // Enable Planning System
    "tdd_enabled": true,                  // Enable TDD workflows
    "ado_integration": false              // Azure DevOps (requires PAT)
  },
  "response_format": {
    "template_version": "4.0",            // Response template version
    "include_author": true,               // Show author in responses
    "token_budget": "ADAPTIVE"            // INSTANT | FOCUSED | COMPREHENSIVE
  }
}
Important: If enabling Azure DevOps integration, you'll need to add your Personal Access Token (PAT) to the configuration. See the ADO Integration Guide for details.

Method 1: Reference CORTEX Prompts

The simplest way to use CORTEX across repositories is to reference the CORTEX prompt files at the start of your Copilot Chat sessions:

Example Workflow

  1. Open your project in VS Code (e.g., D:\MyProjects\MyApp)
  2. Open Copilot Chat
  3. Type the reference command:
Follow instructions in D:\PROJECTS\CORTEX\.github\prompts\CORTEX.prompt.md
  1. Then use CORTEX commands like plan add authentication or start tdd
How It Works: GitHub Copilot can read files from your local system. By referencing the CORTEX prompt file, you give Copilot access to all CORTEX orchestrators, brain tiers, and workflows—even when working in a different repository.

Method 2: VS Code Workspace with Multiple Folders

For tighter integration, add CORTEX as a secondary folder in your VS Code workspace: 

# Step 1: Open your project in VS Code
code D:\MyProjects\MyApp

# Step 2: In VS Code, add CORTEX folder
# File → Add Folder to Workspace → Select D:\PROJECTS\CORTEX

# Step 3: Save workspace (optional)
# File → Save Workspace As → MyApp-with-CORTEX.code-workspace

Benefits of Multi-Folder Workspace

  • Automatic Context
    Copilot always has CORTEX context without manual referencing
  • Cross-Folder Search
    Search both your project and CORTEX simultaneously
  • Dual Terminal Access
    Run commands in either folder without switching windows
  • Persistent Setup
    Save workspace file to quickly reopen the configuration

Brain Isolation & Safety

CORTEX implements strict isolation to prevent cross-contamination:

What CORTEX DOES

  • ✅ Read your project files for context
  • ✅ Generate plans in CORTEX's brain
  • ✅ Create tests in your project's test folder
  • ✅ Provide TDD guidance and code suggestions
  • ✅ Remember project context across sessions

What CORTEX NEVER DOES

  • ❌ Copy CORTEX code into your repo
  • ❌ Commit CORTEX files to your Git
  • ❌ Mix your code with CORTEX internals
  • ❌ Expose CORTEX's brain to your repo
  • ❌ Create CORTEX dependencies in your project
SKULL Protection: CORTEX enforces "GIT_ISOLATION" rule— the CORTEX repository never commits to user repositories. All CORTEX artifacts (plans, reports, brain data) stay in D:\PROJECTS\CORTEX\cortex-brain\, isolated from your project.

Example: Multi-Repo Workflow

Scenario: Adding User Authentication to Your App 

1. Open Your Project with CORTEX Context
   # Open your app
   code D:\MyProjects\MyApp
   
   # In Copilot Chat:
   Follow instructions in D:\PROJECTS\CORTEX\.github\prompts\CORTEX.prompt.md

2. Create a Plan
   # In Copilot Chat:
   plan add user authentication with JWT
   
   # CORTEX creates:
   # D:\PROJECTS\CORTEX\cortex-brain\documents\planning\active\user-authentication\
   #   ├── 00-master-plan.md
   #   ├── context/
   #   ├── reports/
   #   └── tracking/progress-tracker.json

3. Start TDD Implementation
   # In Copilot Chat:
   start tdd
   
   # CORTEX guides you through RED→GREEN→REFACTOR
   # Tests are created in YOUR project:
   # D:\MyProjects\MyApp\tests\test_authentication.py

4. Implementation
   # CORTEX generates code in YOUR project:
   # D:\MyProjects\MyApp\src\auth\jwt_handler.py
   # D:\MyProjects\MyApp\src\auth\middleware.py

5. Verify Isolation
   # Check Git status in your project
   cd D:\MyProjects\MyApp
   git status
   
   # You'll see ONLY your new files:
   #   new file: tests/test_authentication.py
   #   new file: src/auth/jwt_handler.py
   #   new file: src/auth/middleware.py
   
   # NO CORTEX files appear!
Result: Your project has new authentication features with tests, but CORTEX remains separate. The planning artifacts are stored in CORTEX's brain, not committed to your repository.

Troubleshooting

GitHub Copilot doesn't recognize CORTEX commands

Solution: Ensure you've referenced the CORTEX prompt file:

Follow instructions in D:\PROJECTS\CORTEX\.github\prompts\CORTEX.prompt.md

If the issue persists, reload VS Code window (Ctrl+Shift+P → "Reload Window").

Python dependencies installation fails

Solution 1: Upgrade pip and try again:

python -m pip install --upgrade pip
pip install -r requirements.txt

Solution 2: Use a virtual environment:

python -m venv venv
venv\Scripts\activate  # Windows
source venv/bin/activate  # Linux/macOS
pip install -r requirements.txt
CORTEX creates files in the wrong repository

Cause: This is likely due to ambiguous context in Copilot Chat.

Solution: Always specify the target when creating files:

# Explicitly specify paths:
Create test file in D:\MyProjects\MyApp\tests\test_feature.py

# Or be clear about context:
In my MyApp project, create a new authentication module

CORTEX's SKULL protection should prevent this, but explicit instructions help.

Can't find CORTEX plans or reports

Location: All CORTEX artifacts are stored in the CORTEX brain, not your project.

Check these paths:

  • D:\PROJECTS\CORTEX\cortex-brain\documents\planning\active\ - Active plans
  • D:\PROJECTS\CORTEX\cortex-brain\documents\reports\ - Generated reports
  • D:\PROJECTS\CORTEX\cortex-brain\tier1\ - Working memory

Use VS Code's Explorer to navigate to these folders in the CORTEX workspace.
