Executive Summary

CORTEX is built on a four-tier brain architecture that provides intelligent memory management, pattern learning, and context preservation across conversations. Two specialist agents (Planning and Strategic Reasoning) work within orchestrators to coordinate complex multi-phase workflows. The system enforces safety through SKULL brain protection rules at Tier 0, while maintaining sub-100ms working memory access at Tier 1.

Four-Tier Brain Architecture

Tier 0: Governance (SKULL Rules)

▼

Purpose: Brain protection and safety enforcement

SKULL Rules:

  • TDD_ENFORCEMENT: RED→GREEN→REFACTOR mandatory
  • HOLISTIC_CODE_DISCOVERY: Search before create (prevent duplication)
  • REFACTOR_CODE_CLEANUP: Remove orphaned/duplicate code
  • GIT_ISOLATION: CORTEX code never in user repos

Storage: cortex-brain/brain-protection-rules.yaml

Learn more about SKULL →

Tier 1: Working Memory (70-Conversation FIFO)

▼

Purpose: Recent conversation history with fast access

Capabilities:

  • Retention: Last 70 conversations preserved
  • Performance: Sub-100ms retrieval
  • Format: JSON Lines (JSONL)
  • Cleanup: Automatic FIFO eviction

Storage: cortex-brain/conversation-context.jsonl

Orchestrator Ecosystem

Orchestrators coordinate complex multi-phase workflows with validation gates, checkpoints, and rollback support. All orchestrators inherit from BaseOrchestrator.

8 Core Orchestrators

  • Planning System: Multi-phase feature planning with auto-TDD
  • TDD Orchestrator: RED→GREEN→REFACTOR enforcement
  • System Maintenance: 7-phase health and optimization
  • Code Sanitization: 5-phase sensitive data removal
  • System Refinement: 7-phase holistic improvement
  • ADO Operations: Azure DevOps work item generation
  • Architectural Review: 6-phase architecture analysis
  • Git Checkpoint: Automatic commits with rollback

System Flow

User Request → Response

  1. Entry Point: User says command in Copilot Chat
  2. Intent Classification: Determine operation type (plan, tdd, maintenance, etc.)
  3. Context Retrieval: Pull relevant context from Four-Tier Brain
  4. Agent Engagement: Planning or Strategic Reasoning agent analyzes request
  5. Orchestrator Selection: Route to appropriate orchestrator
  6. Phase Execution: Execute workflow phases with validation gates
  7. Checkpoint Creation: Git commits at phase boundaries
  8. Response Generation: Template-based adaptive response
  9. Brain Update: Store conversation in Tier 1, patterns in Tier 2

Execution Methods

  • cli_wrapper: File I/O, git operations (align, healthcheck, optimize)
  • copilot_chat: Interactive workflows (planning, tdd, feedback)
  • internal: Infrastructure not directly invoked by users

Design Principles

  • Brain Protection First: Tier 0 SKULL rules enforce safety
  • Test-Driven Development: TDD mandatory for all production code
  • Git Isolation: CORTEX code never mixed with user repos
  • Adaptive Responses: Template-based responses scale by complexity
  • Context Preservation: Four-Tier Brain maintains long-term memory
  • Multi-Repo Support: 1:∞ scaling with workspace detection
  • Rollback Safety: Git checkpoints enable safe experimentation
  • Phase Gating: Validation gates prevent invalid state transitions
