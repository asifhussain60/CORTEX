# CORRECTION: AC-COPILOT Requirements Clarification

**Date:** 2026-01-10  
**Issue:** Misunderstanding of GitHub Copilot TODO integration mechanism  
**Status:** CORRECTED  

## Original Misunderstanding

The original AC-COPILOT-001 to AC-COPILOT-012 requirements described creating a **JSON-based bridge** to GitHub Copilot's `manage_todo_list` API tool, with the expectation that CORTEX would emit JSON payloads for Copilot to consume via a tool call.

## Correct Understanding

The actual requirement is to **write TODO comments** to a file (`.cortex/copilot-todos.md`) that **VS Code's GitHub Copilot automatically detects** and displays in its built-in **TODO panel**.

### How VS Code's Copilot TODO Feature Works

1. **Comment-Based Detection**: VS Code's GitHub Copilot scans workspace files for TODO comments
2. **Format**: Recognizes standard TODO formats:
   - `// TODO: description` (JavaScript, C++, Java, etc.)
   - `# TODO: description` (Python, Shell, Ruby, etc.)
   - `<!-- TODO: description -->` (HTML, Markdown, XML, etc.)
3. **TODO Panel**: Displays all detected TODOs in a searchable, filterable panel
4. **Automatic**: No API calls required - Copilot automatically scans on file change

## Corrected Architecture

### Component Name Change
- **Old:** GitHubCopilotTodoBridge (JSON API bridge)
- **New:** VSCodeCopilotTodoBridge (file-based TODO writer)

### Integration Mechanism Change
- **Old:** `OrchestratorResult.copilot_todos` → JSON payload → `manage_todo_list` tool
- **New:** `MasterOrchestrator.execute()` → `VSCodeCopilotTodoBridge.write_todos_to_file()` → `.cortex/copilot-todos.md`

### File Format
**Location:** `.cortex/copilot-todos.md` (workspace root)

**Format:** Markdown with HTML TODO comments

```markdown
# CORTEX TodoManager Tasks

> **⚠️ This file is auto-generated by CORTEX. Do not edit manually.**  
> Last updated: 2026-01-10 17:30:00 UTC

---

<!-- TODO: Implement JWT authentication handler -->
**Task:** AC-AUTH-001  
**Description:** Implement JWT token generation, validation, and refresh logic

**Governance:**
- CORE-008: TDD required (write tests first)
- CORE-001: Incremental execution (<500 lines per commit)
- CORE-005: Use pathlib.Path for all file operations

**Files:**
- `src/auth/jwt_handler.py`
- `tests/auth/test_jwt_handler.py`

**Dependencies:**
- ✅ AC-AUTH-000 (Database schema) - COMPLETED

**Status:** ⏳ Not Started

- CORE-008: TDD required
- Test coverage: >90% for security-critical code

**Files:**
- `tests/auth/test_jwt_handler.py`

**Status:** ⏳ Not Started

```

### VS Code Detection

When this file is saved, VS Code's GitHub Copilot automatically:
1. Scans for `<!-- TODO: ... -->` comments
2. Extracts the TODO title
3. Displays in the TODO panel with file location
4. Links to the file for easy navigation

### Benefits of Corrected Approach

| Feature | Old (JSON API) | New (File-based) |
|---------|---------------|------------------|
| **Detection** | Requires API integration | Automatic (built-in VS Code feature) |
| **Visibility** | Hidden in Copilot state | Visible in dedicated TODO panel |
| **Persistence** | Stateless (lost on restart) | File-based (survives restarts) |
| **Editing** | Not user-editable | User can view context in file |
| **Compatibility** | Depends on Copilot API changes | Standard Markdown TODO format |
| **Performance** | API call latency | File I/O (faster) |
