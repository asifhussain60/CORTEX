📨 Authorization Code Flow (PKCE)

The most secure OAuth 2.0 flow for web and mobile apps. PKCE (Proof Key for Code Exchange) prevents authorization code interception attacks.

🔒 PKCE Security Benefits:
  • Protects against authorization code interception attacks
  • No client secret required (safe for mobile/SPA apps)
  • Code verifier never transmitted over network before token exchange
  • Authorization server validates challenge matches verifier

🎫 JWT Token Lifecycle

JSON Web Tokens (JWT) are self-contained tokens that encode user identity and claims. Understand generation, validation, refresh, and expiration patterns.

Access Token

Lifetime: 15-60 minutes
Purpose: Authorize API requests
Storage: Memory (never localStorage)
Contains: User ID, roles, permissions

Refresh Token

Lifetime: 7-30 days
Purpose: Obtain new access token
Storage: HttpOnly cookie
Contains: User ID, token family

ID Token

Lifetime: Same as access token
Purpose: Prove user identity
Storage: Memory or session
Contains: Name, email, profile data

👥 Access Control Models: RBAC vs ABAC

Choose between Role-Based Access Control (RBAC) and Attribute-Based Access Control (ABAC) based on your application's complexity and requirements.

🎯 RBAC Example

{
  "user": "alice@company.com",
  "roles": ["editor", "viewer"],
  "permissions": {
    "editor": ["read", "write", "delete"],
    "viewer": ["read"]
  }
}

// Simple check:
if (user.roles.includes("editor")) {
  allowAccess();
}

🎯 ABAC Example

{
  "user": {"dept": "finance", "level": 3},
  "resource": {"type": "report", "dept": "finance"},
  "environment": {"time": "09:00", "ip": "10.0.0.5"},
  "action": "read"
}

// Complex policy:
if (user.dept === resource.dept &&
    user.level >= 2 &&
    environment.time >= "09:00") {
  allowAccess();
}

🏆 Security Challenge: Implement Multi-Factor Authentication

Design a secure MFA system that combines password + TOTP (Time-based One-Time Password). Your implementation must prevent common attacks and follow OWASP guidelines.

Requirements:

  • Password Validation: Hash with bcrypt, enforce strong password policy (12+ chars, mixed case, special chars)
  • TOTP Generation: Generate time-based codes (30-second window, 6 digits, SHA-256)
  • Rate Limiting: Max 5 failed attempts per 15 minutes, exponential backoff
  • Session Management: Secure tokens, HttpOnly cookies, CSRF protection
  • Audit Logging: Track all auth events (success, failures, lockouts)
  • Backup Codes: Generate 10 single-use recovery codes (SHA-256 hashed)

✅ Secure MFA Solution

🔒 Security Features Implemented:

  • Password Security: Bcrypt with 12 rounds, strong policy enforcement, no plaintext storage
  • TOTP Security: SHA-256 HMAC, 30-second window, base32 secret encoding
  • Rate Limiting: Token bucket algorithm, IP + user tracking, progressive delays
  • Session Security: Cryptographically random tokens, HttpOnly+Secure cookies, SameSite=Strict
  • Audit Trail: Structured logging with timestamps, IP addresses, user agents
  • Recovery Codes: Cryptographically random, SHA-256 hashed, single-use enforcement
  • Timing Attack Prevention: Constant-time comparisons for all sensitive operations
  • Account Lockout: Temporary lockout after 5 failures, automatic unlock after 15 minutes
