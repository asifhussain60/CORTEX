What is the Planning System?

The Planning System is CORTEX's strategic feature planning orchestrator that transforms user requests into comprehensive, executable implementation plans. It enforces Definition of Ready (DoR) requirements before planning begins and validates Definition of Done (DoD) criteria during execution.

Unlike manual planning that's inconsistent and error-prone, the Planning System uses structured workflows with automated complexity detection, incremental phase execution, and built-in TDD integration.

10 Planning Phases

1

Requirements

Extract and validate DoR requirements. Ensure user story is complete with acceptance criteria, constraints, and success metrics.

2

Architecture

Design system architecture. Identify components, dependencies, and integration points. Document technical approach and design decisions.

3

TDD Blueprint

Design test strategy for RED→GREEN→REFACTOR. Define test cases, coverage targets, and validation criteria before implementation.

4

Implementation

Execute TDD workflow: write failing tests (RED), implement features (GREEN), refactor for quality (REFACTOR). Track progress per component.

5

Integration

Integrate components with existing system. Validate interfaces, test interactions, and ensure backward compatibility.

6

DoD Validation

Verify all DoD criteria met: tests passing, coverage targets achieved, documentation complete, no regressions.

7

Documentation

Generate comprehensive documentation: API references, usage guides, architecture diagrams, and troubleshooting tips.

8

Deployment

Prepare deployment artifacts, create deployment guide, configure CI/CD, and establish monitoring/rollback procedures.

9

Review

Conduct comprehensive review: code quality, test coverage, performance, security, and adherence to standards.

10

Finalization

Complete final tasks: update YAML manifests, create git checkpoint, archive planning artifacts, and update knowledge base.

Automatic Complexity Detection

LOW Complexity

Simple changes with minimal risk. Single file, no dependencies.

Planning Strategy: Skeleton (minimal phases)
Example: Add utility function, fix typo

MEDIUM Complexity

Moderate changes with some dependencies. Multiple files affected.

Planning Strategy: Conditional (skip optional phases)
Example: Add API endpoint, refactor module

HIGH Complexity

Complex changes with significant risk. System-wide impact.

Planning Strategy: Incremental (all 10 phases)
Example: New feature, architecture change

Definition of Ready & Definition of Done

📋 Definition of Ready (DoR)

Requirements must meet all 8 criteria before planning begins:

  • ✅ Clear user story with acceptance criteria
  • ✅ Dependencies identified
  • ✅ Testability defined
  • ✅ Technical constraints documented
  • ✅ Success metrics established
  • ✅ Complexity estimated
  • ✅ Priority assigned
  • ✅ Stakeholder approval obtained

✅ Definition of Done (DoD)

Implementation must meet all 6 criteria before completion:

  • ✅ All tests passing (unit, integration, E2E)
  • ✅ Code coverage ≥80%
  • ✅ Documentation complete
  • ✅ Code reviewed and approved
  • ✅ No regressions introduced
  • ✅ Acceptance criteria validated
