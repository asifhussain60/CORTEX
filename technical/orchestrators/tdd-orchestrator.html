Executive Summary

The TDD Orchestrator enforces Test-Driven Development workflow by validating each phase transition in the RED→GREEN→REFACTOR cycle. It automatically discovers your technology stack, generates appropriate tests, validates they fail before implementation (RED), ensures tests pass with minimal code (GREEN), and maintains test coverage during refactoring (REFACTOR). Git checkpoints at each phase enable safe rollback if issues occur.

Key capabilities: Adaptive tech discovery (11+ languages), RED phase validation (tests must fail), GREEN phase coverage tracking (≥80%), REFACTOR quality scoring (0-10), and automatic rollback on phase failures.

RED→GREEN→REFACTOR Cycle

🔴 Phase 1: RED - Write Failing Tests

▼

Purpose: Define expected behavior through tests before implementation

What happens:

  • Technology Discovery: Auto-detects language, framework, test tools, versions
  • Test Generation: Creates test cases for happy path and edge cases
  • DoR Validation: Feature defined, no existing tests, git clean
  • Test Execution: Runs all tests to verify they FAIL
  • Validation Gate: Blocks GREEN phase if any tests pass
  • Checkpoint: Creates RED git checkpoint for rollback

Example output:

🔴 RED Phase Complete
├── Tests written: 5
├── Tests failing: 5 ✅
├── Tests passing: 0 ✅
├── Expected errors: ModuleNotFoundError, AttributeError
└── Checkpoint: commit abc123 (RED: User authentication tests)

SKULL Enforcement:

  • TDD_ENFORCEMENT: Tests must be written before implementation
  • RED_PHASE_VALIDATION: All tests must fail with expected errors

🟢 Phase 2: GREEN - Minimal Implementation

▼

Purpose: Implement minimum code required to pass all tests

What happens:

  • DoR Validation: Tests failing, no passing tests from RED phase
  • Implementation: Write minimal code (no over-engineering)
  • Continuous Testing: Run tests after each change
  • Pass Rate Check: Validates ≥90% of tests passing
  • Coverage Check: Ensures ≥80% code coverage
  • Checkpoint: Creates GREEN git checkpoint

Example output:

🟢 GREEN Phase Complete
├── Tests passing: 5/5 (100%) ✅
├── Coverage: 92% ✅
├── Implementation: src/auth/user_validator.py (45 lines)
├── Complexity: 8 (LOW)
└── Checkpoint: commit def456 (GREEN: User authentication implemented)

Anti-Patterns Prevented:

  • Over-engineering (framework creation, unnecessary abstractions)
  • Gold-plating (features not required by tests)
  • Premature optimization (performance before correctness)

♻️ Phase 3: REFACTOR - Clean Code

▼

Purpose: Improve code quality while maintaining test coverage

What happens:

  • Quality Analysis: Check SOLID principles, detect code smells
  • Complexity Measurement: Identify functions with complexity >30
  • Refactoring: Extract methods, remove duplication, simplify logic
  • Test Validation: Run tests after every refactoring
  • Rollback Safety: Undo refactoring if tests break
  • Quality Score: Calculate 0-10 score based on SOLID/DRY/KISS/YAGNI
  • Checkpoint: Creates REFACTOR git checkpoint

Example output:

♻️ REFACTOR Phase Complete
├── Complexity before: 12
├── Complexity after: 6 ✅
├── Refactorings applied: 3 (extract method, remove duplication, simplify conditional)
├── Tests still passing: 5/5 (100%) ✅
├── Quality score: 8.5/10 ✅
├── SOLID compliance: HIGH
└── Checkpoint: commit ghi789 (REFACTOR: User authentication cleaned)

Clean Code Principles:

  • SOLID: Single responsibility, open/closed, Liskov substitution, interface segregation, dependency inversion
  • DRY: Don't repeat yourself - eliminate duplication
  • KISS: Keep it simple, stupid - prefer simplicity
  • YAGNI: You ain't gonna need it - no speculative features

Adaptive Technology Discovery

TDD Orchestrator automatically discovers your technology stack to generate appropriate tests and validation commands. Supports 11+ languages and frameworks:

Supported Technologies

  • Python: pytest, unittest, coverage.py
  • JavaScript/TypeScript: Jest, Mocha, Jasmine
  • C#: xUnit, NUnit, MSTest
  • Java: JUnit, TestNG, Mockito
  • Go: testing package, testify
  • Ruby: RSpec, Minitest
  • PHP: PHPUnit
  • Rust: cargo test
  • Swift: XCTest
  • Kotlin: JUnit, KotlinTest
  • Scala: ScalaTest

Discovery Process

  1. Project Files: Analyzes package.json, requirements.txt, *.csproj, go.mod, etc.
  2. Test Directories: Detects test/, tests/, spec/, __tests__/ patterns
  3. Framework Detection: Identifies installed test frameworks
  4. Version Detection: Determines language and framework versions
  5. Command Generation: Creates language-specific test commands

Code Quality Scoring (0-10)

REFACTOR phase calculates a quality score based on multiple dimensions:

Scoring Criteria

  • Complexity (30%): Cyclomatic complexity per function (target: <10)
  • SOLID Compliance (25%): Adherence to SOLID principles
  • Duplication (20%): DRY violations detected (target: 0%)
  • Naming (15%): Descriptive names, consistent conventions
  • Test Coverage (10%): Code coverage percentage (target: ≥80%)

Score Interpretation

  • 9-10: Excellent - Production-ready, maintainable code
  • 7-8: Good - Minor improvements recommended
  • 5-6: Fair - Refactoring needed
  • 3-4: Poor - Significant refactoring required
  • 0-2: Critical - Major code quality issues

Configuration

TDD Orchestrator is configured via SKULL brain protection rules in cortex-brain/brain-protection-rules.yaml: 

TDD_ENFORCEMENT:
  enabled: true
  description: "RED→GREEN→REFACTOR mandatory"
  rules:
    - Tests must be written before implementation
    - RED phase must fail before GREEN phase
    - GREEN phase must pass before REFACTOR
    - REFACTOR must maintain test coverage

RED_PHASE_VALIDATION:
  enabled: true
  description: "Validate tests fail in RED phase"
  thresholds:
    min_failing_tests: 1
    max_passing_tests: 0
    allowed_errors:
      - ModuleNotFoundError
      - AttributeError
      - NotImplementedError

GREEN_PHASE_VALIDATION:
  enabled: true
  thresholds:
    min_pass_rate: 0.90
    min_coverage: 0.80
    max_complexity: 30

REFACTOR_PHASE_VALIDATION:
  enabled: true
  thresholds:
    min_quality_score: 7.0
    max_complexity_increase: 0
    must_maintain_coverage: true
