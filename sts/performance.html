N+1 Query Problem

C#

How This Was Refactored

  • Problem: Lazy loading triggers N+1 database queries
  • Fix: Use eager loading with Include() to batch queries
  • Result: Reduced from 101 queries to 1 query
Before: N+1 Queries
public List<OrderDto> GetOrders()
{
    var orders = _context.Orders.ToList(); // 1 query
    
    return orders.Select(o => new OrderDto
    {
        Id = o.Id,
        // Each access triggers a query!
        CustomerName = o.Customer.Name, // N queries
        Items = o.Items.Select(i => i.Name).ToList()
    }).ToList();
}
// Total: 1 + N + N = potentially 201 queries!
After: Eager Loading
public List<OrderDto> GetOrders()
{
    var orders = _context.Orders
        .Include(o => o.Customer)      // Join customer
        .Include(o => o.Items)         // Join items
        .AsNoTracking()                 // Read-only optimization
        .ToList();                      // 1 query total!
    
    return orders.Select(o => new OrderDto
    {
        Id = o.Id,
        CustomerName = o.Customer.Name,
        Items = o.Items.Select(i => i.Name).ToList()
    }).ToList();
}

Sequential vs Parallel Async

TypeScript

How This Was Refactored

  • Problem: Sequential awaits block unnecessarily
  • Fix: Use Promise.all() for independent operations
  • Result: 3 seconds reduced to 1 second (parallel)
Before: Sequential (3s)
async function loadDashboard(userId: string) {
  // Each await blocks the next - total 3 seconds!
  const user = await fetchUser(userId);      // 1 sec
  const orders = await fetchOrders(userId);  // 1 sec  
  const stats = await fetchStats(userId);    // 1 sec
  
  return { user, orders, stats };
}
After: Parallel (1s)
async function loadDashboard(userId: string) {
  // All requests fire simultaneously!
  const [user, orders, stats] = await Promise.all([
    fetchUser(userId),
    fetchOrders(userId),
    fetchStats(userId)
  ]);
  // Total time = slowest request only (1 sec)
  
  return { user, orders, stats };
}

Angular Change Detection

Angular

How This Was Refactored

  • Problem: Default change detection checks entire tree
  • Fix: OnPush strategy + immutable data patterns
  • Result: Component only re-renders when inputs change
Before: Check Always
@Component({
  selector: 'app-user-list',
  template: `
    <div *ngFor="let user of users">
      {{ user.name }} - {{ getStatus(user) }}
    </div>
  `
  // Default: checks on EVERY change detection cycle
})
export class UserListComponent {
  @Input() users: User[];
  
  getStatus(user: User): string {
    console.log('Called every cycle!');
    return user.active ? 'Active' : 'Inactive';
  }
}
After: OnPush + Pure Pipe
@Component({
  selector: 'app-user-list',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <div *ngFor="let user of users; trackBy: trackById">
      {{ user.name }} - {{ user | userStatus }}
    </div>
  `
})
export class UserListComponent {
  @Input() users: User[];
  trackById = (i: number, user: User) => user.id;
}

@Pipe({ name: 'userStatus', pure: true })
export class UserStatusPipe implements PipeTransform {
  transform(user: User): string {
    return user.active ? 'Active' : 'Inactive';
  }
}

Database Indexing

SQL

How This Was Refactored

  • Problem: Full table scan on every query
  • Fix: Add covering index for common query patterns
  • Result: Query time from 5s to 10ms
Before: Full Table Scan
-- No index on Status or CreatedAt
-- Full table scan: 5+ seconds on 10M rows

SELECT OrderId, CustomerId, Total, Status
FROM Orders
WHERE Status = 'Pending'
  AND CreatedAt > DATEADD(day, -7, GETDATE())
ORDER BY CreatedAt DESC;

-- Execution plan shows: Table Scan (100% cost)
After: Covering Index
-- Create covering index for this query pattern
CREATE NONCLUSTERED INDEX IX_Orders_Status_Date
ON Orders (Status, CreatedAt DESC)
INCLUDE (OrderId, CustomerId, Total);

-- Same query now uses Index Seek: 10ms
SELECT OrderId, CustomerId, Total, Status
FROM Orders
WHERE Status = 'Pending'
  AND CreatedAt > DATEADD(day, -7, GETDATE())
ORDER BY CreatedAt DESC;

-- Execution plan: Index Seek (0.01% cost)
