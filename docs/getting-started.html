Prerequisites

Everything runs locally. No infrastructure provisioning. No database server. Just these five things on your machine.

Python 3.9+ (3.11 recommended)
Git 2.30+
VS Code 1.85+ or Visual Studio 2022+
GitHub Copilot (active subscription)
~500 MB disk space
Why These Requirements?

Python is CORTEX's runtime — all 290+ orchestrators and 35+ MCP tools are Python. Git powers the audit trail, commit hooks, and governance enforcement. GitHub Copilot is the AI engine — CORTEX orchestrates it, adding structure, memory, and governance that raw Copilot doesn't provide. No Docker containers, no Kubernetes, no cloud databases. Period.

Choose Your IDE

Two Paths, Same CORTEX

VS Code is the primary path with native MCP auto-discovery. Visual Studio 2022+ works via the GitHub Copilot extension with manual MCP configuration. Choose your IDE below — every step adapts.

Step 1 — Clone
Clone the Repository
git clone https://github.com/asifhussain60/CORTEX.git cd CORTEX

This is the only download step. The entire framework — orchestrators, tools, governance rules, and knowledge base — lives in one repository.

Step 2 — Python Environment
Create a Virtual Environment
python3 -m venv .venv source .venv/bin/activate # Windows PowerShell: # .venv\Scripts\activate

Isolates CORTEX dependencies from your system Python. The .venv directory is gitignored and auto-detected by VS Code.

Step 3 — Dependencies
Install Requirements
pip install -r requirements.txt

Installs all Python packages CORTEX needs — testing frameworks, MCP protocol libraries, and intelligence tooling. Takes about 60 seconds.

Step 4 — Open in VS Code
Launch the Workspace
code .

VS Code opens the workspace. The MCP server starts automatically via stdio transport — no manual startup, no exposed ports, no Docker.

Step 5 — MCP Setup
Configure the AI Connection
python3 scripts/setup-mcp.py

Auto-detects your OS (macOS/Linux/Windows), locates the correct Python executable, and writes the MCP configuration to .vscode/settings.json. One command. Cross-platform.

Step 6 — Verify
Confirm Everything Works
make test-smoke # → All tests pass in <60s

Validates Python, dependencies, and the test suite. A passing smoke test means CORTEX is fully operational. On Windows: python scripts\run_tests.py smoke.

Final Check

Verify the AI Connection

  • 1 Open Copilot Chat — Ctrl+Shift+I (Windows) or Cmd+Shift+I (macOS)
  • 2 Select Agent mode in the chat mode dropdown (top of chat panel)
  • 3 Click the Tools button — you should see CORTEX tools listed (cortex_verify, cortex_classify, etc.)
  • 4 Type: What is CORTEX? — if it responds with the CORTEX header, you're connected

Under the Hood

The MCP Configuration

CORTEX uses Pylance-style stdio transport — the same mechanism that powers language servers in modern IDEs. No network ports. No Docker. No cloud API keys. One JSON block is all it takes.

VS Code — .vscode/settings.json
{ "github.copilot.chat.mcpServers": { "cortex": { "command": "python3", "args": ["-m", "cortex.mcp"], "transport": "stdio", "cwd": "${workspaceFolder}" } } }

Auto-generated by python3 scripts/setup-mcp.py. Cross-platform — detects the correct Python path for macOS, Linux, and Windows.

How It Works
  • → Auto-start: The MCP server launches when VS Code opens the workspace — no manual startup
  • → stdio transport: Communication flows over standard input/output — no exposed network ports
  • → Tool discovery: 30+ tools auto-register and appear in Copilot Chat's tool panel instantly
  • → Process lifecycle: VS Code manages the server process — restarts automatically if needed

Full Suite

All Tests — Parallel

Uses all CPU cores via pytest-xdist. 3–4× faster than sequential. Pre-commit standard.

Windows Users

Replace make test-* with python scripts\run_tests.py {mode} in PowerShell. All commands also available as VS Code Tasks: Ctrl+Shift+P → Run Task → CORTEX.

Common Issues

Troubleshooting

MCP tools don't appear in Copilot Chat

  • 1 Run python3 scripts/setup-mcp.py in the terminal
  • 2 Reload VS Code: Cmd+Shift+P → Reload Window
  • 3 Ensure you're in Agent mode (not Ask or Edit mode)

Python version issues

  • 1 Verify: python3 --version (must be ≥3.9)
  • 2 Ensure the virtual environment is activated: which python3 should point to .venv/
  • 3 Windows: use python (not python3)

Tests fail on first run

  • 1 Ensure all dependencies installed: pip install -r requirements.txt
  • 2 Run preflight first: make test-preflight
  • 3 Check for stale cache: CORTEX_DISABLE_TESTMON=true make test-smoke

Need help inside CORTEX

  • → Ask in Copilot Chat: "What can CORTEX help me with?"
  • → Ask for explanation: "Why did CORTEX recommend X?"
  • → The audit trail stores reasoning behind every decision

Python Environment Check

Confirm Your Virtual Environment

Check 1 — venv is active
# macOS / Linux: which python3 # Expected output: /path/to/CORTEX/.venv/bin/python3 # Windows PowerShell: where python # Expected: ...CORTEX\.venv\Scripts\python.exe

If the path points to .venv/, your environment is isolated correctly. If it points to /usr/bin/ or system Python, reactivate with source .venv/bin/activate.

Check 2 — CORTEX package loads
python3 -c "import cortex; print('✅ CORTEX ready')" # Expected output: ✅ CORTEX ready # Then confirm MCP tools respond: python3 -m cortex.mcp --help 2>&1 | head -3

A clean import confirms all dependencies are installed and the cortex package is on your path. If this fails, run pip install -r requirements.txt again.
