SQL Injection Prevention
C#

How This Was Refactored

  • Vulnerability: String concatenation allows SQL injection
  • Fix: Parameterized queries separate data from SQL
  • Result: User input is data, never executable SQL
Before: SQL Injection Vulnerable 
public class UserRepository
{
    public User GetUser(string username)
    {
        // VULNERABLE: String concatenation
        var query = "SELECT * FROM Users WHERE Username = '" 
                    + username + "'";
        
        // Attack: "admin'--" bypasses auth
        using var conn = new SqlConnection(connectionString);
        using var cmd = new SqlCommand(query, conn);
        conn.Open();
        return MapUser(cmd.ExecuteReader());
    }
}
After: Parameterized Query 
public class UserRepository
{
    public User GetUser(string username)
    {
        // SECURE: Parameterized query
        const string query = @"
            SELECT Id, Username, Email 
            FROM Users WHERE Username = @Username";
        
        using var conn = new SqlConnection(connectionString);
        using var cmd = new SqlCommand(query, conn);
        cmd.Parameters.AddWithValue("@Username", username);
        conn.Open();
        return MapUser(cmd.ExecuteReader());
    }
}
Cross-Site Scripting (XSS)
Angular

How This Was Refactored

  • Vulnerability: innerHTML bypasses sanitization
  • Fix: Use interpolation or DomSanitizer
  • Result: Malicious scripts are neutralized
Before: XSS Vulnerable 
@Component({
  selector: 'app-comment',
  template: \`
    <!-- VULNERABLE: innerHTML executes scripts -->
    <div [innerHTML]="userComment"></div>
  \`
})
export class CommentComponent {
  @Input() userComment: string;
  // No sanitization = XSS attacks possible
}
After: Sanitized Content 
@Component({
  selector: 'app-comment',
  template: \`
    <!-- SECURE: Interpolation auto-escapes -->
    <p>{{ userComment }}</p>
    <div [innerHTML]="sanitizedHtml"></div>
  \`
})
export class CommentComponent {
  @Input() userComment: string;
  sanitizedHtml: SafeHtml;
  
  constructor(private sanitizer: DomSanitizer) {}
  
  ngOnChanges() {
    this.sanitizedHtml = this.sanitizer
      .bypassSecurityTrustHtml(this.stripScripts(this.userComment));
  }
}
Secure Authentication
TypeScript

How This Was Refactored

  • Vulnerability: Plain text passwords
  • Fix: bcrypt hashing + rate limiting
  • Result: Passwords safe even if DB breached
Before: Insecure Passwords 
class AuthService {
  async login(email: string, password: string) {
    const user = await this.db.findUser(email);
    
    // VULNERABLE: Plain text comparison
    if (user.password === password) {
      return user;
    }
    throw new Error('Invalid credentials');
  }
  
  async register(email: string, password: string) {
    // VULNERABLE: Storing plain text
    await this.db.createUser({ email, password });
  }
}
After: Secure Passwords 
import bcrypt from 'bcrypt';

class AuthService {
  private limiter = new RateLimiter({ maxAttempts: 5 });
  
  async login(email: string, password: string) {
    await this.limiter.checkLimit(email);
    const user = await this.db.findUser(email);
    
    // SECURE: bcrypt comparison
    const isValid = await bcrypt.compare(password, user.passwordHash);
    if (!isValid) throw new AuthError('Invalid credentials');
    return this.sanitizeUser(user);
  }
  
  async register(email: string, password: string) {
    const passwordHash = await bcrypt.hash(password, 12);
    await this.db.createUser({ email, passwordHash });
  }
}
Secure SQL Procedures
SQL

How This Was Refactored

  • Vulnerability: EXEC with string concat
  • Fix: sp_executesql with parameters
  • Result: Parameters bound safely
Before: Dynamic SQL Injection 
CREATE PROCEDURE SearchProducts
    @SearchTerm NVARCHAR(100)
AS
BEGIN
    -- VULNERABLE: String concatenation
    DECLARE @SQL NVARCHAR(MAX)
    SET @SQL = 'SELECT * FROM Products 
                WHERE Name LIKE ''%' + @SearchTerm + '%'''
    
    -- Attack: "'; DROP TABLE Products;--"
    EXEC(@SQL)
END
After: Parameterized Dynamic SQL 
CREATE PROCEDURE SearchProducts
    @SearchTerm NVARCHAR(100)
AS
BEGIN
    -- SECURE: Parameterized dynamic SQL
    DECLARE @SQL NVARCHAR(MAX)
    DECLARE @Params NVARCHAR(200)
    
    SET @SQL = N'SELECT * FROM Products 
                 WHERE Name LIKE @Search'
    SET @Params = N'@Search NVARCHAR(102)'
    
    EXEC sp_executesql @SQL, @Params, 
         @Search = N'%' + @SearchTerm + N'%'
END
