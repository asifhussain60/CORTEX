🎓 Testing Concepts Explained

Testing isn't about proving your code works—it's about catching bugs before users do, enabling fearless refactoring, and documenting expected behavior.

TDD

Test-Driven Development

"Write the test first, then write code to make it pass."

🎯 Process: RED (write failing test) → GREEN (make it pass) → REFACTOR (clean up)

%

Code Coverage

"The percentage of code lines executed during tests."

📊 Targets: 80%+ is good, 100% isn't always necessary. Quality > quantity.

🎭

Mocking

"Replacing real dependencies with fake ones for isolated testing."

🎬 Analogy: Using a stunt double instead of the real actor for dangerous scenes.

🔺

Test Pyramid

"Many unit tests (fast), fewer integration tests, fewest E2E tests (slow)."

🏗️ Ratio: ~70% unit, ~20% integration, ~10% end-to-end

TEST-01 No Tests CRITICAL

Untested Code: "It Works on My Machine"

The Problem: Without tests, you can't know if changes break existing functionality. Every deployment is a gamble. Developers are afraid to refactor because they might break something.

❌ BEFORE No tests/ directory at all 
# src/business/payment.py
class PaymentProcessor:
    def process_payment(self, amount, card_number):
        # Does this work? Who knows!
        # Does it handle edge cases? No idea!
        # Will refactoring break it? Probably!
        
        if amount <= 0:
            return {"error": "Invalid amount"}
        
        # Magic number, hardcoded validation
        if len(card_number) != 16:
            return {"error": "Invalid card"}
        
        return {"success": True, "amount": amount}

# How is this tested?
# 1. Manual testing in browser (slow, unreliable)
# 2. "It works on my machine" (famous last words)
# 3. Production is the test environment (yikes)
✅ AFTER tests/test_payment.py 
import pytest
from src.business.payment import PaymentProcessor

class TestPaymentProcessor:
    """Comprehensive tests for payment processing"""
    
    @pytest.fixture
    def processor(self):
        return PaymentProcessor()
    
    # Happy path tests
    def test_valid_payment_succeeds(self, processor):
        result = processor.process_payment(100.00, "4111111111111111")
        assert result["success"] is True
        assert result["amount"] == 100.00
    
    # Edge case tests
    def test_zero_amount_rejected(self, processor):
        result = processor.process_payment(0, "4111111111111111")
        assert "error" in result
        assert "Invalid amount" in result["error"]
    
    def test_negative_amount_rejected(self, processor):
        result = processor.process_payment(-50, "4111111111111111")
        assert result["success"] is False
    
    # Boundary tests
    def test_card_number_too_short(self, processor):
        result = processor.process_payment(100, "411111111111")
        assert "Invalid card" in result["error"]
    
    def test_card_number_too_long(self, processor):
        result = processor.process_payment(100, "41111111111111111111")
        assert "Invalid card" in result["error"]

TEST-02 No Isolation HIGH

Brittle Tests: Depends on Real Database & APIs

The Problem: Tests that hit real databases or external APIs are slow, flaky, and can fail for reasons unrelated to your code. Mocking replaces real dependencies with controlled fakes.

❌ BEFORE Tests depend on real services 
# This test is slow and unreliable
def test_user_creation():
    # Needs real database running
    db = Database("postgresql://prod-server/db")
    
    # Needs real email server
    email_service = EmailService("smtp.gmail.com")
    
    user_service = UserService(db, email_service)
    
    # Takes 5 seconds, fails if DB is down
    result = user_service.create_user({
        "name": "Test User",
        "email": "test@example.com"
    })
    
    # Pollutes real database with test data!
    assert result["id"] is not None
    
    # Sends real email to real address! 😱
    # What if email server is down? Test fails.
    # What if it's rate limited? Test fails.
✅ AFTER Properly Mocked 
from unittest.mock import Mock, patch
import pytest

class TestUserService:
    @pytest.fixture
    def mock_db(self):
        """Fake database - fast and controllable"""
        db = Mock()
        db.insert.return_value = {"id": 123}
        return db
    
    @pytest.fixture
    def mock_email(self):
        """Fake email service - no real emails sent"""
        return Mock()
    
    def test_user_creation(self, mock_db, mock_email):
        user_service = UserService(mock_db, mock_email)
        
        result = user_service.create_user({
            "name": "Test User",
            "email": "test@example.com"
        })
        
        # Verify behavior without real services
        assert result["id"] == 123
        mock_db.insert.assert_called_once()
        mock_email.send_welcome.assert_called_with("test@example.com")
    
    def test_handles_db_error(self, mock_db, mock_email):
        """Test error handling - impossible with real DB"""
        mock_db.insert.side_effect = DatabaseError("Connection lost")
        
        user_service = UserService(mock_db, mock_email)
        
        with pytest.raises(ServiceError):
            user_service.create_user({"name": "Test"})
CORTEX Capability: TDD Mastery → Mock generation & dependency injection
TEST-03 No Integration MEDIUM

Missing Integration Tests: Components Don't Talk

The Problem: Unit tests verify individual functions work. But what about when they work together? Integration tests verify that components communicate correctly.

❌ BEFORE Only unit tests (if any) 
# Unit tests pass, but system fails!

# ✓ PaymentProcessor.validate() works
# ✓ OrderService.create() works  
# ✓ InventoryService.reserve() works

# But together?
# PaymentProcessor returns {"status": "success"}
# OrderService expects {"payment_status": "completed"}
# Mismatch! System breaks in production.

# No tests verify the full flow:
# User clicks "Buy" → Payment → Order → Inventory → Email
✅ AFTER tests/integration/test_checkout.py 
import pytest
from testcontainers.postgres import PostgresContainer

class TestCheckoutFlow:
    """Integration tests for complete checkout process"""
    
    @pytest.fixture(scope="class")
    def test_db(self):
        """Real database in Docker container"""
        with PostgresContainer("postgres:15") as postgres:
            yield postgres.get_connection_url()
    
    def test_complete_checkout_flow(self, test_db, test_client):
        """Test the entire happy path"""
        # 1. Add item to cart
        cart = test_client.post("/cart/add", json={"product_id": 1})
        assert cart.status_code == 200
        
        # 2. Start checkout
        checkout = test_client.post("/checkout/start")
        assert checkout.json()["cart_total"] > 0
        
        # 3. Process payment
        payment = test_client.post("/checkout/pay", json={
            "card_number": "4111111111111111",
            "amount": checkout.json()["cart_total"]
        })
        assert payment.json()["status"] == "completed"
        
        # 4. Verify order created
        order = test_client.get(f"/orders/{payment.json()['order_id']}")
        assert order.json()["status"] == "confirmed"
        
        # 5. Verify inventory updated
        product = test_client.get("/products/1")
        assert product.json()["stock"] == 99  # Decremented
