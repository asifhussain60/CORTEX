🎓 Documentation Concepts Explained

Good documentation isn't about writing novels—it's about making code discoverable, understandable, and maintainable by future developers (including future you!).

📝

Docstrings

"Built-in documentation strings in Python functions and classes."

🏷️ Purpose: Explain WHAT a function does, its parameters, return values, and exceptions.

💡

Type Hints

"Annotations that specify the expected types of parameters and returns."

🎯 Benefit: IDEs provide autocomplete, errors are caught before runtime.

📖

API Documentation

"Structured documentation for REST endpoints, generated from code."

🗺️ Tools: OpenAPI/Swagger, automatically generated from annotations.

⚠️

Comments vs. Self-Documenting Code

"Good code explains itself; comments explain WHY, not WHAT."

🚫 Bad: # increment i by 1
✅ Good: # Skip header row per CSV spec v2.1

The Problem: Functions without docstrings force readers to analyze every line of code to understand purpose, parameters, and return values. This wastes time and leads to misuse.

DOC-02 No Type Hints MEDIUM

Type Confusion: What Can I Pass Here?

The Problem: Without type hints, developers guess what types are expected. Pass a string when an int is expected? Runtime error. Type hints enable IDE autocomplete and catch errors before code runs.

❌ BEFORE No type information 
def calculate_discount(price, quantity, customer):
    # What type is price? int? float? Decimal?
    # What type is customer? dict? object? ID?
    
    if customer.is_premium:  # Assumes customer has this attr
        rate = 0.2
    else:
        rate = 0.1
    
    return price * quantity * (1 - rate)

# Calling code - what's correct?
calculate_discount(100, 5, user_dict)      # Wrong type?

calculate_discount(99.99, 3, {"premium": True})  # Dict ok?
✅ AFTER Fully Typed 
from decimal import Decimal
from dataclasses import dataclass

@dataclass
class Customer:
    id: int
    name: str
    is_premium: bool

def calculate_discount(
    price: Decimal,
    quantity: int,
    customer: Customer
) -> Decimal:
    """Calculate discounted total for customer order."""
    discount_rate = Decimal("0.2") if customer.is_premium else Decimal("0.1")
    subtotal = price * quantity
    return subtotal * (1 - discount_rate)

# ✓ Autocomplete for Customer attributes
# ✓ Error squiggles if wrong type passed
# ✓ Hover documentation for parameters
# ✓ Refactoring support across codebase

DOC-03 Stale Comments MEDIUM

Lying Comments: Code Changed, Comment Didn't

The Problem: Comments that describe what code used to do are worse than no comments. They actively mislead readers. Comments should explain WHY, not WHAT—the code already shows what it does.
