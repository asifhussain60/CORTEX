Documentation Patterns

Write code that explains itself through meaningful documentation

Good documentation is the bridge between your code and its users. These examples show how to transform undocumented code into self-explanatory, maintainable systems.

DOC-01

Missing Code Documentation

Medium Impact

Functions without documentation force developers to read implementation details to understand behavior. Add comprehensive TSDoc/JSDoc comments to public APIs.

❌ Before: No Documentation TypeScript 
export class UserService {
    private cache = new Map<string, User>();

    async getUser(id: string, includeDeleted?: boolean): Promise<User | null> {
        if (this.cache.has(id)) {
            return this.cache.get(id)!;
        }
        
        const user = await this.repository.findById(id);
        if (!user || (user.deletedAt && !includeDeleted)) {
            return null;
        }
        
        this.cache.set(id, user);
        return user;
    }

    async updateUser(id: string, data: Partial<User>, merge?: boolean): Promise<User> {
        const existing = await this.getUser(id);
        if (!existing) {
            throw new Error('User not found');
        }
        
        const updated = merge 
            ? { ...existing, ...data }
            : { ...existing, ...data, updatedAt: new Date() };
        
        await this.repository.save(updated);
        this.cache.delete(id);
        return updated;
    }
}

Key Documentation Elements

  • @param - Document every parameter with type and purpose
  • @returns - Describe what the function returns and when
  • @throws - List all exceptions that can be thrown
  • @example - Provide usage examples with code snippets
  • @remarks - Add implementation notes and caveats
DOC-02

Missing API Documentation

High Impact

APIs without documentation create integration barriers. Use Swagger/OpenAPI attributes to generate interactive documentation automatically.

❌ Before: Undocumented API C# ASP.NET 
[ApiController]
[Route("api/[controller]")]
public class OrdersController : ControllerBase
{
    [HttpPost]
    public async Task<IActionResult> CreateOrder(
        CreateOrderRequest request)
    {
        var order = await _orderService.CreateAsync(request);
        return CreatedAtAction(
            nameof(GetOrder), 
            new { id = order.Id }, 
            order);
    }

    [HttpGet("{id}")]
    public async Task<IActionResult> GetOrder(Guid id)
    {
        var order = await _orderService.GetByIdAsync(id);
        if (order == null)
            return NotFound();
        return Ok(order);
    }

    [HttpGet]
    public async Task<IActionResult> GetOrders(
        int page, int pageSize, string? status)
    {
        var orders = await _orderService.GetPagedAsync(
            page, pageSize, status);
        return Ok(orders);
    }
}
✅ After: Swagger/OpenAPI Documentation C# ASP.NET 
/// <summary>
/// Manages customer orders and order lifecycle.
/// </summary>
[ApiController]
[Route("api/[controller]")]
[Produces("application/json")]
[Tags("Orders")]
public class OrdersController : ControllerBase
{
    /// <summary>
    /// Creates a new order for the authenticated customer.
    /// </summary>
    /// <param name="request">Order details including items</param>
    /// <returns>The newly created order</returns>
    /// <response code="201">Order created successfully</response>
    /// <response code="400">Invalid order data</response>
    /// <response code="401">User not authenticated</response>
    [HttpPost]
    [ProducesResponseType(typeof(OrderResponse), 201)]
    [ProducesResponseType(typeof(ProblemDetails), 400)]
    [ProducesResponseType(401)]
    public async Task<IActionResult> CreateOrder(
        [FromBody] CreateOrderRequest request)
    {
        var order = await _orderService.CreateAsync(request);
        return CreatedAtAction(
            nameof(GetOrder), 
            new { id = order.Id }, 
            order);
    }

    /// <summary>
    /// Retrieves a specific order by its unique identifier.
    /// </summary>
    /// <param name="id">The order's unique identifier</param>
    /// <returns>The order details if found</returns>
    /// <response code="200">Order found</response>
    /// <response code="404">Order not found</response>
    [HttpGet("{id:guid}")]
    [ProducesResponseType(typeof(OrderResponse), 200)]
    [ProducesResponseType(404)]
    public async Task<IActionResult> GetOrder(
        [FromRoute] Guid id)
    {
        var order = await _orderService.GetByIdAsync(id);
        if (order == null) return NotFound();
        return Ok(order);
    }

    /// <summary>
    /// Lists orders with pagination and optional filtering.
    /// </summary>
    /// <param name="page">Page number (1-based)</param>
    /// <param name="pageSize">Items per page (max 100)</param>
    /// <param name="status">Filter by status</param>
    /// <returns>Paginated list of orders</returns>
    [HttpGet]
    [ProducesResponseType(typeof(PagedResult<OrderResponse>), 200)]
    public async Task<IActionResult> GetOrders(
        [FromQuery] int page = 1,
        [FromQuery][Range(1, 100)] int pageSize = 20,
        [FromQuery] OrderStatus? status = null)
    {
        var orders = await _orderService.GetPagedAsync(
            page, pageSize, status);
        return Ok(orders);
    }
}

Swagger/OpenAPI Benefits

  • Interactive docs - Try API calls directly from documentation
  • Client generation - Auto-generate TypeScript/C# clients
  • Response types - Document all possible response codes
  • Validation - Schema validation from annotations
DOC-03

Poor Component Documentation

Medium Impact

UI components without documentation make reuse difficult. Document inputs, outputs, and usage examples to enable team adoption.

❌ Before: Undocumented Component Angular 
@Component({
    selector: 'app-data-table',
    templateUrl: './data-table.component.html',
    styleUrls: ['./data-table.component.scss']
})
export class DataTableComponent<T> {
    @Input() data: T[] = [];
    @Input() columns: ColumnDef[] = [];
    @Input() pageSize = 10;
    @Input() sortable = true;
    @Input() selectable = false;
    @Input() loading = false;
    
    @Output() rowClick = new EventEmitter<T>();
    @Output() selectionChange = new EventEmitter<T[]>();
    @Output() sortChange = new EventEmitter<SortEvent>();
    @Output() pageChange = new EventEmitter<PageEvent>();
    
    selectedRows: T[] = [];
    currentPage = 1;
    sortColumn?: string;
    sortDirection: 'asc' | 'desc' = 'asc';
}
✅ After: Well-Documented Component Angular 
/**
 * A flexible, generic data table component with sorting,
 * pagination, and row selection capabilities.
 * 
 * @usageNotes
 * ### Basic Usage
 * ```html
 * <app-data-table
 *   [data]="users"
 *   [columns]="columnDefs"
 *   (rowClick)="onUserSelect($event)">
 * </app-data-table>
 * ```
 * 
 * ### With Selection
 * ```html
 * <app-data-table
 *   [data]="products"
 *   [columns]="productColumns"
 *   [selectable]="true"
 *   (selectionChange)="onProductsSelected($event)">
 * </app-data-table>
 * ```
 * 
 * @example
 * // Define columns in component
 * columnDefs: ColumnDef[] = [
 *   { field: 'name', header: 'Name', sortable: true },
 *   { field: 'email', header: 'Email' },
 *   { field: 'status', header: 'Status', template: statusTpl }
 * ];
 */
@Component({
    selector: 'app-data-table',
    templateUrl: './data-table.component.html',
    styleUrls: ['./data-table.component.scss']
})
export class DataTableComponent<T> {
    /**
     * The data array to display in the table.
     * Each item represents one row.
     */
    @Input() data: T[] = [];

    /**
     * Column definitions specifying which fields to display
     * and how to render them.
     * @see ColumnDef for configuration options
     */
    @Input() columns: ColumnDef[] = [];

    /**
     * Number of rows to display per page.
     * @default 10
     */
    @Input() pageSize = 10;

    /**
     * Enable column sorting functionality.
     * When true, clicking headers toggles sort direction.
     * @default true
     */
    @Input() sortable = true;

    /**
     * Enable row selection with checkboxes.
     * Selected rows are emitted via selectionChange.
     * @default false
     */
    @Input() selectable = false;

    /**
     * Display loading skeleton while data is being fetched.
     * @default false
     */
    @Input() loading = false;

    /**
     * Emitted when a row is clicked.
     * @param row The data object for the clicked row
     */
    @Output() rowClick = new EventEmitter<T>();

    /**
     * Emitted when row selection changes.
     * Contains all currently selected rows.
     */
    @Output() selectionChange = new EventEmitter<T[]>();

    /**
     * Emitted when sort column or direction changes.
     * Use to implement server-side sorting.
     */
    @Output() sortChange = new EventEmitter<SortEvent>();

    /**
     * Emitted when the current page changes.
     * Use to implement server-side pagination.
     */
    @Output() pageChange = new EventEmitter<PageEvent>();
}

Component Documentation Best Practices

  • @usageNotes - Show HTML template examples
  • @example - Show TypeScript configuration
  • @default - Document default values for optional inputs
  • @see - Link to related interfaces and types

## Quick Start

```bash
# Clone the repository
git clone https://github.com/company/oms.git
cd oms

# Install dependencies
npm install
dotnet restore

# Set up environment
cp .env.example .env
# Edit .env with your database credentials

# Run database migrations
dotnet ef database update

# Start development servers
npm run dev        # Frontend on http://localhost:4200
dotnet run         # Backend on http://localhost:5000
```
