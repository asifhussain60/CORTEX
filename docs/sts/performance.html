Why Performance Matters

Performance isn't just about speed—it's about user experience, server costs, and scalability. A 1-second delay in page load can cause a 7% reduction in conversions.

N+1 Queries

The silent killer: 1 query for a list, then N queries for each item's details. Use eager loading.

Big O Complexity

O(n²) loops can bring servers to their knees. Know your algorithms' time complexity.

Caching

The fastest database query is the one you don't make. Cache frequently accessed data.

Async Patterns

Don't block threads waiting for I/O. Use async/await for responsive applications.

public class OrderService
{
    public async Task<List<OrderDto>> GetOrdersWithDetails()

After CORTEX 
public class OrderService
{
    public async Task<List<OrderDto>> GetOrdersWithDetails()
    {
        // Single query with eager loading!
        var orders = await _context.Orders
            .Include(o => o.Customer)
            .Include(o => o.Items)
                .ThenInclude(i => i.Product)
            .AsSplitQuery() // Optimize for many includes
            .AsNoTracking() // Read-only optimization
            .ToListAsync();
        
        return orders.Select(o => new OrderDto
        {
            Id = o.Id,
            OrderDate = o.OrderDate,
            CustomerName = o.Customer.Name,
            Items = o.Items.Select(i => new OrderItemDto
            {
                ProductName = i.Product.Name,
                Quantity = i.Quantity,
                Price = i.Price
            }).ToList()
        }).ToList();
    }
    
    // For large datasets, use projection instead
    public async Task<List<OrderSummaryDto>> GetOrderSummaries()
    {
        return await _context.Orders
            .Select(o => new OrderSummaryDto
            {
                Id = o.Id,
                CustomerName = o.Customer.Name,
                TotalAmount = o.Items.Sum(i => i.Price * i.Quantity),
                ItemCount = o.Items.Count
            })
            .AsNoTracking()
            .ToListAsync();
    }
}

// Now: 1-2 queries total
// Takes ~50ms - 300x faster!

What CORTEX Fixed

  • Eager loading: Include() loads related data in single query
  • Split queries: AsSplitQuery() prevents Cartesian explosion
  • No tracking: AsNoTracking() skips change detection overhead
  • Projection: Select only needed fields, computed in database
PERF-02

O(n²) Nested Loops

Quadratic complexity killing performance

TypeScript
Before CORTEX 
interface User { id: string; name: string; }
interface Order { id: string; userId: string; total: number; }

function getUserOrderTotals(
    users: User[], 
    orders: Order[]
): Map<string, number> {
    const totals = new Map<string, number>();
    
    // O(n²) - nested loops!
    for (const user of users) {
        let userTotal = 0;
        
        // Scans ALL orders for EACH user
        for (const order of orders) {
            if (order.userId === user.id) {
                userTotal += order.total;
            }
        }
        
        totals.set(user.id, userTotal);
    }
    
    return totals;
}

// With 10,000 users and 100,000 orders:
// 10,000 × 100,000 = 1 BILLION iterations
// Takes 30+ seconds

function getUserOrderTotals(
    users: User[], 
    orders: Order[]
): Map<string, number> {
    // O(n) - Single pass to build index
    const ordersByUser = new Map<string, number>();
    
    // One pass through orders - O(m)
    for (const order of orders) {
        const current = ordersByUser.get(order.userId) ?? 0;
        ordersByUser.set(order.userId, current + order.total);
    }
    
    // One pass through users - O(n)
    const totals = new Map<string, number>();
    for (const user of users) {
        totals.set(user.id, ordersByUser.get(user.id) ?? 0);
    }
    
    return totals;
}

// Even cleaner with reduce
function getUserOrderTotalsClean(
    users: User[], 
    orders: Order[]
): Map<string, number> {
    // Build lookup in O(m)
    const orderTotals = orders.reduce((acc, order) => {
        acc.set(order.userId, (acc.get(order.userId) ?? 0) + order.total);
        return acc;
    }, new Map<string, number>());
    
    // Map users in O(n)
    return new Map(
        users.map(u => [u.id, orderTotals.get(u.id) ?? 0])
    );
}

// O(n + m) instead of O(n × m)
// 10,000 + 100,000 = 110,000 iterations
// Takes ~5ms - 6000x faster!

What CORTEX Fixed

  • Index/lookup pattern: Build Map for O(1) lookups
  • Linear complexity: O(n + m) vs O(n × m)
  • Single passes: Each collection iterated only once
  • 6000x speedup: From 30 seconds to 5 milliseconds

@Injectable({ providedIn: 'root' })
export class ProductService {
    private categoriesCache$?: Observable<Category[]>;
    private productCache = new Map<string, Observable<Product>>();
    private currentUser$?: Observable<User>;
    
    constructor(private http: HttpClient) {}
    
    // Cached with shareReplay - fetches once, shares result
    getCategories(): Observable<Category[]> {
        if (!this.categoriesCache$) {
            this.categoriesCache$ = this.http
                .get<Category[]>('/api/categories')
                .pipe(
                    shareReplay({ bufferSize: 1, refCount: true }),
                    catchError(err => {
                        this.categoriesCache$ = undefined; // Reset on error
                        throw err;
                    })
                );
        }
        return this.categoriesCache$;
    }
    
    // Per-item cache with TTL
    getProduct(id: string): Observable<Product> {
        if (!this.productCache.has(id)) {
            const product$ = this.http
                .get<Product>(`/api/products/${id}`)
                .pipe(
                    shareReplay({ bufferSize: 1, refCount: true }),
                    tap(() => {
                        // Auto-expire after 5 minutes
                        setTimeout(() => this.productCache.delete(id), 
                            5 * 60 * 1000);
                    })
                );
            this.productCache.set(id, product$);
        }
        return this.productCache.get(id)!;
    }
    
    // Share across all subscribers
    getCurrentUser(): Observable<User> {
        if (!this.currentUser$) {
            this.currentUser$ = this.http
                .get<User>('/api/users/me')
                .pipe(shareReplay(1));
        }
        return this.currentUser$;
    }
    
    // Manual cache invalidation
    invalidateProductCache(id?: string): void {
        if (id) {
            this.productCache.delete(id);
        } else {
            this.productCache.clear();
        }
    }
}

What CORTEX Fixed

  • shareReplay: Multicasts results to all subscribers
  • Per-item caching: Map stores individual product observables
  • TTL expiration: Cache auto-invalidates after 5 minutes
  • Manual invalidation: Clear cache after updates

public async Task<DashboardData> GetDashboardAsync(Guid userId)
{
    // Parallel - all requests fire simultaneously!
    var userTask = _userService.GetUserAsync(userId);
    var ordersTask = _orderService.GetRecentOrdersAsync(userId);
    var notificationsTask = _notificationService
        .GetUnreadAsync(userId);
    var recommendationsTask = _recommendationService
        .GetPersonalizedAsync(userId);
    var analyticsTask = _analyticsService
        .GetUserStatsAsync(userId);
    
    // Wait for all to complete
    await Task.WhenAll(
        userTask, 
        ordersTask, 
        notificationsTask,
        recommendationsTask,
        analyticsTask
    );
    
    // Total: ~200ms (slowest task) instead of 650ms!
    
    return new DashboardData
    {
        User = await userTask,
        RecentOrders = await ordersTask,
        Notifications = await notificationsTask,
        Recommendations = await recommendationsTask,
        Analytics = await analyticsTask
    };
}

Performance Best Practices

Eager Loading

Use Include() and ThenInclude() to fetch related data in one query.

.Include(o => o.Items)

Know Your Big O

O(n²) loops are red flags. Use Maps/Sets for O(1) lookups.

new Map() // O(1) access

Cache Wisely

Cache expensive operations with shareReplay, Redis, or in-memory stores.

pipe(shareReplay(1))

Parallelize I/O

Independent async operations should run in parallel with Task.WhenAll.

await Task.WhenAll(...)
