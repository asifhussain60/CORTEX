# CORTEX MCP Cross-Platform Setup Fix

**Problem:** `.vscode/settings.json` was tracked in git with platform-specific Python paths, causing MCP breakage when pulling code between Mac and Windows.

**Root Cause:** 
- Windows: `.venv/Scripts/python.exe`
- macOS/Linux: `.venv/bin/python`

When committed to git, the wrong path breaks MCP on the other platform.

---

## ✅ Solution Implemented (BUG-CROSSPLATFORM-001)

### 1. **Remove `.vscode/settings.json` from Git Tracking**

`.vscode/settings.json` is now machine-specific and **NOT committed** to git:

```bash
git rm --cached .vscode/settings.json
```

**Rationale:** Each developer's machine must generate its own platform-specific configuration.

### 2. **Update `.gitignore`**

Changed from:
```gitignore
# VS Code - Allow settings.json (Copilot suppression), ignore everything else
.vscode/*
!.vscode/settings.json
```

To:
```gitignore
# VS Code - Machine-specific, regenerated by .githooks/post-checkout
# CRITICAL: .vscode/settings.json contains platform-specific paths (Mac: bin/python, Windows: Scripts/python.exe)
# Committing it causes cross-platform breakage. Let each machine generate its own via setup-mcp.py.
.vscode/
```

### 3. **Enhanced `post-checkout` Git Hook**

Updated `.githooks/post-checkout` to **regenerate** `.vscode/settings.json` on every `git pull` / `git checkout`:

```bash
# CRITICAL FIX (BUG-CROSSPLATFORM-001): .vscode/settings.json is platform-specific
# Mac uses: .venv/bin/python
# Windows uses: .venv/Scripts/python.exe
# Solution: Regenerate settings.json on EVERY checkout (not tracked in git)

echo -e "${CYAN}🔧 Regenerating platform-specific MCP configuration...${NC}"
python .cortex/setup-mcp.py --silent 2>/dev/null || python .cortex/setup-mcp.py
```

### 4. **Platform Detection in `setup-mcp.py`**

The setup script auto-detects the platform and uses the correct path:

```python
# Cross-platform Python path using VS Code variable
if IS_WINDOWS:
    python_path = "${workspaceFolder}/.venv/Scripts/python.exe"
else:
    python_path = "${workspaceFolder}/.venv/bin/python"
```

## 📋 Architecture Notes

### MCP Runs Locally (Pylance-Style)

- **NO manual server startup** required
- VS Code auto-starts MCP when Copilot invokes `cortex_*` tools
- Uses stdio transport (stdin/stdout JSON-RPC 2.0)
- Configuration files:
  - `.vscode/settings.json` (PRIMARY - regenerated per-machine)
  - `.vscode/mcp.json` (SECONDARY - also regenerated)

### Cross-Platform Variables

Both paths use VS Code's `${workspaceFolder}` variable:
- **Mac:** `${workspaceFolder}/.venv/bin/python`
- **Windows:** `${workspaceFolder}/.venv/Scripts/python.exe`

VS Code resolves `${workspaceFolder}` at runtime to the absolute workspace path.
