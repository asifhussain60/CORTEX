CORE-008 — Immutable Contract

The TDD Quality Flywheel

CORTEX does not suggest writing tests. It enforces writing them first — before any implementation — on every feature and every bug fix. No flag to skip it. No exception for "small changes." When you ask CORTEX to implement a feature, it generates the failing tests first.

🔴
RED — Write Failing Test

Define expected behaviour via a test. CORTEX verifies the test fails before any production code exists — a test that passes immediately is flagged as testing nothing.

🟢
GREEN — Minimum Passing Code

Write exactly the code needed to satisfy the test — no over-engineering. CORTEX validates the test suite passes before allowing the next gate to open.

♻️
REFACTOR — Clean & Converge

Improve structure, remove duplication, enforce CORE rules. The convergence gate rescans until zero P0/P1 violations remain — then the cycle repeats.

Test Quality Scoring

Every test scored across 5 dimensions: Impact, Likelihood, Detection, Efficiency, Maintenance. Top-tier tests promoted to the Golden suite. Low-quality tests flagged for removal — false confidence is worse than no test.

Golden Tests — Never Break

A curated set of high-scoring tests covering critical end-to-end behaviours. Promoted by quality scores. Contract is absolute: they must always pass with zero regressions. A golden test failure is production-blocking.

Sweep Completeness (CORE-064)

When one instance of an issue is found, CORTEX scans the entire codebase and fixes every occurrence. The sweep is not complete until the catalogue is empty — no partial fixes allowed.

Agent Authoring — You Can Build This

Build Your Own Agents

CORTEX is not just a framework you use — it is a framework you extend. Software engineers author custom agents in .github/agents/ that encode team-specific expertise, domain rules, and workflow automations. Every agent is automatically governed, learns from outcomes, and integrates into the same orchestration pipeline as the 290+ built-in capabilities.

What an Agent Is

An agent is a Markdown prompt file placed in .github/agents/. It declares its scope, its governing rules, its orchestration chain, and its output contract. CORTEX auto-discovers agents, registers them in the orchestration layer, and routes relevant intents to them — no manual wiring and no Python required to get started.

What You Get for Free
  • •Automatic governance enforcement — your agent inherits all CORE rules without extra config
  • •RCA memory integration — PLIP-001 consults prior failures before every run automatically
  • •SQLite audit trail — every invocation recorded with AC markers and full routing chain
  • •Reinforcement learning — success/failure signals update your agent's strategy confidence over time
  • •Scope isolation — your agent's learned patterns never leak into other domains (PLIP scope lock)

Institutional Memory

RCA Memory — Failures Never Repeat

Every root cause analysis generates a SQLite-backed PreventionRule that surfaces automatically the next time a similar pattern is about to be introduced — across your entire team, not just your session.

❌ Without RCA Memory
  • •Same bug fixed multiple times across different sessions — no shared memory, no awareness it happened before.
  • •Security gaps reintroduced by engineers who weren't in the original post-mortem.
  • •Post-mortems written, filed, and forgotten. Institutional knowledge leaves when engineers leave.
  • •Junior engineers repeat senior mistakes — no mechanism to surface prior lessons at the point of recurrence.
✅ With RCA Memory
  • •Every fix converted into a named PreventionRule with confidence scores that decay appropriately over time.
  • •PLIP-001: cortex_learning op=history consulted before every code-modifying operation — automatically.
  • •Three escalation levels: Advisory → Warning → Block (based on severity multiplied by recurrence count).
  • •Cross-team: one fix prevents the same failure being reintroduced across the entire portfolio instantly.
