🖥️ Local Installation (Per Developer)

Best For: Solo developers or distributed teams

  • Each developer clones CORTEX to their machine
  • Full control over upgrades and customization
  • No network dependencies
  • Works offline

Setup Time: 5 minutes per developer

🌐 Shared Network Drive (Team)

Best For: Co-located teams with shared infrastructure

  • Single CORTEX installation on network drive
  • All devs point to same location
  • Centralized upgrades
  • Shared knowledge graph benefits entire team

Setup Time: 10 minutes (one-time), 2 minutes per developer config

🔀 Hybrid (Recommended for Teams 5+)

Best For: Teams needing balance of independence and sharing

  • Central CORTEX on network drive (read-only)
  • Local Tier 3 brain per developer
  • Shared Tier 0-2 (governance + knowledge)
  • Individual workspace contexts

Setup Time: 15 minutes (one-time setup)

📦 Installation Steps

1

Prerequisites

  • Python 3.8+ (python --version)
  • Git (git --version)
  • VS Code with GitHub Copilot extension
  • 50MB disk space (CORTEX core)
  • 100MB+ for Brain databases (grows with usage)
2

Clone Repository

# Local Installation
cd D:\PROJECTS  # Or your preferred location
git clone https://github.com/asifhussain60/CORTEX.git

# Network Drive Installation (Team Admin)
cd \\server\shared\dev-tools
git clone https://github.com/asifhussain60/CORTEX.git
3

Install Dependencies

cd CORTEX
python -m venv .venv

# Windows
.venv\Scripts\activate

# Mac/Linux
source .venv/bin/activate

# Install packages
pip install -r requirements.txt
4

Configure Machine Path

# Edit cortex.config.json
{
  "cortex_root": "D:/PROJECTS/CORTEX",  # Local path
  "workspace_roots": [],  # Auto-populated
  "brain_db_path": "cortex-brain/cortex-brain.db",
  "tier3_base_path": "cortex-brain/tier3"
}

Team Setup: Point cortex_root to network drive path

5

Verify Installation

# Test Python entry point
python -m src.main --version

# Expected output:
# CORTEX 4.0.0

# Test Copilot integration
# Open VS Code → Copilot Chat:
"Hello CORTEX, system healthcheck"

👥 Team Deployment Best Practices

🔐 Access Control

  • Network drive: Read-only for team, write for admin
  • Each developer has local Tier 3 brain (isolated)
  • Shared Tier 0-2 (SKULL rules, knowledge graph)

📊 Centralized Knowledge

  • Team admin upgrades CORTEX weekly
  • Shared knowledge graph learns from all devs
  • Common patterns benefit entire team

🔄 Upgrade Strategy

  • Use upgrade cortex command (brain-safe)
  • 9-phase workflow with rollback support
  • Zero data loss guarantee
  • Team notification before upgrades

🧪 Testing Environment

  • Maintain separate CORTEX for testing
  • Test upgrades before deploying to team
  • Validate operations in sandbox

🔧 Common Issues

❌ "Module not found" errors

Solution: Ensure virtual environment is activated

# Re-activate venv
.venv\Scripts\activate  # Windows
source .venv/bin/activate  # Mac/Linux

# Reinstall dependencies
pip install -r requirements.txt

❌ Network path issues (Team)

Solution: Use UNC paths with forward slashes

# cortex.config.json
{
  "cortex_root": "//server/shared/dev-tools/CORTEX"
}

❌ Copilot not loading CORTEX

Solution: Verify .github/copilot-instructions.md

# Check file exists
ls .github/copilot-instructions.md

# Reload VS Code window
Ctrl+Shift+P → "Reload Window"

❌ Brain database locked (Team)

Solution: Use local Tier 3 brain per developer

# Edit cortex.config.json
{
  "tier3_base_path": "C:/Users/[username]/cortex-tier3"
}
