4-Tier Brain Architecture

A distributed intelligence system designed like a skyscraper—each floor has a specific purpose, and information travels between layers in under 100 milliseconds

Executive Summary

CORTEX's 4-tier architecture is not just an AI assistant—it's a governed, learning, context-aware development partner. Governance at the top ensures quality through 22 immutable SKULL rules. Working memory in Tier 1 provides rich context from the last 70 conversations. Knowledge in Tier 2 learns patterns through 8,429 nodes and 24,817 connections. Context in Tier 3 tracks reality with real-time git activity, code metrics, and hotspot detection. Together: intelligent, fast, governed.

🏛️ Tier 0: Governance Layer

▼

At the top, we have Tier 0—CORTEX's constitution. This layer contains 22 immutable rules we call SKULL (System Knowledge Unified for Long-term Learning). These rules enforce TDD, git isolation, and red-phase validation. They cannot be bypassed, ensuring code quality and system integrity at all times. Notice the golden color—this represents the highest authority in the system.

💾 Tier 1: Working Memory

▼

Tier 1 is CORTEX's short-term memory—the last 70 conversations stored in a FIFO (First-In, First-Out) queue. When conversation 71 arrives, conversation 1 is automatically deleted. This design gives CORTEX rich context without memory bloat. Query speed? Under 100 milliseconds. That's the time it takes light to travel 30 kilometers.

Why 70 Conversations?

It's a sweet spot discovered through testing. More than 70 and queries slow down. Fewer than 70 and context becomes shallow. We tested 50, 100, and 150 conversations—70 gave the best balance between richness and speed while staying under the critical 100ms threshold.

🕸️ Tier 2: Knowledge Graph

▼

Tier 2 is CORTEX's long-term memory—a knowledge graph where patterns emerge and semantic understanding lives. With over 8,400 nodes and 24,000 connections, this layer uses Hebbian learning: concepts that fire together, wire together. When you ask about TDD and git checkpoints together multiple times, CORTEX strengthens that connection, learning your workflow patterns.

Hebbian Learning in Action

Named after neuroscientist Donald Hebb, this learning principle states: "Neurons that fire together, wire together." In CORTEX, when you use two concepts together frequently, their connection strengthens. Over time, CORTEX learns your patterns and can anticipate related concepts.

Example: If you frequently ask about "TDD" and "git checkpoints" together, CORTEX will strengthen the connection between these concepts. Next time you mention TDD, CORTEX automatically considers git checkpoint patterns.

📊 Tier 3: Development Context

▼

At the foundation is Tier 3—CORTEX's awareness of your project's health. This layer tracks your codebase in real-time: which files are hot (frequently changed), git activity patterns, code metrics, and test coverage. Those red glowing zones in the visualization? Those are your development hotspots—areas of high change velocity that deserve attention.

Distributed Database Architecture

Each tier has its own SQLite database—distributed by design. No single point of failure, optimized for specific query patterns. Working memory needs speed, knowledge graph needs graph traversal, development context needs aggregation. Each database is purpose-built.

Why SQLite Instead of PostgreSQL or MongoDB?

⚡ Zero Configuration

No server to manage, no complex setup. File-based storage means CORTEX is portable and easy to deploy.

📁 File-Based Portability

Backup with a simple file copy. Move databases between machines effortlessly. No export/import required.

🚀 Sub-Millisecond Queries

For CORTEX's access patterns and scale, SQLite delivers sub-millisecond query times—perfect for the 87ms target.

Graceful Degradation

CORTEX's 4-tier architecture degrades gracefully under failure. Only Tier 0 failure would stop the system—and Tier 0 is read-only immutable code, the most reliable component.

Tier 3 Fails

CORTEX loses development context but still has memory and knowledge. Can still provide intelligent responses using Tier 1 & 2.

Tier 2 Fails

CORTEX loses long-term patterns but still has recent conversations and governance. Operates with reduced learning capability.

Tier 1 Fails

CORTEX loses recent context but still has knowledge and governance. Operates with no short-term memory but long-term patterns intact.

Tier 0 Fails

System stops—but Tier 0 is read-only immutable code, the most reliable component. Only code corruption could cause failure.
