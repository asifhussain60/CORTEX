A01: Broken Access Control

Critical

Description: Restrictions on authenticated users not properly enforced. Attackers can access unauthorized functionality and/or data, such as accessing other users' accounts, viewing sensitive files, or modifying data.

Mitigation Strategies

Implement proper authorization checks at the server side
Deny by default - fail securely
Use centralized access control mechanisms
Minimize CORS usage
Disable directory listing on web servers

A02: Cryptographic Failures

Critical

Description: Failures related to cryptography (or lack thereof) that often lead to exposure of sensitive data. Previously known as "Sensitive Data Exposure," this includes weaknesses in encryption, key management, and data protection.

Mitigation Strategies

Classify data processed, stored, or transmitted by application
Apply controls per classification (e.g., GDPR, PCI DSS)
Encrypt all sensitive data at rest and in transit
Use strong, up-to-date encryption algorithms and protocols
Implement proper key management practices
Disable caching for sensitive data responses

A03: Injection

High

Description: Application is vulnerable when user-supplied data is not validated, filtered, or sanitized. Includes SQL, NoSQL, OS command, ORM, LDAP, and Expression Language (EL) or Object Graph Navigation Library (OGNL) injection.

Mitigation Strategies

Use parameterized queries, prepared statements, or stored procedures
Use ORM frameworks safely (watch for lazy loading vulnerabilities)
Validate input using positive server-side validation (allowlists)
Escape special characters using syntax-appropriate escaping
Use LIMIT and other SQL controls within queries

A04: Insecure Design

High

Description: Risks related to design and architectural flaws. Missing or ineffective control design. Different from insecure implementation - even perfect implementation cannot fix insecure design. Requires secure development lifecycle and threat modeling.

Mitigation Strategies

Establish and use a secure development lifecycle with security professionals
Use threat modeling for critical authentication, access control, business logic, and key flows
Integrate security language and controls into user stories
Implement plausibility checks at each tier of application
Write unit and integration tests to validate all critical flows

A05: Security Misconfiguration

High

Description: Missing appropriate security hardening or improperly configured permissions. Includes insecure default configurations, incomplete or ad hoc configurations, open cloud storage, misconfigured HTTP headers, verbose error messages.

Mitigation Strategies

Implement secure installation processes with repeatable hardening
Use minimal platform without unnecessary features, components, or documentation
Review and update configurations as part of patch management process
Use segmented application architecture for effective security separation
Send security directives to clients (e.g., Security Headers)

A06: Vulnerable and Outdated Components

High

Description: Using components with known vulnerabilities. Includes unsupported or out-of-date versions of OS, web/application server, DBMS, APIs, and all components, libraries, and frameworks. Not scanning for vulnerabilities regularly.

Mitigation Strategies

Remove unused dependencies, features, files, and documentation
Continuously inventory versions of client-side and server-side components
Monitor sources like CVE and NVD for vulnerability information
Only obtain components from official sources over secure links
Monitor for unmaintained libraries and components

A07: Identification and Authentication Failures

Medium-High

Description: Confirmation of user's identity, authentication, and session management is critical to protect against authentication-related attacks. Previously "Broken Authentication." Includes credential stuffing, brute force, and weak passwords.

Mitigation Strategies

Implement multi-factor authentication wherever possible
Do not ship or deploy with default credentials (especially for admin users)
Implement weak password checks (e.g., against top 10,000 worst passwords)
Limit or delay failed login attempts (rate limiting)
Use secure session management with proper invalidation
Align password length, complexity, and rotation policies with NIST 800-63b

A08: Software and Data Integrity Failures

Medium

Description: Code and infrastructure that does not protect against integrity violations. Includes insecure CI/CD pipelines, auto-update without integrity verification, and serialization/deserialization issues. Previously included "Insecure Deserialization."

Mitigation Strategies

Use digital signatures to verify software or data is from expected source
Ensure libraries and dependencies are consuming trusted repositories
Use software supply chain security tools (OWASP Dependency Check, Snyk)
Ensure CI/CD pipeline has proper segregation, configuration, and access control
Verify unsigned or unencrypted serialized data is not sent to untrusted clients

A09: Security Logging and Monitoring Failures

Medium

Description: Insufficient logging, detection, monitoring, and active response. Without logging and monitoring, breaches cannot be detected. Includes logins, failed logins, and high-value transactions not logged. Warnings and errors generate inadequate logs.

Mitigation Strategies

Ensure all login, access control, and server-side input validation failures can be logged
Log with sufficient user context to identify suspicious or malicious accounts
Ensure logs are in a format that can be consumed by centralized log management
Establish effective monitoring and alerting for suspicious activities
Establish or adopt incident response and recovery plans (e.g., NIST 800-61r2)

A10: Server-Side Request Forgery (SSRF)

Medium

Description: SSRF flaws occur whenever a web application fetches a remote resource without validating the user-supplied URL. Allows an attacker to coerce the application to send a crafted request to an unexpected destination, even when protected by firewall, VPN, or network ACL.

Mitigation Strategies

Sanitize and validate all client-supplied input data
Enforce URL schema, port, and destination with a positive allow list
Do not send raw responses to clients
Disable HTTP redirections
Use network segmentation to separate resource access (e.g., DMZ)
