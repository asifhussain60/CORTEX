OWASP Top 10 (2021)

A01

Broken Access Control

CRITICAL

Access control enforces policy such that users cannot act outside of their intended permissions. Failures typically lead to unauthorized information disclosure, modification, or destruction of data.

Common Weaknesses
  • Bypassing access control checks by modifying URLs
  • Viewing/editing someone else's account (IDOR)
  • Accessing API with missing access controls
  • Elevation of privilege (user to admin)
Mitigations
  • Deny by default except for public resources
  • Implement access control mechanisms once
  • Model access controls should enforce record ownership
  • Log access control failures, alert on repeated failures
Code Example
// Bad: Direct Object Reference without authorization app.get('/api/users/:id', (req, res) => { return db.users.findById(req.params.id); }); // Good: Verify ownership before returning data app.get('/api/users/:id', authorize, (req, res) => { if (req.user.id !== req.params.id && !req.user.isAdmin) { return res.status(403).json({ error: 'Forbidden' }); } return db.users.findById(req.params.id); });
A02

Cryptographic Failures

CRITICAL

Previously known as "Sensitive Data Exposure," focusing on failures related to cryptography which often leads to sensitive data exposure or system compromise.

Common Weaknesses
  • Transmitting data in clear text (HTTP, FTP)
  • Using old or weak cryptographic algorithms
  • Using default or weak crypto keys
  • Not enforcing encryption (missing TLS directives)
Mitigations
  • Classify data and identify sensitive data
  • Encrypt all sensitive data at rest
  • Use strong algorithms, protocols, and keys
  • Disable caching for sensitive responses
A03

Injection

CRITICAL

An application is vulnerable to attack when user-supplied data is not validated, filtered, or sanitized. This includes SQL, NoSQL, OS, and LDAP injection.

Common Weaknesses
  • SQL Injection via untrusted data in queries
  • LDAP injection in directory lookups
  • XPath injection in XML queries
  • OS command injection
Mitigations
  • Use parameterized queries or prepared statements
  • Use ORM with proper escaping
  • Implement input validation (whitelist)
  • Escape special characters in queries
Code Example
// Bad: String concatenation in SQL query = "SELECT * FROM users WHERE id = '" + userId + "'"; // Good: Parameterized query query = "SELECT * FROM users WHERE id = ?"; db.execute(query, [userId]);
A04

Insecure Design

HIGH

A new category focusing on risks related to design flaws. Secure design requires threat modeling, secure design patterns, and reference architectures.

Common Weaknesses
  • Missing rate limiting on sensitive operations
  • Insufficient business logic validation
  • Trust boundaries not properly defined
  • Lack of threat modeling in design phase
Mitigations
  • Use threat modeling from design phase
  • Integrate security into the development lifecycle
  • Use secure design patterns and libraries
  • Define trust boundaries and data flows
A05

Security Misconfiguration

HIGH

Security misconfiguration is the most commonly seen issue. This includes insecure default configurations, incomplete configurations, and verbose error messages.

Common Weaknesses
  • Default credentials left unchanged
  • Unnecessary features enabled
  • Error handling reveals too much information
  • Missing security headers
Mitigations
  • Implement hardening procedures
  • Remove unnecessary features and frameworks
  • Use security headers (CSP, HSTS, etc.)
  • Automate configuration verification
A06

Vulnerable & Outdated Components

HIGH

Components like libraries, frameworks, and other software modules run with the same privileges as the application. Vulnerable components can undermine application defenses.

Common Weaknesses
  • Unknown component versions in use
  • Vulnerable or outdated software
  • No regular vulnerability scanning
  • Not fixing dependencies in timely manner
Mitigations
  • Maintain inventory of component versions
  • Monitor for vulnerabilities (CVE databases)
  • Only obtain components from official sources
  • Use software composition analysis tools
A07

Identification & Authentication Failures

HIGH

Confirmation of the user's identity, authentication, and session management is critical. Weaknesses exist if the application permits automated attacks or uses weak credentials.

Common Weaknesses
  • Permits automated credential attacks
  • Allows weak or well-known passwords
  • Missing or ineffective MFA
  • Session IDs exposed in URLs
Mitigations
  • Implement multi-factor authentication
  • Don't ship with default credentials
  • Implement weak-password checks
  • Limit failed login attempts
A08

Software & Data Integrity Failures

MEDIUM

A new category focusing on software updates, critical data, and CI/CD pipelines without verifying integrity. Includes insecure deserialization.

Common Weaknesses
  • Using untrusted CDNs without integrity checks
  • Auto-update without signature verification
  • Insecure deserialization
  • Unsigned CI/CD pipeline modifications
Mitigations
  • Use digital signatures to verify integrity
  • Use SRI (Subresource Integrity) for CDN resources
  • Implement code signing for CI/CD
  • Review code and configuration changes
A09

Security Logging & Monitoring Failures

MEDIUM

Without logging and monitoring, breaches cannot be detected. Insufficient logging, detection, monitoring, and active response allows attackers to persist.

Common Weaknesses
  • Auditable events not logged
  • Logs only stored locally
  • No alerting for suspicious activities
  • Penetration tests don't trigger alerts
Mitigations
  • Log all login, access control, and input validation failures
  • Ensure logs are generated in a format for log management
  • Establish effective monitoring and alerting
  • Create incident response plan
A10

Server-Side Request Forgery (SSRF)

MEDIUM

SSRF flaws occur when a web application fetches a remote resource without validating the user-supplied URL. It allows attackers to coerce the application to send requests to an unexpected destination.

Common Weaknesses
  • Fetching URLs provided by users without validation
  • Accessing internal services via user-supplied URLs
  • Cloud metadata endpoint access
  • Internal network scanning
Mitigations
  • Segment remote resource access functionality
  • Enforce "deny by default" firewall policies
  • Sanitize and validate all user-supplied URLs
  • Disable HTTP redirections
