Penetration Testing Phases

📋

1. Planning & Reconnaissance

Scope: Define targets, rules of engagement, success criteria
OSINT: Passive information gathering (DNS, WHOIS, social media)
Active Recon: Network mapping, subdomain enumeration
Tools: Maltego, theHarvester, Shodan, Recon-ng

🔍

2. Scanning & Enumeration

Port Scanning: Identify open services (TCP/UDP)
Service Detection: Version fingerprinting, banner grabbing
OS Detection: Identify operating systems and patch levels
Tools: Nmap, Masscan, Unicornscan, Netcat

🎯

3. Vulnerability Analysis

CVE Matching: Compare versions to known vulnerabilities
Config Audit: Identify misconfigurations and weak settings
Manual Testing: Logic flaws, business logic bypass
Tools: Nessus, OpenVAS, Burp Suite, OWASP ZAP

💥

4. Exploitation

Manual Exploits: SQL injection, XSS, command injection
Automated Exploits: Metasploit Framework, ExploitDB
Proof of Concept: Demonstrate impact without damage
Tools: Metasploit, SQLMap, BeEF, Custom scripts

🔗

5. Post-Exploitation

Privilege Escalation: Gain higher-level access
Lateral Movement: Pivot to other systems
Data Exfiltration: Simulate data theft (non-destructive)
Tools: Mimikatz, PowerSploit, Empire, BloodHound

📊

6. Reporting

Executive Summary: Business impact, risk ratings
Technical Details: Vulnerability descriptions, POC, remediation
Remediation Plan: Prioritized action items with timelines
Retesting: Validate fixes and confirm closure

Penetration Testing Types

🖤

Black Box Testing

No Prior Knowledge: Simulates external attacker with zero info
Realistic Approach: Tests actual attack surface visibility
Time-Intensive: Requires extensive reconnaissance
Best For: External network, public-facing applications
⚪

White Box Testing

Full Disclosure: Complete access to source code, architecture
Comprehensive: Deep analysis of code and logic flaws
Time-Efficient: Faster identification of vulnerabilities
Best For: Code review, API testing, secure SDLC integration
🩶

Grey Box Testing

Partial Knowledge: Limited credentials or documentation
Balanced Approach: Simulates insider or compromised user
Practical: Most common real-world testing scenario
Best For: Internal applications, hybrid environments
🔴

Red Team Engagement

Adversarial Simulation: Full-scope attack simulation
Objective-Driven: Achieve specific goals (e.g., exfiltrate data)
Social Engineering: Includes phishing, physical access
Best For: Mature security programs, compliance validation

Penetration Testing Best Practices

📝

Legal & Compliance

Always obtain written authorization before testing. Define clear rules of engagement, scope boundaries, and emergency contacts. Maintain chain of custody for evidence.

⏱️

Scheduled Testing

Conduct annual penetration tests at minimum. Perform tests after major changes (new features, infrastructure updates). Schedule during maintenance windows when possible.

🎯

Goal-Oriented

Define clear objectives (e.g., "access customer database", "gain domain admin"). Focus on realistic attack scenarios. Test critical business functions first.

📊

Actionable Reporting

Provide executive summary with business impact. Include technical details with step-by-step reproduction. Prioritize findings with CVSS scores and remediation guidance.

🔄

Retesting

Validate remediation effectiveness through retesting. Track vulnerability closure rates. Build regression test suites for recurring issues.

🤝

Collaboration

Work with dev/ops teams, not against them. Provide security training based on findings. Foster a culture of continuous security improvement.
