Step 1: Define Scope

Begin by defining the boundaries of your threat model. Identify the system, application, or component you want to analyze and establish clear boundaries.

Scoping Tips

  • Start with a well-defined component or feature
  • Identify all entry and exit points
  • Document data flows and trust boundaries

Step 2: STRIDE Threat Analysis

STRIDE is a threat classification model developed by Microsoft. Select each threat category to identify potential threats in your system.

S - Spoofing Identity

Pretending to be someone or something else. Includes using stolen credentials, forging authentication tokens, or impersonating other systems.

"Can an attacker impersonate a user, service, or system?"

T - Tampering with Data

Unauthorized modification of data at rest or in transit. Includes altering database records, modifying API requests, or corrupting files.

"Can an attacker modify data or system behavior?"

R - Repudiation

Denying having performed an action without ability to prove otherwise. Includes lack of audit logs, unsigned transactions, or missing non-repudiation controls.

"Can a user deny performing an action?"

I - Information Disclosure

Unauthorized access to sensitive information. Includes data breaches, error message leakage, or insufficient access controls on data stores.

"Can an attacker access sensitive information?"

D - Denial of Service

Making a system unavailable or degrading its performance. Includes resource exhaustion, DDoS attacks, or algorithmic complexity attacks.

"Can an attacker disrupt or degrade service availability?"

E - Elevation of Privilege

Gaining capabilities without proper authorization. Includes privilege escalation, bypassing authorization, or exploiting trust relationships.

"Can an attacker gain higher privileges than authorized?"
