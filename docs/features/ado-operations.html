Overview

ADO Operations brings Planning System 2.0's quality standards to Azure DevOps work items. Create User Stories, Features, Tasks, Bugs, and Epics with the same DoR/DoD compliance, TDD integration, and contextual review that makes Planning System 2.0 world-class. All output is ADO-formatted markdown ready for copy-paste into Azure DevOps.

📋 Work Item Types

Command: plan ado story

Template Structure:

  • Title: Concise feature description
  • Description: "As a [user], I want [feature], so that [benefit]"
  • Acceptance Criteria: Testable conditions (interactive refinement)
  • Story Points: SWAG estimation via Swagger (if API-related)
  • Priority: High/Medium/Low/Very Low
  • DoR Validation: Iterative questioning until unambiguous
  • TDD Plan: RED→GREEN→REFACTOR per layer

Example: "As a registered user, I want to log in with email/password, so that I can access my account securely"

Command: plan ado feature

Template Structure:

  • Title: High-level feature name
  • Description: Business value proposition
  • Child Stories: Auto-generated story breakdown (3-8 stories)
  • Dependencies: External APIs, databases, services
  • Technical Approach: Architecture decisions documented
  • Rollout Strategy: Phased deployment plan
  • Contextual Review: Auto-run before feature planning

Example: "User Authentication System" → Generates stories for login, signup, password reset, session management

Command: plan ado task

Template Structure:

  • Title: Specific technical action
  • Description: Implementation details
  • Estimated Hours: Time-boxed work units
  • Parent: Links to story or feature
  • Files Modified: Expected file changes
  • DoD Checklist: Code complete, tests pass, reviewed

Example: "Configure JWT token middleware" - 2 hours, modifies auth/middleware.py

Command: plan ado bug

Template Structure:

  • Title: Symptom description
  • Steps to Reproduce: Exact reproduction path
  • Expected Behavior: What should happen
  • Actual Behavior: What actually happens
  • Root Cause: Why bug occurred (after analysis)
  • Fix Strategy: How to resolve
  • Regression Test: TDD test to prevent recurrence

Command: plan ado epic

Template Structure:

  • Title: Strategic goal (e.g., "Payment Processing System")
  • Business Objective: Why this matters (revenue, retention, compliance)
  • Child Features: 3-10 features with story breakdowns
  • Timeline: Quarterly roadmap
  • Success Metrics: KPIs to track
  • Stakeholders: Who needs to be involved

📦 Work Summaries

Generate Completion Summary

After completing work, generate an ADO-formatted summary with:

Command:

generate ado summary

Summary Includes:

  • Work Item Metadata: ID, type, title, status
  • Files Changed: Created, modified, tested (with line counts)
  • Test Results: RED phase failures → GREEN phase passes
  • Technical Decisions: Architecture choices documented
  • DoD Validation: All criteria met checklist
  • Time Tracking: Estimated vs actual hours
  • Copy-Paste Ready: Markdown formatted for ADO comments

Example Output:

## Work Item Summary

**ID:** 12345
**Type:** User Story
**Title:** User Login with Email/Password
**Status:** ✅ Completed

### Files Changed
- **Created:** auth/login.py (145 lines), auth/tests/test_login.py (87 lines)
- **Modified:** auth/__init__.py (+5 lines), routes.py (+12 lines)
- **Tested:** 94% coverage (15 tests, all passing)

### Technical Decisions
1. JWT tokens for session management (30-minute expiry)
2. bcrypt for password hashing (cost factor 12)
3. Rate limiting: 5 failed attempts → 15-minute lockout

### DoD Validation
- ✅ Code complete (4 files modified)
- ✅ Tests passing (15/15 green, RED→GREEN cycle documented)
- ✅ Code reviewed (peer review by @teammate)
- ✅ Documentation updated (README + API docs)
- ✅ Acceptance criteria validated (all 5 criteria met)

🔗 Integration with Planning System

ADO Operations seamlessly integrates with Planning System 2.0:

Start with plan [feature], then create ADO items from the plan:

  • Planning System generates detailed phase-by-phase plan
  • ADO Operations converts phases into work items (stories/tasks)
  • Contextual review findings auto-propagate to ADO items
  • TDD test specs from plan become acceptance criteria in stories

Both systems route through unified_entry_point_utility.py:

  • Shared workflow result tracking
  • Automatic summary generation across operations
  • Cross-operation integration (plan → ADO → code review)
  • Universal result container for consistent output
