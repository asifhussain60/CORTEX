What are ADO Operations?

ADO Operations extends CORTEX's Planning System to generate Azure DevOps-formatted work items with all the intelligence of strategic planning. It inherits all 10 planning phases, DoR/DoD compliance, and TDD integration while outputting Markdown-formatted stories, features, and epics optimized for ADO boards.

This bridges the gap between CORTEX's intelligent planning and enterprise project management workflows, enabling teams to use CORTEX for planning while tracking work in Azure DevOps.

How ADO Operations Work

1️⃣

Inherit Planning

Uses full Planning System workflow with all 10 phases.

2️⃣

ADO Formatting

Transforms output to ADO Markdown with proper sections.

3️⃣

Work Item Type

Detects appropriate type (Story/Feature/Epic) by scope.

4️⃣

Generate Output

Creates ready-to-paste ADO work item description.

ADO Work Item Types

📋

User Story

Small, focused work item representing single feature or change.

Complexity: LOW-MEDIUM
Duration: 1-3 days
Example: "Add export button to dashboard"
Sections: Description, Acceptance Criteria, Tasks, DoD
🎯

Feature

Collection of related stories delivering significant functionality.

Complexity: MEDIUM-HIGH
Duration: 1-2 weeks
Example: "Implement analytics dashboard"
Sections: Overview, Architecture, Stories, Timeline
🚀

Epic

Large initiative spanning multiple features and teams.

Complexity: HIGH
Duration: 1-3 months
Example: "Build reporting platform"
Sections: Vision, Features, Roadmap, Dependencies

ADO Markdown Format

Example ADO Story Output

## 📋 User Story
**As a** developer
**I want to** export dashboard data as CSV
**So that** I can analyze data in Excel

---

## ✅ Acceptance Criteria
- [ ] Export button visible on dashboard header
- [ ] CSV file contains all visible data columns
- [ ] Exported file follows naming convention: dashboard_export_YYYYMMDD.csv
- [ ] Export completes within 5 seconds for datasets <10K rows

---

## 🎯 Tasks
1. [ ] Add export button component to dashboard header (RED phase)
2. [ ] Implement CSV generation service (GREEN phase)
3. [ ] Add unit tests for CSV formatting (GREEN phase)
4. [ ] Refactor for performance optimization (REFACTOR phase)
5. [ ] Add integration test with sample data (DoD validation)

---

## 📊 Definition of Done
- [ ] All tests passing (unit + integration)
- [ ] Code coverage ≥80%
- [ ] Documentation updated
- [ ] Code reviewed and approved
- [ ] No performance regressions
- [ ] Acceptance criteria validated
