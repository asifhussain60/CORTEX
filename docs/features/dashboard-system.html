Overview

CORTEX Dashboard is a pure client-side, glassmorphism-designed web application that visualizes repository health, architecture, security, and team metrics. No backend required—just generate 7 JSON files from your repository scanner and launch the HTTP server. Features auto-port fallback (8080-8089), CORS support, and responsive design.

🎨 Glassmorphism Design System

Modern dark mode aesthetic with translucent cards, subtle animations, and cyan/purple accent gradient:

Glass Cards

backdrop-filter: blur(10px) with rgba backgrounds for translucent depth effect.

Responsive Grid

Mobile-first with 768px breakpoint for tablet/desktop layouts.

📁 7 Required JSON Files

Your repository scanner must generate these files in cortex-brain/dashboards/{source}/:

Purpose: Overall health score, test coverage, documentation completeness, technical debt indicators

Key Fields:

  • health_score: 0-100 overall health rating
  • test_coverage: Percentage of code covered by tests
  • documentation_completeness: README, docstrings, comments
  • technical_debt_hours: Estimated hours to fix issues
  • last_commit_date: Recent activity indicator

Purpose: Programming languages, frameworks, libraries with version info

Key Fields:

  • languages: [{name, percentage, loc}] - Language distribution
  • frameworks: [{name, version}] - React, Flask, Express, etc.
  • dependencies: [{name, version, outdated}] - Package list
  • total_loc: Total lines of code

Purpose: Security scan results, OWASP Top 10 compliance, vulnerability counts

Key Fields:

  • security_score: 0-100 security rating
  • vulnerabilities: [{severity, cve_id, description}]
  • owasp_compliance: {A01_broken_access_control: passed, ...}
  • secrets_exposed: Count of exposed API keys/passwords

Purpose: Directory structure, module dependencies, architecture patterns

Key Fields:

  • architecture_pattern: MVC, Microservices, Monolith, etc.
  • components: [{name, type, dependencies}] - Module graph
  • circular_dependencies: List of circular import chains
  • cohesion_score: 0-100 module cohesion rating

Purpose: Cyclomatic complexity, code smells, hotspots needing refactoring

Key Fields:

  • average_complexity: Mean cyclomatic complexity across codebase
  • hotspots: [{file, complexity, churn}] - Files changed frequently
  • code_duplication: Percentage of duplicated code blocks
  • long_methods: Methods exceeding 50 lines

Purpose: Team velocity, commit patterns, contributor statistics

Key Fields:

  • contributors: [{name, commits, additions, deletions}]
  • commit_frequency: Commits per day/week/month
  • average_pr_size: Mean lines changed per pull request
  • bus_factor: Number of people who know critical code

Purpose: External APIs, cloud services, monitoring tools

Key Fields:

  • cloud_providers: AWS, Azure, GCP with services used
  • apis: [{name, url, authentication_method}]
  • monitoring: Datadog, New Relic, Sentry configurations
  • ci_cd: GitHub Actions, Jenkins, CircleCI status

📖 Full JSON Schema: See cortex-brain/documents/user-guides/dashboard-data-format-guidelines.md for exact field specifications and validation rules.

🚀 Launch Dashboard

Quick Start

1. Generate JSON Files:

Run your repository scanner and output 7 JSON files to cortex-brain/dashboards/{source}/

2. Launch Server (GitHub Copilot Chat):

load dashboard

Auto-starts HTTP server on port 8080-8089, opens browser

3. View Dashboard:

http://localhost:8080/ui/index.html?source=mock

Change source parameter to your repository name

Manual Launch (PowerShell)

cd cortex-brain/dashboards
python -m http.server 8080

⚙️ Technical Architecture

If port 8080 is busy, the launcher automatically tries ports 8081-8089 until it finds an available port:

  • Checks port availability with socketserver.TCPServer
  • Kills existing Python HTTP servers on target port (Windows/Unix)
  • Falls back to next port if kill fails
  • Returns error if all 10 ports occupied

Custom CORSHTTPRequestHandler extends SimpleHTTPRequestHandler:

  • Access-Control-Allow-Origin: *
  • Access-Control-Allow-Methods: GET, POST, OPTIONS
  • Cache-Control: no-store (disable caching for dev)

All logic runs in browser—HTTP server only serves static files:

  • JavaScript fetches JSON files via fetch()
  • Data processing happens client-side (filtering, sorting, charting)
  • No database, no API endpoints, no server-side rendering
  • Works offline after initial load (service worker optional)

Comprehensive test suite in cortex-brain/dashboards/ui/tests/:

  • Integration tests: Tab rendering, data loading, navigation
  • Unit tests: Data validation, utility functions, error handling
  • Test framework: Jest + JSDOM for browser simulation
  • Coverage: 94% code coverage across all UI components
