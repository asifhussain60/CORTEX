Executive Summary

System Maintenance is CORTEX's comprehensive health and optimization orchestrator. In a single command, it runs 6 sequential phases: pre-healthcheck (baseline), alignment (auto-fix issues), cleanup (remove obsolete files), optimization (performance tuning), prompt refresh (regenerate documentation), and post-healthcheck (validation). Each phase builds on the previous, with conditional execution ensuring safe operation.

6-Phase Maintenance Workflow

📊 Phase 1: Pre-Maintenance Healthcheck

▼

Purpose: Establish baseline system health before making changes

What happens:

  • 15+ System Checks: File integrity, imports, YAML validation, brain health
  • Metrics Collection: Operation counts, orchestrator inventory, test coverage
  • Baseline Report: JSON report saved to cortex-brain/health-reports/
  • Risk Assessment: Identifies critical vs warning issues

Sample output:

✅ Pre-healthcheck: 13/15 checks passed (2 warnings)
├── Operations: 302 registered
├── Orchestrators: 8 active
├── Test Coverage: 87%
└── Brain Health: GOOD

🔄 Phase 2: System Alignment (Auto-Fix)

▼

Purpose: Automatically fix common issues and synchronize system state

What happens:

  • Auto-Fix Enabled: Applies fixes automatically (no manual intervention)
  • Operation Registration: Scans src/ and registers missing operations
  • YAML Validation: Checks cortex-operations.yaml for consistency
  • Import Resolution: Fixes broken imports and missing modules
  • Git Sync: Ensures CORTEX/user repo isolation

Sample fixes applied:

✅ Alignment: 4 fixes applied
├── Registered 3 new operations
├── Fixed 1 broken import
├── Updated YAML (consistency)
└── Validated git isolation

🧹 Phase 3: Cleanup Orchestrator

▼

Purpose: Remove obsolete files, organize structure, free disk space

What happens:

  • Obsolete File Detection: Identifies unused/outdated files
  • Safe Backup: Archives to cortex-brain/archives/ before deletion
  • Reference Updates: Updates imports and links to moved files
  • Space Optimization: Compresses logs, removes duplicates
  • Structure Validation: Ensures cortex-brain/ organization

Safety features:

  • Dry-run mode available (preview changes without applying)
  • Git checkpoint before any deletions
  • Rollback capability (restore from archives)

⚡ Phase 4: CORTEX Optimization

▼

Purpose: Performance tuning and efficiency improvements

What happens:

  • Query Optimization: Indexes brain databases for faster queries
  • Token Reduction: Compresses prompts, removes redundancy
  • Cache Warming: Pre-loads frequently accessed data
  • Memory Optimization: Trims Tier 1 working memory (FIFO enforcement)
  • Benchmarking: Measures before/after performance

Conditional execution:

Only runs if Phase 2 (Alignment) succeeds. If alignment fails, optimization is skipped to prevent optimizing a broken system.

📝 Phase 5: Refresh Prompts

▼

Purpose: Regenerate documentation and prompt files with latest content

What happens:

  • Prompt Regeneration: Updates .github/prompts/ with latest operations
  • Module Guides: Regenerates planning, TDD, response format guides
  • Feature Catalogs: Updates capabilities.yaml with new features
  • API Documentation: Refreshes docstring-based API docs
  • Version Sync: Ensures version numbers consistent across files

Why this matters:

As CORTEX evolves, documentation can become stale. This phase ensures GitHub Copilot always has the latest operation list, command syntax, and feature descriptions.

✅ Phase 6: Post-Maintenance Healthcheck

▼

Purpose: Validate improvements and ensure system stability

What happens:

  • Re-run All Checks: Same 15+ checks as Phase 1
  • Before/After Comparison: Shows improvements vs baseline
  • Regression Detection: Alerts if any checks worsened
  • Final Report: Comprehensive JSON with all 6 phases

Success criteria:

✅ Post-healthcheck: 15/15 checks passed
   Improvements: +2 checks (13→15)
   Warnings: -2 (2→0)
   System Health: EXCELLENT

SKULL Protection Integration

System Maintenance respects SKULL rules throughout execution:

GIT_ISOLATION_ENFORCEMENT

Phase 2 (Alignment) validates CORTEX code never touches user repos. Git checkpoints before Phase 3 (Cleanup) ensure safe rollback.

REFACTOR_CODE_CLEANUP_ENFORCEMENT

Phase 3 (Cleanup) enforces removal of orphaned code and obsolete files, satisfying this SKULL rule automatically.

HOLISTIC_CODE_DISCOVERY_ENFORCEMENT

Phase 2 (Alignment) searches entire codebase for duplicate operations before registration, preventing code duplication.

How to Use

Simple command in Copilot Chat: 

system maintenance

Alternative commands:

  • maintain system
  • run maintenance
  • full maintenance
  • comprehensive maintenance

All commands execute the same 6-phase workflow. No configuration needed.
