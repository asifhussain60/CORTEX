Overview

Planning System 2.0 transforms feature requests into executable, phase-by-phase plans with built-in quality gates. The system automatically detects complexity (LOW/MEDIUM/HIGH), validates Definition of Ready (DoR), generates Definition of Done (DoD) criteria, integrates TDD at every layer, and can execute autonomously through all phases with continuous user feedback loops.

🎯 Auto-Complexity Detection

The system analyzes your feature request and automatically routes to the appropriate planning strategy:

🔴

HIGH Complexity

Security, Auth, Migrations, Multi-Tier APIs

Triggers:

Authentication, authorization, database migrations, payment integration, complex APIs, data pipelines

Strategy:

Incremental delivery with phased rollout

Phases:

4-6 phases with checkpoints

Example:

"Implement OAuth2 authentication with social login"

  • Phase 0: Contextual architectural review (auto-fix blockers)
  • Phase 1: Core authentication infrastructure
  • Phase 2: Social provider integration (Google, GitHub)
  • Phase 3: Token management & refresh
  • Phase 4: Security hardening & audit logging

✅ DoR/DoD Compliance Framework

📋

Definition of Ready (DoR)

Interactive Validation

Before planning begins, the system validates that all prerequisites are met through an interactive question-based workflow:

  • Feature clearly defined: "What problem does this solve for users?"
  • Acceptance criteria exist: "How will we know it's done?"
  • Dependencies identified: "What systems/APIs does this rely on?"
  • Technical feasibility confirmed: "Are there any blockers?"
  • Scope bounded: "What's explicitly out of scope?"
Iterative Refinement: You approve each DoR item individually. The system asks clarifying questions until requirements are unambiguous.

✅

Definition of Done (DoD)

Quality Gates

Each phase generates specific DoD criteria that must be met before proceeding:

  • Code complete: All planned files implemented
  • Tests passing: RED→GREEN→REFACTOR cycle completed
  • Coverage requirements met: 94% minimum per layer
  • Documentation updated: README, API docs, inline comments
  • Code review complete: Peer review or architectural review
  • Acceptance criteria validated: Feature works as specified
Approval Gate: After Phase 3, you explicitly approve acceptance criteria before autonomous execution proceeds. Visual checklist ensures nothing is missed.

🎯

TDD Integration

Every Phase, Every Layer

TDD is not optional—it's baked into every phase of the plan:

  • RED: Write failing test first (validates requirement understanding)
  • GREEN: Implement minimum code to pass
  • REFACTOR: Clean up while maintaining green tests
  • 4-Layer Coverage: Unit → Integration → System → Acceptance
  • Empty Test Detection: No placeholder tests allowed
  • Test-First Enforcement: SKULL rules block implementation-first commits
