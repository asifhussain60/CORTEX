Executive Summary

CORTEX's Response Template System ensures consistent, high-quality AI responses across all operations. Responses use an ADAPTIVE tier-based structure that scales with task complexity - from instant answers to comprehensive multi-phase guidance. With 29 specialized templates, 3 interaction modes (autonomous, guided, detailed), and multilingual support, CORTEX adapts responses to user expertise and context while maintaining professional standards.

Adaptive Tier-Based Response Structure

CORTEX response complexity scales with task requirements: 

## 🧠 CORTEX {Title}
**Author:** Asif Hussain | **GitHub:** github.com/asifhussain60/CORTEX

---

{Adaptive content based on tier}
- INSTANT: Direct answer only (<50 tokens)
- FOCUSED: Solution + context (50-200 tokens)
- STANDARD: Analysis + implementation (200-500 tokens)
- COMPREHENSIVE: Full multi-phase guidance (500+ tokens)

### 🔍 Next Steps
{EXACTLY ONE actionable next step OR completion message}

Rules:

✅ H2 with 🧠, adaptive content depth based on complexity
✅ Author line + one --- separator
✅ Response scales: instant → comprehensive based on task
❌ NO extra separators, NO code unless requested

Interaction Modes

CORTEX adapts response detail level based on user expertise:

🚀 Autonomous Mode (Experienced Users)

For: Users who know CORTEX well and want minimal guidance

Concise responses by default
Action-focused, minimal explanations
No "Challenge" section unless critical
Compact format preferred

🎓 Guided Mode (Standard Users)

For: Users learning CORTEX or working on unfamiliar features

Balanced detail level
Explanations for why decisions made
Step-by-step guidance when needed
Links to documentation

📚 Detailed Mode (Learning/Onboarding)

For: New users or complex operations requiring deep explanation

Comprehensive explanations
Educational context and rationale
Examples and code snippets
Best practices and pitfalls

Intelligent Template Selection

CORTEX automatically selects templates based on:

1. Operation Type

Maps user command to template via cortex-operations.yaml. For example, plan [feature] → planning template.

2. User Intent

Analyzes natural language patterns. "Should we..." triggers decision-making template. "How does..." triggers explanation template.

3. Context

First interaction? Use onboarding template. Mid-planning session? Use interactive_planning. Error occurred? Use error-recovery.

4. Fallback Strategy

If no template matches, uses fallback template with adaptive tier-based structure. Never fails to respond.

Real-World Example: Planning Template

User command: plan authentication system

Template selection:

1. Operation: "plan" → planning template
2. Complexity: "authentication" → HIGH (triggers incremental planning)
3. Mode: User history → Guided mode
4. Result: planning template + detailed DoR/DoD + TDD integration

Technical Implementation

Template system components:

cortex-brain/response-templates.yaml - 29 templates (14,718 lines)
cortex-brain/response-profile-variants.yaml - Interaction modes (395 lines)
cortex-brain/response-routing-rules.yaml - Template selection logic
cortex-brain/multilingual-templates.yaml - Language support
src/response_templates/ - Template rendering engine

Templates use Jinja2-style variable substitution and support conditional sections based on operation context, user mode, and response requirements.
