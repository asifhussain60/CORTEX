🏛️ CORTEX Architecture

Four-Tier Brain, Agent System, and Orchestrator Ecosystem

🧠 4 Brain Tiers 🤖 2 Specialist Agents ⚙️ 8 Orchestrators 📅 Updated: Dec 2025

📋 Executive Summary

CORTEX is built on a four-tier brain architecture that provides intelligent memory management, pattern learning, and context preservation across conversations. Two specialist agents (Planning and Strategic Reasoning) work within orchestrators to coordinate complex multi-phase workflows. The system enforces safety through SKULL brain protection rules at Tier 0, while maintaining sub-100ms working memory access at Tier 1.

Key Architectural Principles:
  • Brain Protection First: Tier 0 SKULL rules enforce safety
  • Test-Driven Development: TDD mandatory for all production code
  • Git Isolation: CORTEX code never mixed with user repos
  • Context Preservation: Four-Tier Brain maintains long-term memory

Tier Details

🛡️

Tier 0: Governance

SKULL Brain Protection Rules

Purpose

  • Brain protection and safety enforcement
  • Validates all operations before execution
  • Prevents code duplication and anti-patterns

SKULL Rules

  • TDD_ENFORCEMENT: RED→GREEN→REFACTOR mandatory
  • HOLISTIC_DISCOVERY: Search before create
  • REFACTOR_CLEANUP: Remove orphaned code
  • GIT_ISOLATION: CORTEX/user separation

Storage

  • cortex-brain/brain-protection-rules.yaml
💾

Tier 1: Working Memory

70-Conversation FIFO Buffer

Purpose

  • Recent conversation history with fast access
  • Sub-100ms retrieval performance
  • Context for current session

Capabilities

  • Retention: Last 70 conversations
  • Format: JSON Lines (JSONL)
  • Cleanup: Automatic FIFO eviction
  • Performance: < 100ms retrieval

Storage

  • cortex-brain/conversation-context.jsonl
🕸️

Tier 2: Knowledge Graph

Pattern Learning & Relationships

Purpose

  • Long-term pattern storage
  • Relationship mapping between modules
  • Technology stack learning

Capabilities

  • Patterns: Code patterns, architectural decisions
  • Relationships: Module dependencies
  • Learning: Technology stack patterns
  • Retrieval: Context-aware matching

Storage

  • cortex-brain/knowledge-graph.yaml
📊

Tier 3: Development Context

Per-Repository Metrics

Purpose

  • Repository-specific context and metrics
  • Multi-repo support (1:∞ scaling)
  • Hotspot and complexity tracking

Capabilities

  • Hotspots: High change frequency files
  • Complexity: Cyclomatic complexity tracking
  • Coverage: Per-module test coverage
  • Multi-Repo: Separate context per repo

Storage

  • cortex-brain/development-context.yaml
⚡

Performance Profile

Speed & Efficiency

Response Times

  • Tier 0: Instant (rule validation)
  • Tier 1: < 100ms (memory access)
  • Tier 2: < 500ms (pattern matching)
  • Tier 3: < 1s (metric retrieval)

Storage Size

  • Total: ~500MB (codebase + brain)
  • Tier 1: ~5MB (70 conversations)
  • Tier 2: ~50MB (patterns)
  • Tier 3: ~10MB per repo
🔄

Brain Maintenance

Automatic Optimization

Cleanup Operations

  • FIFO Eviction: Tier 1 (automatic)
  • Pattern Pruning: Tier 2 (monthly)
  • Metric Refresh: Tier 3 (per commit)
  • Backup: All tiers (weekly)

Health Checks

  • SKULL rule validation

Agent Collaboration

Orchestrator Integration Pattern

How Agents Work

  • Embedded: Not standalone services
  • Context-Aware: Access to Four-Tier Brain
  • Orchestrator-Driven: Invoked by workflow phases
  • Stateless: No persistent agent state

Communication Pattern

  • Orchestrator passes context bundle
  • Agent analyzes and generates output
  • Output stored in brain tiers
  • Orchestrator proceeds to next phase

Future Expansion

  • Testing Agent (test generation)
  • Refactoring Agent (code improvement)
  • Documentation Agent (doc generation)

TDD Orchestrator

RED→GREEN→REFACTOR Workflow

Purpose

  • Enforce test-driven development
  • Prevent untested production code
  • Maintain >80% coverage

Phases

  • RED: Write failing tests
  • GREEN: Minimal passing code
  • REFACTOR: Improve design

Validation

  • Tests must fail initially (RED)
  • All tests must pass (GREEN)
  • Coverage maintained (REFACTOR)
