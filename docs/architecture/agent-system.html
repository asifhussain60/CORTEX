CORTEX Agent System

Specialized autonomous agents coordinating via shared brain tiers

Overview

CORTEX's agent system consists of 4 specialized agents that divide responsibilities for planning, execution, learning, and analysis. Unlike traditional monolithic AI assistants, CORTEX agents operate autonomously with clearly defined roles, coordinating through the 4-tier brain architecture.

This separation of concerns enables parallel processing, specialized expertise, and fail-safe isolation—if one agent encounters an error, others continue operating. Agents communicate via Tier 1 Working Memory, share knowledge through Tier 2, and respect Tier 0 governance rules universally.

The Four Agents

Planning Agent

Role: Creates incremental development plans with phases, tasks, and acceptance criteria.
Input: User feature request + knowledge graph patterns
Output: 17-phase plan structure in Tier 1
Key Logic: Phase -1 knowledge loading, AST scanning integration, visual progress generation

Execution Agent

Role: Implements code according to plan phases using TDD workflow.
Input: Active plan from Tier 1 + dev context from Tier 3
Output: Code files, tests, refactored implementation
Key Logic: RED→GREEN→REFACTOR enforcement, holistic discovery, git isolation

Learning Agent

Role: Extracts patterns, lessons, and relationships from completed work.
Input: Execution results + plan outcomes + error logs
Output: Knowledge graph updates in Tier 2
Key Logic: Pattern recognition, anti-pattern detection, relationship mapping

Analysis Agent

Role: Performs root cause analysis, architectural reviews, and debugging.
Input: Error reports + stack traces + architectural context
Output: Root cause report + fix recommendations
Key Logic: Holistic review, brittleness detection, dependency analysis

Agent Coordination Patterns

Sequential Hand-off

Pattern: Planning Agent → Execution Agent → Learning Agent
Use Case: New feature development
Flow:

  1. User requests feature via Master Orchestrator
  2. Planning Agent creates 17-phase plan, stores in Tier 1
  3. Execution Agent reads plan, implements Phase 1, updates progress
  4. After completion, Learning Agent extracts patterns, updates Tier 2

Parallel Execution

Pattern: Multiple agents run simultaneously on different tasks
Use Case: Complex plan with independent phases
Example: Execution Agent implements Phase 5 (API endpoint) while Learning Agent analyzes Phase 4 results

Reactive Invocation

Pattern: Agent triggered by system event
Use Case: Error occurs during execution
Flow: Execution Agent encounters error → Analysis Agent automatically invoked → Root cause report generated

Agent Communication via Brain Tiers

Tier 1: Shared State
Agents read/write active plans, conversation context, execution status. Primary coordination mechanism.
Tier 2: Collective Knowledge
Learning Agent writes patterns. Planning/Execution agents read to improve decisions.
Tier 0: Universal Constraints
All agents must obey SKULL rules. No exceptions.
Tier 3: Execution Context
Only Execution Agent writes to workspace. Others read-only.

Real-World Example: Feature Implementation

Scenario: User requests /CORTEX plan user authentication

Step 1: Planning Agent (2 minutes)

  • Loads Phase -1 knowledge modules: API design, authentication patterns, security best practices
  • Scans workspace for existing auth code via AST scanning
  • Creates 17-phase plan with OAuth2, JWT, session management, password hashing
  • Stores plan in Tier 1 (PlanningStateDB), status = "active", phase = 0

Step 2: Execution Agent (45 minutes, 17 iterations)

  • Phase 1: Create User model (TDD: failing test → implementation → refactor)
  • Phase 2: Add password hashing (bcrypt integration)
  • Phase 3: Implement JWT token generation
  • ...continues through Phase 17: Final REFACTOR cleanup
  • Updates Tier 1 after each phase (progress tracker, acceptance criteria validation)

Step 3: Learning Agent (5 minutes)

  • Analyzes plan outcome: 17/17 phases complete, all tests passing
  • Extracts patterns: OAuth2 + JWT + Redis session pattern successful
  • Records lessons: "Password hashing must use bcrypt cost factor ≥12"
  • Updates Tier 2 knowledge graph with new authentication pattern node
