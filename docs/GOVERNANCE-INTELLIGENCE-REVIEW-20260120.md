# CORTEX Governance Intelligence Review
## Evaluating Context-Aware, Situational Rule Application

**Date**: 2026-01-20  
**Review Focus**: Does CORTEX master orchestrator intelligently apply governance rules based on context?  
**Status**: ⚠️ **CRITICAL GAP IDENTIFIED**

---

## Executive Summary

**Finding**: CORTEX contains sophisticated governance infrastructure but **lacks context-aware, situational rule application logic**. Rules are applied uniformly across all contexts rather than intelligently evaluated based on operation type, file type, or phase.

**Impact**: 
- ❌ CORE-022/CORE-028 (file naming) applied to Python files but not strategic configs
- ❌ CORE-008 (TDD) expected uniformly but not conditionally for tool vs. production code
- ❌ No mechanism to skip rules for generated or third-party files
- ❌ Response headers (CORE-030) applied as immutable requirement with no context filtering

**Recommendation**: Implement situational rule engine that evaluates rule applicability before enforcement.

## Part 5: What SHOULD Exist

### 5.1 Situational Rule Application Framework

**Missing component**: Context-aware rule dispatcher

```python
class SituationalRuleEvaluator:
    """
    Evaluates rule applicability BEFORE enforcement.
    
    Example:
    - CORE-022 applies to user-facing files, not generated code
    - CORE-008 applies to production code, relaxed for utilities
    - CORE-030 applies to orchestrator responses, not error messages
    """
    
    def should_apply_rule(
        self,
        rule_id: str,
        context: RuleContext
    ) -> bool:
        """
        Determine if rule should be enforced in this context.
        
        Examples:
        - should_apply_rule("CORE-022", context={"file_type": "py", "context": "internal"})
          → False (Python internals exempt from kebab-case)
        
        - should_apply_rule("CORE-008", context={"operation": "create_file", "phase": "exploration"})
          → False (Early exploration allows test-after)
        
        - should_apply_rule("CORE-030", context={"response_type": "error_message"})
          → False (Error messages don't need ornamental headers)
        """
```

## Part 8: Conclusion

### Finding Summary

**CORTEX has:**
- ✅ Sophisticated, well-documented governance rules (29 rules)
- ✅ Tiered enforcement system with proper precedence (Tier 0 > 1 > 2)
- ✅ Comprehensive audit trail infrastructure
- ✅ Governance gate integration at orchestrator level

**CORTEX lacks:**
- ❌ Context-aware rule applicability determination
- ❌ Situational enforcement (rules applied uniformly, not by context)
- ❌ Rule-to-context mapping (which rules apply where?)
- ❌ Intelligent skipping of inapplicable rules
- ❌ File-type/operation-type dispatch logic

### Intelligent Application Expected

**Your question**: "Does CORTEX intelligently apply rules based on context?"

**Answer**: **No, not yet.**

The framework exists but the intelligence is missing. Rules are:
- ✓ Well-defined with clear intent
- ✓ Registered and indexed properly  
- ❌ Applied universally instead of situationally
- ❌ Lacking context evaluation before enforcement

### Path Forward

Implement situational rule evaluation (Priority 1-3 above) to enable the master orchestrator to:
- ✓ Know which rules apply to each operation
- ✓ Skip rules that don't apply (generated code, test fixtures, etc.)
- ✓ Enforce strictly where rules DO apply
- ✓ Provide clear justification for rule application decisions

**Estimated total effort**: 4-6 days (1 developer)  
**Impact**: Transforms CORTEX from uniform rule application to truly intelligent, context-aware governance.
