Chapter 1

What Is Claude Code?

Claude Code is an AI-powered coding agent built by Anthropic. Think of it as a developer teammate that lives inside your terminal (or IDE). Unlike a chatbot that just answers questions, Claude Code reads your files, edits your code, runs commands, and verifies results — all while you watch, redirect, or step away entirely.

💡
Key mental shift Instead of writing code yourself and asking an AI to review it, you describe what you want and Claude figures out how to build it. You become the architect; Claude becomes the builder.

What can it actually do?

🏗️
Build Features
Implement auth, APIs, UI — from spec to code
🐛
Fix Bugs
Diagnose errors, trace issues, patch & verify
🧪
Write Tests
Generate test suites with edge cases covered
♻️
Refactor Code
Modernize patterns, clean up tech debt
📝
Write Docs
READMEs, docstrings, inline comments
🚀
Ship PRs
Commit, push, and create pull requests

Where does it run?

Claude Code works on every major development surface — and your settings, memory, and MCP servers travel with you:

🖥️ Terminal CLI 📝 VS Code ☕ JetBrains 🖱️ Desktop App 🌐 Web (claude.ai)

The Agentic Loop — How Claude Thinks

Every time you give Claude a task, it enters an autonomous tool-use loop. It reads context, decides what to do next, takes an action (reading a file, editing code, running a command), observes the result, and repeats until the task is done. This is what makes it fundamentally different from a simple chatbot.

The Agentic Loop
🧪
Try it yourself Open any project and run: claude "give me an overview of this codebase" — watch Claude systematically read files, analyze the structure, and synthesize an answer.

The Context Window — Your Most Important Resource

Claude has a ~200K token context window — think of it as short-term memory that holds your entire conversation: every message, file it read, and command output. Performance degrades as context fills up, so keeping sessions focused is critical.

What fills contextImpactSolution
Long sessionsIrrelevant history piles upUse /clear between tasks
Large file readsEach file consumes tokensReference specific sections
Verbose command outputBuild logs bloat contextPipe to files, summarize
Unfocused conversationClaude loses track of intentUse /compact to summarize

Chapter 3

Memory & CLAUDE.md

Sessions come and go, but your project knowledge should stick around. Claude Code has two memory systems that work together to carry knowledge across every session — one that you write, and one that Claude writes for itself.

📝 CLAUDE.md — You Write

  • Project ./CLAUDE.md (shared via Git)
  • User ~/.claude/CLAUDE.md (local)
  • Org policy (managed by IT)
  • Scoped rules in .claude/rules/

🤖 Auto Memory — Claude Writes

  • Build commands discovered
  • Debugging insights learned
  • Architecture patterns observed
  • First 200 lines loaded per session

Writing an effective CLAUDE.md

Think of CLAUDE.md as a brief onboarding doc for a new team member. Keep it under 200 lines. Include things Claude can't guess from reading your code; skip what it already knows.

CLAUDE.md
# Code style - Use ES modules (import/export), not CommonJS (require) - Destructure imports when possible # Workflow - Be sure to typecheck when done making code changes - Prefer running single tests, not the whole suite # Architecture - API handlers live in src/api/handlers/ - Database models use Drizzle ORM - Tests mirror src/ structure under tests/ # Build commands - npm run dev → start dev server - npm test → run test suite - npm run lint → check linting
💡
Pro tip You can import external files into CLAUDE.md using @path syntax: See @docs/git-workflow.md for branch conventions. Maximum 5 hops of recursive imports.

Scoped rules for larger projects

For bigger codebases, split your instructions into focused topic files under .claude/rules/. Use YAML frontmatter to scope rules to specific file paths:

.claude/ ├── CLAUDE.md ← main instructions └── rules/ ├── code-style.md ← style guidelines ├── testing.md ← testing conventions └── security.md ← security requirements
.claude/rules/api-rules.md
--- paths: - "src/api/**/*.ts" --- # API Development Rules - All endpoints must include input validation - Use standard error response format - Include OpenAPI documentation comments

Rules without paths frontmatter load unconditionally. Path-scoped rules only activate when Claude reads files matching those patterns — keeping context lean.

🧪
Try it yourself Create a CLAUDE.md in any project with 5–10 lines of instructions, then start a session and ask Claude "What do you know about this project?" — it should reflect your instructions back.

Chapter 4

CLI Commands & Flags

Claude Code is a CLI-first tool. Mastering the command line gives you speed and control that GUI wrappers can't match. Here are the commands you'll use every single day.

Core commands

terminal
# Start an interactive session claude # Ask a question right away claude "explain this project" # Non-interactive (great for scripts) claude -p "list all API endpoints" # Pipe content in cat error.log | claude -p "explain this error" # Continue where you left off claude -c # Resume a named session claude -r "auth-refactor"

Essential flags

FlagWhat it doesExample
--modelChoose model (sonnet/opus)claude --model opus
-pPrint mode (non-interactive)claude -p "query"
--output-formattext / json / stream-jsonclaude -p --output-format json "query"
--permission-modeControl what Claude can doclaude --permission-mode plan
--allowedToolsSkip prompts for safe tools--allowedTools "Bash(git *)" "Read"
-wIsolated git worktreeclaude -w feature-auth
-nName the sessionclaude -n "my-sprint"

Chapter 5

Everyday Workflows

Now that you know the tools, let's see how real development looks with Claude Code. Most work follows a natural flow:

🔍 Explore → 🐛 Debug → 🧪 Test → ♻️ Refactor → 📝 Document → 🚀 Ship

1. Explore a codebase

The best way to onboard to any project — just ask.

prompts
# Start broad give me an overview of this codebase # Then drill down how is authentication handled? # Reference specific files explain the logic in @src/auth/login.ts # Trace data flow trace the login process from front-end to database
💡
Pro tip Use Plan Mode (Shift+Tab) when exploring — it tells Claude to analyze without modifying anything. Great for read-only investigation.

2. Fix bugs

Give Claude the error message and context. The more specific, the better:

prompt
fix the login bug. Users report login fails after session timeout. Check auth flow in src/auth/, especially token refresh. Write a failing test first, then fix it.

3. Write and run tests

Claude matches your existing test style automatically:

prompts
# Find untested code find functions in NotificationsService without test coverage # Generate tests add tests for the notification service edge cases # Run and verify run the new tests and fix any failures

4. Refactor code

prompts
# Find what needs fixing find deprecated API usage in our codebase # Modernize refactor utils.js to use ES2024 features while maintaining the same behavior # Verify nothing broke run tests for the refactored code

5. Create a pull request

prompts
# Summarize your changes summarize the changes I've made to the authentication module # Create the PR create a pr # Add context enhance the PR description with more context about security improvements

The session auto-links to the PR. Later, you can return with claude --from-pr 123.

The four-phase best practice

Pro developers use Claude in a structured cycle. Here's the pattern that maximizes quality and minimizes wasted context:

The Four-Phase Workflow
1

Explore (Plan Mode)

Read code, ask questions, understand the landscape before touching anything.

2

Plan (Plan Mode)

Create a detailed implementation plan. Use Ctrl+G to open it in your editor and refine.

3

Implement (Normal Mode)

Write the code, add tests, and verify everything passes.

4

Commit & Ship

Create a descriptive commit and open a PR — Claude handles the messaging.

🧪
Try the full workflow Pick a small feature in any project. Use Shift+Tab into Plan Mode, explore the code, create a plan, switch back to Normal Mode, implement it, write tests, and create a commit. The whole cycle in one session.
