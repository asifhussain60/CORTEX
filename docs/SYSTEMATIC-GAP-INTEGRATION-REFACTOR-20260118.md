### Old Workflow (Ad-Hoc Gap Management)

```
1. Run review (Phase 0-2 complete)
2. Read consolidated findings report
3. Manually identify which findings are "gaps"
4. Manually decide which need new ACs
5. Manually create AC-FIX-XXX entries
6. Manually update phase_tracker status
7. Manually update gaps_addressed section
8. Manually verify dependencies
9. Git commit

Timeline: Varies (often 2-4 hours of manual work)
Error rate: High (missed gaps, inconsistent formatting)
Traceability: Low (findings → ACs connection unclear)
```

```
A. cortex-review.prompt.md (Automatic)
   1. Phase 0-2: Run review (standard)
   2. Phase 3A: /review extract-gaps
      → Produces REVIEW-GAPS-EXTRACTED-YYYYMMDD.yaml
   3. Phase 3B: /review refactor-holistic

   1. Detects REVIEW-GAPS-EXTRACTED-YYYYMMDD.yaml
   2. Reads gaps_addressed array
   3. Steps A-F: Extract → Classify → Update → Add specs → Validate → Commit
   4. cortex-master.yaml updated with:
      - Phase status IN_PROGRESS, locked: false
      - gaps_addressed section with full entries
      - New AC-FIX specifications
      - Investigation metadata
   5. Git commit with traceable message

Timeline: 20 min (Phase 3) + Automatic (cortex-builder)
Error rate: Low (systematic validation, cycle detection)
Traceability: High (review findings → gaps → ACs → commits)
```

## KEY FEATURES

### 1. Systematic Gap Extraction

**Gap ID Format:** `GAP-{DOMAIN}-{NNN}`
- Example: `GAP-HASH-CHAIN-001`, `GAP-TEST-FIXTURE-001`
- Automatic counter per domain
- Uniquely identifies each gap

**Gap Entry Structure:**
```yaml
gap_id: "GAP-HASH-CHAIN-001"
severity: "CRITICAL"          # CRITICAL, HIGH, MEDIUM, LOW
evidence_grade: "A"            # A=95%, B=85%, C=70%
description: "[specific issue]"
root_cause: "[IMPLEMENTATION_FLAW|INTEGRATION_ISSUE|DESIGN_WEAKNESS]"
affected_ac_ids: ["AC-FIX-001-01"]
remedy_ac_id: "AC-FIX-001-02"
remedy_effort: "1h"
remedy_priority: "P0 - CRITICAL"
blocking_for: ["AC-FIX-001-03"]
depends_on: ["AC-FIX-001-01"]
related_skull_rules: ["CORE-025", "CORE-027"]
issue_id: "ISSUE-005B"
```

### 2. Holistic Refactoring Analysis

**Six-Layer Analysis Before AC Creation:**

1. **Root Cause Clustering**
   - Question: Do multiple gaps stem from single root cause?
   - Example: 78 hash chain breaks → 2 ACs (fix + validate)
   - Benefit: Prevents 78 separate ACs from 1 defect

2. **Pattern Recognition**
   - Question: Does same issue appear in multiple places?
   - Example: Bare except clauses in 5 files → 1 AC-REFACTOR
   - Benefit: Consolidates related fixes

3. **Dependency Optimization**
   - Question: Can independent ACs be parallelized?
   - Example: AC-FIX-001-02 and AC-REFACTOR-001 independent → parallel
   - Benefit: Faster delivery through parallelization

4. **Evidence Grading Summary**
   - Question: What's the overall evidence quality?
   - Distribution: A (95%), B (85%), C (70%)
   - Benefit: Validates CRITICAL findings have A/B evidence

5. **AC Deduplication Check**
   - Question: Are we creating redundant ACs?
   - Example: Consolidate 5 error-handling gaps into 1 AC
   - Benefit: Minimizes ACs, focuses effort

6. **Governance Coverage**
   - Question: Do remediation ACs cover relevant governance rules?
   - Example: Hash chain ACs cover CORE-025, CORE-027
   - Benefit: Ensures governance compliance in remediation

### 3. Evidence-Based Prioritization

**Automatic Priority Mapping:**
```
Grade A (95% confidence) → P0 - CRITICAL    → Implement immediately
Grade B (85% confidence) → P1 - HIGH        → Next sprint
Grade C (70% confidence) → P2 - MEDIUM      → Backlog (NOT critical)
```

**Rule:** CRITICAL findings MUST have Grade A or B evidence. No speculation (Grade C) allowed for blocking issues.

### 4. Automatic Master Plan Integration

**Trigger:** When `REVIEW-GAPS-EXTRACTED-YYYYMMDD.yaml` appears in `_workspaces/roadmap/issues/`

**Actions (cortex-builder.prompt.md):**
1. Read gaps_addressed entries
2. Update phase_tracker status
3. Add gaps_addressed section to phase
4. Create new AC specifications with full details
5. Update ac_breakdown metrics
6. Add investigation references
7. Git commit (traceable)

**Result:** cortex-master.yaml updated, phase ready for implementation

### 5. Traceability

**Every gap traced from findings to implementation:**
```
REVIEW-FINDINGS-CONSOLIDATED-YYYYMMDD.yaml (Finding F001)
    ↓ (Gap Extraction)
REVIEW-GAPS-EXTRACTED-YYYYMMDD.yaml (Gap GAP-HASH-CHAIN-001)
    ↓ (Holistic Analysis & YAML Generation)
cortex_master_yaml_updates section (Ready for integration)
    ↓ (cortex-builder Integration)
cortex-master.yaml (Phase-REMEDIATION-03 updated)
    ↓ (Implementation)
AC-FIX-001-02 (Code implementation starts)
    ↓ (Git Commit)
"integrate-review-gaps: ISSUE-005B AC-FIX-001-02 added"

All links preserved via:
- issue_id: ISSUE-005B
- investigation_report: [file path]
- decision_gate: [file path]
- Git commit message
```

## VALIDATION & SAFETY CHECKS

### Pre-Integration Validation (cortex-builder.prompt.md)

**1. Syntax Validation**
```bash
yamllint cortex-master.yaml
```

**2. Gap-to-AC Mapping**
- For each remedy_ac_id in gap entry
- Verify AC specification exists in phase
- Report missing AC definitions

**3. Cycle Detection**
- If AC-X depends_on AC-Y
- Then AC-Y cannot be in AC-X.blocking_for
- Prevents infinite dependency chains

**4. Governance Rule Verification**
- For each related_skull_rule
- Verify rule exists in cortex-brain/tier0/governance/core-rules.yaml
- Report unknown rule IDs

**5. Evidence Grading Check**
- If severity == CRITICAL
- Then evidence_grade must be A or B
- Report violations of this rule

```yaml
  - gap_id: "GAP-HASH-CHAIN-001"
```

### Step 3B: Holistic Analysis (Phase 3B)
```bash
/review refactor-holistic --gaps REVIEW-GAPS-EXTRACTED-YYYYMMDD.yaml
```

- Root cause clustering: 2 gaps (GAP-HASH-CHAIN-001, GAP-HASH-VALIDATE-001) from 1 defect
- Pattern: Sequential ACs (fix then validate) - cannot parallelize
- Dependencies: AC-FIX-001-03 blocks clean_audit_log_regeneration
- Evidence: Both A-grade (95% confidence)
- Deduplication: 2 ACs necessary (not 78 for each violation)
