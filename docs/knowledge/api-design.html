🌐 API Design Excellence

REST, GraphQL, and API Versioning Strategies

📡 Backend APIs 🏷️ REST & GraphQL 📅 Updated: Dec 2025

📋 Overview

API Design Excellence encompasses the principles, patterns, and practices for designing robust, scalable, and maintainable APIs. Master REST architectural constraints, GraphQL schema design, and versioning strategies for backward-compatible API evolution.

Key Concepts:
  • REST Architecture: Stateless, client-server, cacheable, uniform interface
  • GraphQL: Strongly-typed schemas with client-specified queries
  • API Versioning: Backward compatibility and safe evolution
  • Security: Authentication, authorization, rate limiting

🔷 REST API Design

Core Principles

📦

Resource-Based

Key Concepts

  • Nouns not Verbs: /users not /getUsers
  • Plural Forms: /users /orders /products
  • Hierarchical: /users/123/orders
  • Lowercase: Use hyphens for multi-word
⚡

HTTP Methods

Standard Operations

  • GET: Retrieve (safe, idempotent)
  • POST: Create new resource
  • PUT: Replace entire resource
  • PATCH: Partial update
  • DELETE: Remove resource
✅

Status Codes

HTTP Responses

  • 200 OK: Successful GET/PUT/PATCH
  • 201 Created: Resource created (POST)
  • 204 No Content: Successful DELETE
  • 400 Bad Request: Invalid input
  • 401 Unauthorized: Authentication required
  • 404 Not Found: Resource doesn't exist

Pagination Strategies

📄

Offset-Based

Page and Limit Parameters

Implementation

  • Query: ?page=2&limit=20
  • Simple to implement
  • Good for small datasets
  • Issues with data changes

Response Format

  • Total pages/items count
  • Current page number
  • Has next/previous flags
🔗

Cursor-Based

Recommended for Large Datasets

Implementation

  • Query: ?cursor=abc123&limit=20
  • Consistent results
  • Handles real-time data
  • Better performance

Response Format

  • Next/previous cursor tokens
  • Has more indicator
  • No total count (expensive)

Best Practices

REST API Excellence:
  • Versioning: Include API version in URL or headers
  • Filtering: Use query parameters (?status=active&role=admin)
  • Sorting: Support multi-field sorting (?sort=created_at,-price)
  • Field Selection: Let clients specify fields (?fields=id,name,email)
  • Error Format: Consistent JSON error structure with codes
  • HATEOAS: Include links to related resources

🔷 GraphQL Design

Schema Design Principles

📐

Type System

Core Types

  • Object Types: Main schema building blocks
  • Scalar Types: Int, Float, String, Boolean, ID
  • Enums: Fixed set of values
  • Interfaces: Abstract types with shared fields
  • Unions: Multiple possible types
🔤

Naming Conventions

Best Practices

  • Types: PascalCase (User, OrderItem)
  • Fields: camelCase (firstName, createdAt)
  • Enums: SCREAMING_SNAKE_CASE
  • Booleans: Prefix with is/has
  • Input Types: End with Input suffix
⚠️

Nullability

Field Requirements

  • ! (Non-null): Use sparingly
  • Nullable Default: More flexible evolution
  • Lists: Consider [Type!]! patterns
  • Required Fields: Only guaranteed data
  • Evolution: Can't make non-null later

Query Optimization

🔄

DataLoader Pattern

Solve N+1 Query Problem

Batching

  • Batch multiple requests
  • Single database query
  • Per-request caching
  • Automatic deduplication
🎯

Query Complexity

Prevent Expensive Queries

Analysis

  • Calculate query cost
  • Depth limiting (max 7 levels)
  • Complexity scoring
  • Rate limiting by cost
📊

Pagination

Relay-Style Connections

Pattern

  • Edges and nodes structure
  • Cursor-based pagination
  • PageInfo with indicators
  • Total count optional

Mutation Best Practices

GraphQL Mutations:
  • Naming: Verb + noun (createUser, updateProduct, deleteOrder)
  • Input Types: Single input argument with Input suffix
  • Payload Types: Include data, errors, clientMutationId
  • Error Handling: User errors in payload, system errors thrown
  • Side Effects: Document all side effects clearly
  • Idempotency: Use clientMutationId for deduplication

🔄 API Versioning

Versioning Strategies

🔗

URI Versioning

Most Common Approach

Implementation

  • Pattern: /v1/users
  • Highly visible
  • Easy to test
  • Cache-friendly

Best For

  • Public APIs
  • External clients
  • Clear communication
📝

Header Versioning

Clean URLs

Implementation

  • Header: X-API-Version: 2
  • Clean URLs
  • Per-resource versioning
  • More RESTful

Best For

  • Internal APIs
  • Microservices
  • Gradual migration
🎯

Content Negotiation

Most RESTful

Implementation

  • Accept: application/vnd.api.v2+json
  • Standards-compliant
  • Hypermedia support
  • Complex setup

Best For

  • Mature REST APIs
  • HATEOAS compliance
  • Content types matter

Breaking Changes

Change Type Breaking? Safe Alternative
Remove endpoint/field BREAKING Deprecate first, then remove
Rename field/endpoint BREAKING Add new, deprecate old, support both
Change data type BREAKING New field with different name
Add required field BREAKING Make optional, then require later
Add optional field SAFE Deploy directly
Add new endpoint SAFE Deploy directly

Deprecation Best Practices:
  • Sunset Header: RFC 8594 standard deprecation header
  • Migration Guide: Clear documentation for transition
  • Support Period: Minimum 6-12 months for major changes
  • Monitoring: Track usage of deprecated endpoints
  • Communication: Email campaigns, changelog, release notes
  • Final Warning: 3-month notice before actual removal

🔒 Security & Performance

Authentication & Authorization

🔑

JWT Tokens

Stateless Authentication

Implementation

  • Bearer token in Authorization header
  • Short expiration (15 minutes)
  • Refresh token rotation
  • Claims for permissions
🛡️

Rate Limiting

Prevent Abuse

Strategies

  • Per-user or per-IP limits
  • Sliding window algorithm
  • 429 Too Many Requests response
  • Retry-After header
✅

Input Validation

Data Integrity

Best Practices

  • Schema validation (JSON Schema)
  • Type checking
  • Length/range validation
  • Sanitize user input

Performance Optimization

⚡

HTTP Caching

Cache Headers

  • ETag: Response version identifier
  • Cache-Control: Caching directives
  • If-None-Match: Conditional request
  • 304 Not Modified: Use cached version
🗜️

Compression

Response Optimization

  • GZIP: Standard compression
  • Brotli: Better compression ratio
  • Accept-Encoding: Client support check
  • Content-Encoding: Applied compression
