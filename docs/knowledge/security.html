Critical Security Rules

🛡️

A01:2021 - Broken Access Control

CRITICAL

Description: Access control enforces that users cannot act outside their intended permissions. Failures lead to unauthorized information disclosure, modification, or destruction.

✅ Secure Pattern

# Policy-based authorization
@require_permission('document:read')
def get_document(document_id):
    doc = Document.query.get(document_id)
    # Verify ownership
    if doc.owner_id != current_user.id:
        if not current_user.has_role('admin'):
            abort(403)
    return doc

❌ Vulnerable Pattern

# IDOR vulnerability - no ownership check
@app.route('/document/<id>')
def get_document(id):
    # Direct database access without authorization
    return Document.query.get(id)
💉

A03:2021 - Injection

CRITICAL

Description: SQL, NoSQL, OS, and LDAP injection occur when untrusted data is sent to an interpreter as part of a command or query. Always use parameterized queries.

✅ Secure - Parameterized Query

# Safe - uses parameterized query
from sqlalchemy import text

query = text("SELECT * FROM users WHERE id = :user_id")
result = db.execute(query, {"user_id": user_id})

❌ Vulnerable - String Concatenation

# DANGEROUS - SQL injection vulnerability
query = f"SELECT * FROM users WHERE id = {user_id}"
result = db.execute(query)
🔐

Use HTTPS Everywhere

CRITICAL

Description: All API endpoints and web applications must use TLS 1.2+ to protect data in transit. Implement HSTS headers to prevent downgrade attacks.

✅ Secure Configuration

from flask import Flask
from flask_talisman import Talisman

app = Flask(__name__)

# Force HTTPS with HSTS
Talisman(
    app, 
    force_https=True, 
    strict_transport_security=True,
    strict_transport_security_max_age=31536000
)

❌ Insecure - No TLS

# DANGEROUS - HTTP without encryption
app.run(host='0.0.0.0', port=80)
# Data transmitted in plaintext!
✅

Whitelist Input Validation

HIGH

Description: Always validate input against a whitelist of allowed characters, length, format, and type. Never trust user input.

✅ Whitelist Validation

from pydantic import BaseModel, constr, validator

class UserRegistration(BaseModel):
    username: constr(
        min_length=3, 
        max_length=20, 
        regex=r'^[a-zA-Z0-9_]+$'
    )
    email: constr(regex=r'^[\w\.-]+@[\w\.-]+\.\w+$')
    age: int
    
    @validator('age')
    def validate_age(cls, v):
        if not 13 <= v <= 120:
            raise ValueError('Age must be 13-120')
        return v

❌ No Validation

# DANGEROUS - accepts any input
def register(username, email, age):
    User.create(
        username=username,  # XSS risk
        email=email,        # Invalid emails
        age=age             # SQL injection risk
    )

Source: OWASP Secure Coding Practices Quick Reference Guide

Defensive programming techniques covering input validation, output encoding, authentication, session management, access control, cryptography, and error handling.

Key Practice Areas:

  • Input Validation: Whitelist validation, length limits, type checking
  • Output Encoding: HTML, URL, JavaScript, SQL encoding
  • Authentication: Password hashing (bcrypt/Argon2), MFA
  • Session Management: Secure cookies, session timeout
  • Access Control: Deny by default, least privilege

  • Error Handling: Generic messages, secure logging

🛡️ Security Scanning Integration

CORTEX uses OWASP Top 10 patterns to detect vulnerabilities during code review:

  • SQL Injection Detection: Identifies string concatenation in SQL queries
  • XSS Prevention: Flags unencoded user input in HTML output
  • CSRF Protection: Validates anti-forgery tokens in forms
  • IDOR Detection: Identifies direct object references without authorization
  • Secrets Exposure: Scans for hardcoded credentials and API keys
