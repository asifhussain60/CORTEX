💾 Database Design

SQL, NoSQL, Data Modeling, and Optimization

🗄️ Data Storage ⚡ Performance 📅 Updated: Dec 2025

📋 Overview

Database design encompasses data modeling, schema design, query optimization, and choosing the right database technology for your application. Understanding relational and non-relational paradigms enables building scalable, performant data storage solutions.

Key Concepts:
Normalization: Organize data to reduce redundancy
Indexing: Accelerate query performance
Transactions: ACID guarantees for data integrity
Sharding: Horizontal scaling for large datasets

🗄️ Relational Databases (SQL)

Core Principles

📐

Normalization

Forms

1NF: Atomic values, no repeating groups
2NF: No partial dependencies
3NF: No transitive dependencies
BCNF: Every determinant is a key

Benefits

Eliminates data redundancy
Prevents update anomalies
Maintains data integrity
🔗

Relationships

Types

One-to-One: User ↔ Profile
One-to-Many: Customer → Orders
Many-to-Many: Students ↔ Courses

Implementation

Foreign keys enforce integrity
Junction tables for M:N
Cascade operations
✅

ACID Properties

Guarantees

Atomicity: All-or-nothing transactions
Consistency: Valid state transitions
Isolation: Concurrent transaction safety
Durability: Committed data persists

Indexing Strategies

⚡

B-Tree Index

Default for Most RDBMS

Best For

Equality searches (WHERE id = 5)
Range queries (WHERE price BETWEEN 10 AND 50)
ORDER BY operations
Primary keys, unique constraints
🔍

Full-Text Index

Text Search Optimization

Best For

Natural language search
Keyword matching
Relevance ranking
PostgreSQL: GIN/GiST
🗺️

Spatial Index

Geospatial Queries

Best For

Location-based queries
Distance calculations
Bounding box searches
PostGIS for PostgreSQL
Index Best Practices:
Selective Columns: Index columns with high cardinality
Composite Indexes: Order matters (most selective first)
Covering Indexes: Include all query columns
Avoid Over-Indexing: Each index slows writes
Monitor Usage: Remove unused indexes

Performance Techniques

🔍

EXPLAIN Plans

Analysis

📈 Scaling Strategies

Horizontal vs Vertical

Aspect Vertical Scaling (Scale Up) Horizontal Scaling (Scale Out)
Approach Add more CPU/RAM/Disk to single server Add more servers to cluster
Complexity Simple Complex
Cost Expensive at high end Cost-effective with commodity hardware
Limits Hardware ceiling Nearly unlimited
Availability Single point of failure High availability built-in
Best For Traditional SQL, small-medium apps NoSQL, large-scale distributed apps

Sharding Patterns

🔢

Range-Based

Strategy

Partition by value ranges
Example: A-M, N-Z
Time-based: 2024, 2025

Pros/Cons

  • ✅ Simple range queries
  • ❌ Risk of hot spots
🔑

Hash-Based

Strategy

Hash function on shard key
Consistent hashing
Even distribution

Pros/Cons

  • ✅ Balanced load
  • ❌ Range queries harder
🗺️

Geographic

Strategy

Partition by location
US-East, EU, Asia
Data locality

Pros/Cons

  • ✅ Low latency
  • ❌ Cross-shard joins complex

Replication Strategies

👑

Leader-Follower

Master-Slave Replication

Pattern

Writes to leader only
Reads from followers
Async or sync replication
Failover to follower
🤝

Multi-Leader

Multi-Master

Pattern

Multiple write nodes
Conflict resolution needed
Geographic distribution
Better write availability
🌐

Leaderless

Peer-to-Peer

Pattern

Write to multiple nodes
Quorum-based consistency
Cassandra, DynamoDB
High availability
