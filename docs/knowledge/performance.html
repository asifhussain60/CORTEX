Optimization Example

# ❌ BAD: O(n²) - Quadratic lookup
def find_duplicates_slow(items):
    duplicates = []
    for i, item in enumerate(items):
        for j in range(i + 1, len(items)):
            if items[j] == item:
                duplicates.append(item)
    return duplicates

# ✅ GOOD: O(n) - Linear with hash set
def find_duplicates_fast(items):
    seen = set()
    duplicates = []
    for item in items:
        if item in seen:  # O(1) lookup
            duplicates.append(item)
        seen.add(item)
    return duplicates

Profile Before Optimizing

CRITICAL

Description: Always profile to identify actual bottlenecks. Don't optimize based on assumptions.

Rationale: "Premature optimization is the root of all evil" - Donald Knuth. Measure first.

Python Profiling Example

import cProfile
import pstats
from io import StringIO

def profile_function(func, *args, **kwargs):
    """Profile a function and print stats."""
    profiler = cProfile.Profile()
    profiler.enable()
    
    result = func(*args, **kwargs)
    
    profiler.disable()
    
    # Print top 20 functions by cumulative time
    stream = StringIO()
    stats = pstats.Stats(profiler, stream=stream)
    stats.strip_dirs().sort_stats('cumulative')
    stats.print_stats(20)
    print(stream.getvalue())
    
    return result

# Usage
result = profile_function(my_slow_function, arg1, arg2)

Key Profiling Metrics

  • ncalls: Number of function calls
  • tottime: Time in function (excluding subcalls)
  • cumtime: Total time including subcalls
  • Focus on: High cumtime functions first

Database Index Optimization

HIGH

Description: Proper indexing is the #1 database performance optimization. Create indexes on frequently queried columns.

Index Strategy

  • Index WHERE clause columns: Columns used in filtering
  • Index JOIN columns: Foreign keys and join conditions
  • Index ORDER BY columns: Columns used in sorting
  • Composite indexes: Match query column order

SQL Example

-- Analyze query execution plan
EXPLAIN ANALYZE 
SELECT * FROM orders 
WHERE customer_id = 123 
  AND status = 'pending'
ORDER BY created_at DESC;

-- Create composite index matching query
CREATE INDEX idx_orders_customer_status_created 
ON orders (customer_id, status, created_at DESC);

-- Partial index for common filter
CREATE INDEX idx_orders_pending 
ON orders (customer_id, created_at) 
WHERE status = 'pending';

Cache Patterns

Write-BehindAsync write to DB after cacheHigh write throughput

Cache Invalidation Strategies

  • TTL (Time-To-Live): Automatic expiration after fixed duration
  • Event-Based: Invalidate on data change events
  • Version Tags: Include version in cache key, increment on change
  • Cache Stampede Prevention: Use locks or probabilistic early expiration

Redis Best Practices

# Redis caching with proper patterns
import redis
import json
from functools import wraps

redis_client = redis.Redis(host='localhost', port=6379, db=0)

def cache_with_stampede_prevention(ttl_seconds=3600, beta=1):
    """Cache decorator with probabilistic early expiration."""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            cache_key = f"{func.__name__}:{hash(args + tuple(kwargs.items()))}"
            
            # Try to get from cache
            cached = redis_client.get(cache_key)
            if cached:
                data = json.loads(cached)
                # Probabilistic early expiration
                ttl = redis_client.ttl(cache_key)
                if ttl > 0 and random.random() < beta * math.log(random.random()) * -1 / ttl:
                    # Recompute in background (simulate)
                    pass
                else:
                    return data['value']
            
            # Cache miss - compute value
            result = func(*args, **kwargs)
            
            # Store with TTL
            redis_client.setex(
                cache_key,
                ttl_seconds,
                json.dumps({'value': result})
            )
            
            return result
        return wrapper
    return decorator

Database Query Optimization

# ❌ N+1 Query Problem
def get_orders_slow():
    orders = Order.query.all()  # 1 query
    for order in orders:
        print(order.customer.name)  # N queries!

# ✅ Eager Loading Solution
def get_orders_fast():
    orders = Order.query.options(
        joinedload(Order.customer)
    ).all()  # 1 query with JOIN
    for order in orders:
        print(order.customer.name)  # No additional queries

# ✅ Batch Loading Alternative
def get_orders_batch():
    orders = Order.query.all()  # 1 query
    customer_ids = [o.customer_id for o in orders]
    customers = {c.id: c for c in 
        Customer.query.filter(Customer.id.in_(customer_ids)).all()
    }  # 2nd query - batch
    for order in orders:
        print(customers[order.customer_id].name)

k6 Load Test Example

// k6 load test script
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  stages: [
    { duration: '2m', target: 100 },  // Ramp up
    { duration: '5m', target: 100 },  // Stay at 100 users
    { duration: '2m', target: 200 },  // Ramp to 200
    { duration: '5m', target: 200 },  // Stay at 200
    { duration: '2m', target: 0 },    // Ramp down
  ],
  thresholds: {
    http_req_duration: ['p(95)<500'],  // 95% under 500ms
    http_req_failed: ['rate<0.01'],    // <1% failure rate
  },
};

export default function () {
  const res = http.get('https://api.example.com/users');
  
  check(res, {
    'status is 200': (r) => r.status === 200,
    'response time < 500ms': (r) => r.timings.duration < 500,
  });
  
  sleep(1);
}

Performance SLOs

  • Latency p50: 100ms (median response time)
  • Latency p95: 500ms (95th percentile)
  • Latency p99: 1000ms (99th percentile)
  • Error Rate: <0.1% (availability target)
  • Throughput: Handle 10x normal traffic

Query Optimization Checklist

  • Use EXPLAIN ANALYZE: Understand execution plan
  • Avoid SELECT *: Fetch only needed columns
  • Index WHERE columns: Especially for large tables
  • Batch operations: Use bulk inserts/updates
  • Limit results: Always paginate large datasets
  • Avoid functions in WHERE: Prevents index usage
