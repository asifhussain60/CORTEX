What is Refactoring?

Refactoring is a disciplined technique for restructuring existing code, altering its internal structure without changing its external behavior. The process involves a series of small behavior-preserving transformations, each of which is tiny and unlikely to break anything. The system is kept fully working after each small refactoring, reducing the risk of serious errors.

Martin Fowler's seminal work "Refactoring: Improving the Design of Existing Code" provides a comprehensive catalog of refactoring techniques. Each technique describes a common code smell and the precise steps to transform bad code into good code while maintaining functionality.

Code Smells

Code smells are indicators that something may be wrong with your code. They're not bugs—the code works—but they suggest deeper problems that make code harder to maintain and extend.

Key Refactoring Principles

Test First

Always have solid tests before refactoring to ensure behavior doesn't change

Small Steps

Make tiny changes, test after each one, never break the build

Preserve Behavior

Refactoring changes structure, not functionality

Commit Often

Each successful refactoring step should be committed

When to Refactor

✅ Refactor When

Adding new features (prep the ground first)
Fixing bugs (code unclear → make it clear)
During code review (improve design)
Code smells detected (fix before they worsen)
Rule of Three (third time you duplicate, refactor)

❌ Don't Refactor When

Code doesn't work yet (rewrite instead)
Near a deadline (technical debt trade-off)
No tests in place (write tests first)
Rewrite would be easier (sometimes it is)

Composing Methods

Extract Method

Problem: Code fragment that can be grouped together

Solution: Move fragment to separate method with descriptive name

Mechanics

  1. Create new method with intention-revealing name
  2. Copy extracted code to new method
  3. Replace old code with call to new method
  4. Find all variables used and pass as parameters

Benefits

Reduces method length and complexity
Eliminates code duplication
Improves readability through descriptive method names
Makes code more testable

Extract Variable

Problem: Complex expression is hard to understand

Solution: Put expression result in variable with descriptive name

When to Use

Expression is complex and hard to understand
Expression is used multiple times
Need to explain what expression calculates

Replace Temp with Query

Problem: Temporary variable holds result of expression

Solution: Extract expression to method, replace temp with method call

Why

Temps are temporary and local in scope, limiting their usefulness. By extracting to a method, you make the logic available to other methods in the class and enable further refactorings.

Moving Features Between Objects

Move Method

Problem: Method uses more features of another class than its own

Solution: Create new method in the class it uses most, move code there

Mechanics

  1. Examine features used by method from other classes
  2. Determine which class method should move to
  3. Create new method in target class
  4. Copy code from source method to target
  5. Adjust references and parameters
  6. Replace old method with simple delegation or delete it

Extract Class

Problem: Class doing work of two classes

Solution: Create new class, move relevant fields and methods

Signs You Need This

Class has multiple responsibilities
Subset of data and methods go together
Subset of data that change together
You can't easily describe what class does in one sentence

Hide Delegate

Problem: Client calls delegate class of object

Solution: Create method on server object that hides delegate

Encapsulation means objects need to know less about other parts of the system. When things change, fewer things need to be told about the change, making maintenance easier.

Organizing Data

Replace Magic Number with Symbolic Constant

Problem: Numeric literal with special meaning

Solution: Create constant, name it after meaning, replace number with it

Encapsulate Field

Problem: Public field

Solution: Make it private, provide accessors

Replace Type Code with Class

Problem: Class has numeric type code that doesn't affect behavior

Solution: Replace number with new class

Type codes (like 0 for male, 1 for female) are less type-safe than using classes. With classes, compiler can catch errors at compile time.

Simplifying Conditional Expressions

Decompose Conditional

Problem: Complex conditional (if-then-else) statement

Solution: Extract condition, then, and else into separate methods

Consolidate Conditional Expression

Problem: Multiple conditionals with same result

Solution: Combine into single conditional, extract to method

Replace Nested Conditional with Guard Clauses

Problem: Method has conditional behavior with nested structure

Solution: Use guard clauses for special cases

If condition is unusual, check it and return if true. This clarifies the normal path through the code.

Replace Conditional with Polymorphism

Problem: Conditional based on object type

Solution: Move each conditional branch to overriding method in subclass

This is one of the most powerful refactorings. Polymorphism gives you cleaner code structure and makes adding new types easier.

Dealing with Generalization

Pull Up Method

Problem: Methods with identical results in subclasses

Solution: Move to superclass

Pull Up Field

Problem: Two subclasses have same field

Solution: Move field to superclass

Extract Interface

Problem: Multiple clients use same subset of class interface

Solution: Extract subset to interface

Replace Inheritance with Delegation

Problem: Subclass uses only part of superclass interface

Solution: Create field for superclass, delegate methods, remove inheritance

Inheritance is powerful but can be overused. Delegation gives you more control over which features to expose.

Extract Method - Python

❌ Before: Long Method

# ❌ Long method doing multiple things
def print_invoice(invoice):
    print("***********************")
    print("*** Customer Invoice ***")
    print("***********************")
    
    # Print details
    print(f"Name: {invoice.customer_name}")
    print(f"Amount: ${invoice.amount}")
    print(f"Date: {invoice.date}")

✅ After: Extract Method

# ✅ Extracted to focused methods
def print_invoice(invoice):
    print_banner()
    print_details(invoice)

def print_banner():
    print("***********************")
    print("*** Customer Invoice ***")
    print("***********************")

def print_details(invoice):
    print(f"Name: {invoice.customer_name}")
    print(f"Amount: ${invoice.amount}")
    print(f"Date: {invoice.date}")

Replace Temp with Query - Python

❌ Before: Temporary Variable

# ❌ Temp limits scope
def get_price(self):
    base_price = self.quantity * self.item_price
    discount_factor = 0.98 if base_price > 1000 else 0.95
    return base_price * discount_factor

✅ After: Replace with Query

# ✅ Methods can be reused
def get_price(self):
    return self.base_price() * self.discount_factor()

def base_price(self):
    return self.quantity * self.item_price

def discount_factor(self):
    return 0.98 if self.base_price() > 1000 else 0.95

Replace Conditional with Polymorphism - Python

❌ Before: Type-Based Switch

# ❌ Type checking everywhere
class Bird:
    def __init__(self, bird_type):
        self.type = bird_type
    
    def get_speed(self):
        if self.type == "EUROPEAN":
            return self.base_speed()
        elif self.type == "AFRICAN":
            return self.base_speed() - self.load_factor()
        elif self.type == "NORWEGIAN_BLUE":
            return 0 if self.is_nailed else self.base_speed() * 2

✅ After: Polymorphism

# ✅ Polymorphic design
class Bird(ABC):
    @abstractmethod
    def get_speed(self):
        pass

class EuropeanBird(Bird):
    def get_speed(self):
        return self.base_speed()

class AfricanBird(Bird):
    def get_speed(self):
        return self.base_speed() - self.load_factor()

class NorwegianBlueBird(Bird):
    def get_speed(self):
        return 0 if self.is_nailed else self.base_speed() * 2

Extract Class - C#

❌ Before: Class Doing Too Much

// ❌ Person class has too many responsibilities
public class Person
{
    public string Name { get; set; }
    public string OfficeAreaCode { get; set; }
    public string OfficeNumber { get; set; }
    
    public string GetTelephoneNumber()
    {
        return $"({OfficeAreaCode}) {OfficeNumber}";
    }
}

✅ After: Extract Class

// ✅ Separated concerns
public class Person
{
    public string Name { get; set; }
    public TelephoneNumber OfficeTelephone { get; set; }
}

public class TelephoneNumber
{
    public string AreaCode { get; set; }
    public string Number { get; set; }
    
    public string GetTelephoneNumber()
    {
        return $"({AreaCode}) {Number}";
    }
}

Replace Magic Number - TypeScript

❌ Before: Magic Numbers

// ❌ What do these numbers mean?
function calculateTotal(price: number, quantity: number): number {
    if (quantity > 100) {
        return price * quantity * 0.9;
    }
    return price * quantity;
}

✅ After: Named Constants

// ✅ Self-documenting constants
const BULK_ORDER_THRESHOLD = 100;
const BULK_DISCOUNT_RATE = 0.9;
const STANDARD_RATE = 1.0;

function calculateTotal(price: number, quantity: number): number {
    const rate = quantity > BULK_ORDER_THRESHOLD 
        ? BULK_DISCOUNT_RATE 
        : STANDARD_RATE;
    return price * quantity * rate;
}

Automated Refactoring in CORTEX

CORTEX includes intelligent refactoring agents that detect code smells and suggest appropriate refactorings based on Martin Fowler's catalog.

Code Smell Detection

# CORTEX Code Smell Detector
class CodeSmellDetector:
    def detect_smells(self, code: str) -> List[CodeSmell]:
        smells = []
        
        # Detect Long Method
        for method in self.parse_methods(code):
            if method.line_count > 20:
                smells.append(CodeSmell(
                    type="Long Method",
                    severity="MEDIUM",
                    location=method.location,
                    suggestion="Consider Extract Method refactoring"
                ))
        
        # Detect Large Class
        for cls in self.parse_classes(code):
            if cls.method_count > 10 or cls.line_count > 200:
                smells.append(CodeSmell(
                    type="Large Class",
                    severity="HIGH",
                    location=cls.location,
                    suggestion="Consider Extract Class refactoring"
                ))
        
        # Detect Duplicate Code
        duplicates = self.find_duplicates(code)
        for dup in duplicates:
            smells.append(CodeSmell(
                type="Duplicate Code",
                severity="HIGH",
                location=dup.location,
                suggestion="Consider Extract Method or Pull Up Method"
            ))
        
        return smells

Refactoring Workflow in CORTEX

# CORTEX Refactoring Orchestrator
class RefactoringOrchestrator:
    def refactor_codebase(self, file_path: str) -> RefactoringResult:
        # Step 1: Run tests (ensure they pass)
        if not self.run_tests():
            return RefactoringResult(
                success=False,
                message="Tests must pass before refactoring"
            )
        
        # Step 2: Detect code smells
        smells = self.detector.detect_smells(file_path)
        
        # Step 3: Suggest refactorings
        suggestions = self.map_smells_to_refactorings(smells)
        
        # Step 4: Apply refactorings (one at a time)
        for suggestion in suggestions:
            # Apply refactoring
            self.apply_refactoring(suggestion)
            
            # Run tests after each refactoring
            if not self.run_tests():
                # Rollback if tests fail
                self.rollback_last_refactoring()
                continue
            
            # Commit successful refactoring
            self.git_commit(f"refactor: {suggestion.name}")
        
        return RefactoringResult(success=True)
