What is Code Review?

Code review is systematic examination of source code to find and fix mistakes, improve quality, share knowledge, and maintain consistent coding standards across the team. It's one of the most effective quality assurance techniques in software engineering.

A comprehensive code review examines security vulnerabilities, performance bottlenecks, readability issues, and maintainability concerns before code reaches production.

All checks pass, reviewers approve, code merges

Review Best Practices

Be Kind & Constructive

Focus on the code, not the person. Suggest improvements, don't demand them.

Review Small Changes

Limit PRs to 200-400 lines. Larger changes miss defects.

Use level1-check-icon-error

Follow consistent review level1-check-icon-error for thoroughness.

Automate What You Can

Let tools catch formatting, linting, and basic security issues.

Review Tests Too

Test code needs review just like production code.

Time-Box Reviews

60-90 minutes maximum. Effectiveness drops after that.

Security Review

Input Validation

Severity: CRITICAL

level1-check-icon-error

All user inputs validated (type, format, range, length)
Use allowlists, not blocklists
Sanitize inputs to prevent SQL injection
Sanitize inputs to prevent XSS
Validate file uploads (type, size, content)

Detection Patterns

request.args.get() without validation
Raw SQL with string concatenation
eval() or exec() on user input
Unvalidated file upload

Tools

Bandit: Python security linter
Semgrep: Multi-language static analysis
SonarQube: Comprehensive security scanner

Authentication & Authorization

Severity: CRITICAL

level1-check-icon-error

Authentication required for all protected endpoints
Authorization checks on every operation
Role-based access control (RBAC) implemented
Session management secure (timeouts, regeneration)
Password policies enforced (length, complexity)

Detection Patterns

API endpoint without @login_required
Sensitive operation without permission check
Plain text passwords in database
Weak hashing (MD5, SHA1)

Sensitive Data Exposure

Severity: CRITICAL

level1-check-icon-error

PII never logged (emails, SSNs, credit cards)
Secrets not hardcoded (API keys, passwords)
Error messages don't expose internal details
Debug mode disabled in production
Stack traces not exposed to users

Detection Patterns

logger.info containing email, password, SSN, credit_card
Hardcoded API_KEY, SECRET_KEY, PASSWORD
DEBUG = True in production config
Exception details in API responses

Tools

  • TruffleHog: Find secrets in git history
  • Detect-Secrets: Prevent secrets in commits

Cryptography

Severity: HIGH

level1-check-icon-error

Use bcrypt/Argon2 for password hashing (NOT MD5/SHA1)
Use secure random for tokens (secrets.token_urlsafe, NOT random)
Encrypt sensitive data at rest (AES-256)
Use TLS 1.2+ for data in transit
Verify certificates in HTTPS requests

Detection Patterns

hashlib.md5() or hashlib.sha1() for passwords
random.random() for security tokens
requests.get(..., verify=False)

Performance Review

N+1 Query Detection

Severity: HIGH

level1-check-icon-error

Use eager loading for related data (JOIN, includes, prefetch_related)
Avoid queries inside loops
Use batch queries where possible
Profile database queries in dev environment

Detection Patterns

  • For loop with database query inside
  • ORM query without .join() or .prefetch_related()

Tools

  • Django Silk: Profile Django queries
  • SQLAlchemy Echo: Log all queries

Inefficient Algorithms

Severity: MEDIUM

level1-check-icon-error

No nested loops over large datasets (O(n²) → O(n log n))
Use appropriate data structures (dict for lookups, set for membership)
Avoid repeated calculations (memoization)
Profile hot paths with cProfile

Detection Patterns

Nested for loops with list/array iteration
if x in list: for large lists (use set)
Repeated function calls with same args

Tools

  • cProfile: Python profiler
  • memory_profiler: Track memory usage

Resource Leaks

Severity: HIGH

level1-check-icon-error

Always close files, DB connections, network sockets
Use context managers (with statement)
Dispose IDisposable objects in C#
Close async resources with async with

Detection Patterns

open() without with statement
Database connection without try-finally or context manager
New HttpClient() in method (should be static/singleton)

Readability Review

Naming Clarity

Severity: MEDIUM

level1-check-icon-error

Variables: intention-revealing (user_email, NOT e)
Functions: verb phrases (get_user, NOT user)
Classes: noun phrases (PaymentService, NOT Process)
Constants: SCREAMING_SNAKE_CASE (MAX_RETRY_COUNT)
Avoid abbreviations unless domain-standard

Detection Patterns

Single-letter variables (except i, j, k in loops)
Abbreviations: usr, mgr, prc, tmp
Vague names: data, info, manager, handler

Function Length & Complexity

Severity: MEDIUM

level1-check-icon-error

Max 20 lines per function (ideal: 10)
Single responsibility (one reason to change)
One level of abstraction per function
Max 3 parameters (use objects for more)
Cyclomatic complexity ≤ 10

Tools

  • Radon: Python complexity analyzer
  • McCabe: Complexity checker

Code Duplication

Severity: MEDIUM

level1-check-icon-error

Extract common logic into functions
Use inheritance/composition for shared behavior
Max 5 lines of duplicate code

Tools

Flake8-Duplication: Python duplication detector
Jscpd: Copy-paste detector
PMD: Java/C# duplication

Maintainability Review

Error Handling

Severity: HIGH

level1-check-icon-error

No bare except: clauses (catch specific exceptions)
Log errors with context before re-raising
Don't return None on error (raise exception)
Clean up resources in finally blocks

Detection Patterns

except: pass # Swallowing exceptions
except Exception: # Too broad
return None # Ambiguous failure

Documentation

Severity: MEDIUM

level1-check-icon-error

Public APIs have docstrings
Complex logic has explanatory comments
README updated for new features
Architecture decisions documented (ADRs)

SQL Injection Prevention - Python

❌ Security Violation

# ❌ CRITICAL: SQL injection vulnerability
user_id = request.args.get('user_id')
query = f"SELECT * FROM users WHERE id = {user_id}"
cursor.execute(query)  # Attacker can inject: 1 OR 1=1

✅ Secure Code

# ✅ Parameterized query prevents injection
user_id = request.args.get('user_id')
query = "SELECT * FROM users WHERE id = ?"
cursor.execute(query, (user_id,))  # Safe!

Weak Cryptography - Python

❌ Security Violation

# ❌ HIGH: Weak hashing, insecure random
import hashlib
import random

# MD5 is broken for passwords
password_hash = hashlib.md5(password.encode()).hexdigest()

# random is NOT cryptographically secure
token = ''.join(random.choice(string.ascii_letters) for _ in range(32))

✅ Secure Code

# ✅ Strong hashing, secure random
import secrets
from werkzeug.security import generate_password_hash

# bcrypt/Argon2 for passwords
password_hash = generate_password_hash(password, method='pbkdf2:sha256')

# secrets module for tokens
token = secrets.token_urlsafe(32)

N+1 Query Problem - Python

❌ Performance Issue

# ❌ HIGH: N+1 query problem
# 1 query to get users + N queries for orders
users = User.query.all()  # 1 query
for user in users:
    print(user.orders)  # N queries (1 per user!)

✅ Optimized Code

# ✅ Eager loading - single query
from sqlalchemy.orm import joinedload

# 1 query total with JOIN
users = User.query.options(joinedload(User.orders)).all()
for user in users:
    print(user.orders)  # No additional queries!

Inefficient Algorithm - Python

❌ Performance Issue

# ❌ MEDIUM: O(n²) complexity
matches = []
for i in range(len(list1)):
    for j in range(len(list2)):
        if list1[i] == list2[j]:  # Nested loop is slow!
            matches.append(list1[i])

✅ Optimized Code

# ✅ O(n) complexity with set
set2 = set(list2)  # O(n) to build set
matches = [x for x in list1 if x in set2]  # O(n) lookup

Resource Leak - Python & C#

❌ Resource Leak

# ❌ Python: File not closed
f = open('file.txt')
data = f.read()
# f.close() missing! File handle leaks

✅ Proper Resource Management

# ✅ Python: Context manager auto-closes
with open('file.txt') as f:
    data = f.read()
# File automatically closed
// ✅ C#: using statement disposes
using (var conn = new SqlConnection(connectionString))
{
    conn.Open();
    // Connection automatically closed and disposed
}

Poor Naming - Python

❌ Readability Issue

# ❌ MEDIUM: Unclear names
def proc(d):  # What does this do?
    r = []
    for i in d:
        if i[1] > 100:
            r.append(i[0])
    return r

✅ Clear Naming

# ✅ Self-documenting code
def filter_high_value_transactions(transactions):
    high_value_ids = []
    for transaction in transactions:
        if transaction.amount > 100:
            high_value_ids.append(transaction.id)
    return high_value_ids

Poor Error Handling - Python

❌ Maintainability Issue

# ❌ HIGH: Swallowing exceptions
try:
    result = risky_operation()
except:  # What went wrong? No one knows!
    pass

✅ Proper Error Handling

# ✅ Specific exceptions with context
try:
    result = risky_operation()
except ValueError as e:
    logger.error(f"Invalid input: {e}")
    raise
except ConnectionError as e:
    logger.error(f"Connection failed: {e}")
    raise OperationFailedError("Service unavailable") from e

Automated Code Review in CORTEX

CORTEX provides intelligent code review agents that automatically scan pull requests for security, performance, readability, and maintainability issues.

Code Review Orchestrator

# CORTEX Code Review System
class CodeReviewOrchestrator:
    def review_pull_request(self, pr_id: str) -> ReviewResult:
        results = []
        
        # 1. Security Review
        security_issues = self.security_agent.scan(pr_id)
        results.extend(security_issues)
        
        # 2. Performance Review
        performance_issues = self.performance_agent.scan(pr_id)
        results.extend(performance_issues)
        
        # 3. Readability Review
        readability_issues = self.readability_agent.scan(pr_id)
        results.extend(readability_issues)
        
        # 4. Maintainability Review
        maintainability_issues = self.maintainability_agent.scan(pr_id)
        results.extend(maintainability_issues)
        
        # Generate report
        return self.generate_report(results)
    
    def generate_report(self, issues: List[Issue]) -> ReviewResult:
        critical = [i for i in issues if i.severity == "CRITICAL"]
        high = [i for i in issues if i.severity == "HIGH"]
        medium = [i for i in issues if i.severity == "MEDIUM"]
        
        # Block merge if critical/high issues found
        approval = len(critical) == 0 and len(high) == 0
        
        return ReviewResult(
            approval=approval,
            critical_issues=critical,
            high_issues=high,
            medium_issues=medium,
            summary=self.build_summary(issues)
        )

Security Review Agent

# Automated Security Scanning
class SecurityReviewAgent:
    def scan(self, pr_id: str) -> List[SecurityIssue]:
        issues = []
        files = self.get_changed_files(pr_id)
        
        for file in files:
            # SQL injection detection
            if self.has_sql_injection_risk(file):
                issues.append(SecurityIssue(
                    type="SQL Injection",
                    severity="CRITICAL",
                    file=file.path,
                    line=file.line_number,
                    message="Use parameterized queries"
                ))
            
            # Hardcoded secrets
            if self.has_hardcoded_secrets(file):
                issues.append(SecurityIssue(
                    type="Hardcoded Secret",
                    severity="CRITICAL",
                    file=file.path,
                    message="Use environment variables"
                ))
            
            # Weak cryptography
            if self.uses_weak_crypto(file):
                issues.append(SecurityIssue(
                    type="Weak Cryptography",
                    severity="HIGH",
                    file=file.path,
                    message="Use bcrypt/Argon2 for passwords"
                ))
        
        return issues

Performance Review Agent

# Automated Performance Analysis
class PerformanceReviewAgent:
    def scan(self, pr_id: str) -> List[PerformanceIssue]:
        issues = []
        files = self.get_changed_files(pr_id)
        
        for file in files:
            # N+1 query detection
            if self.has_n_plus_one_query(file):
                issues.append(PerformanceIssue(
                    type="N+1 Query",
                    severity="HIGH",
                    file=file.path,
                    message="Use eager loading (joinedload, prefetch_related)"
                ))
            
            # Inefficient algorithms
            if self.has_nested_loops(file):
                issues.append(PerformanceIssue(
                    type="Inefficient Algorithm",
                    severity="MEDIUM",
                    file=file.path,
                    message="O(n²) complexity detected, consider using set/dict"
                ))
            
            # Resource leaks
            if self.has_resource_leak(file):
                issues.append(PerformanceIssue(
                    type="Resource Leak",
                    severity="HIGH",
                    file=file.path,
                    message="Use context manager (with statement)"
                ))
        
        return issues
