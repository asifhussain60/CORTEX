What are Anti-Patterns?

Anti-patterns are common responses to recurring problems that are ineffective and counterproductive. Unlike design patterns (best practices), anti-patterns document common mistakes and their consequences. Recognizing anti-patterns helps developers avoid repeating past mistakes.

The book "AntiPatterns: Refactoring Software, Architectures, and Projects in Crisis" (1998) by William Brown and others cataloged these problematic patterns and provided refactoring paths to healthier solutions.

Anti-Pattern Categories by Severity

CRITICAL

God Object - Class doing everything
Tight Coupling - Components inseparable
No Abstraction - Concrete dependencies everywhere

HIGH

Spaghetti Code - Tangled control flow
Copy-Paste Programming - Duplicate code everywhere
Hard-Coded Values - No configuration

MEDIUM

Lava Flow - Dead code remains
Golden Hammer - One tool for everything
Premature Optimization - Optimize too early

LOW

Magic Numbers - Unnamed constants
Long Method - Methods too long
Poor Naming - Unclear variable names

God Object Anti-Pattern

God Object

CRITICAL

Description

Single class that knows too much or does too much. Takes on most responsibilities in system, causing tight coupling and low cohesion. Also known as "Blob" or "Winnebago".

Symptoms

Single class with >30 methods
Class with >1000 lines of code
Generic class names (Manager, Controller, Handler, Service)
Many dependencies on this class
Class touches many different concerns
Difficult to test in isolation

Consequences

High coupling to many other classes
Low cohesion (unrelated responsibilities)
Hard to understand and maintain
Difficult to test
Limits reusability
Single point of failure

Detection

Cyclomatic Complexity > 50
Lines of Code > 500
Number of Methods > 30
Fan-In > 10 (many classes depend on it)
Fan-Out > 20 (depends on many classes)

Refactoring Path

  1. Identify distinct responsibilities
  2. Group methods by cohesive functionality
  3. Extract classes for each responsibility
  4. Apply Single Responsibility Principle
  5. Use Dependency Injection for services

Spaghetti Code Anti-Pattern

Spaghetti Code

HIGH

Description

Code with complex and tangled control structure. Difficult to follow logic flow, heavy use of GOTO (in old languages) or complex nested conditionals.

Symptoms

Deeply nested if/else statements (>5 levels)
Complex control flow (hard to follow)
Methods with >50 lines
Minimal use of functions/methods
Lots of global state
Hard to debug

Detection

Cyclomatic Complexity > 20
Nesting Depth > 5
Method Length > 50 lines

Refactoring Path

  1. Extract nested logic into methods
  2. Use guard clauses (early returns)
  3. Apply Strategy pattern for complex conditionals
  4. Replace Conditional with Polymorphism

Lava Flow Anti-Pattern

Lava Flow

MEDIUM

Description

Dead code and forgotten design artifacts that remain in codebase. Code that was experimental or temporary but never removed.

Symptoms

Commented-out code blocks
TODO/FIXME comments from years ago
Unused variables/methods/classes
Obsolete design patterns
Fear of deleting code ("might need it later")

Detection

Static analysis for unused code
Search for TODO/FIXME older than 6 months
Find commented-out code blocks
Coverage analysis (0% coverage = likely unused)

Refactoring Path

  1. Run static analysis (Pylint, ReSharper, SonarQube)
  2. Delete commented-out code (version control preserves history)
  3. Remove or complete TODO/FIXME items
  4. Delete unused methods/classes after verification

Golden Hammer Anti-Pattern

Golden Hammer

MEDIUM

Description

Using familiar tool/technology for everything, regardless of fit. "If all you have is a hammer, everything looks like a nail." Also known as "Silver Bullet".

Symptoms

Same pattern used everywhere
Forcing technology into inappropriate use cases
Resistance to learning new approaches
Complex workarounds to make tool fit

Examples

Singleton for everything - Makes testing difficult, hides dependencies
ORM for all database access - Complex queries become inefficient
Microservices for small apps - Unnecessary complexity, operational overhead
NoSQL for all data - Loses ACID guarantees when needed

Prevention

  1. Understand problem requirements first
  2. Evaluate multiple solutions
  3. Choose technology that fits problem
  4. Learn multiple tools/patterns
  5. Be pragmatic, not dogmatic

Copy-Paste Programming

Copy-Paste Programming

MEDIUM

Description

Copying code from one place and pasting it elsewhere with minor modifications. Creates maintenance burden - bugs must be fixed in multiple places. Also known as "Code Clone" or "Duplicate Code".

Symptoms

Similar code blocks in multiple places
Same logic with slightly different variables
Duplicate validation logic
Repeated algorithms

Consequences

Bug fixes required in multiple places
Inconsistent behavior
Increased maintenance cost
Larger codebase

Detection Tools

PMD CPD - Copy/Paste Detector
SonarQube - Duplicate code detection
Jscpd - JavaScript/TypeScript clone detector
Threshold: >5% duplicate code

Refactoring Path

  1. Identify duplicate code blocks
  2. Extract common logic to shared function
  3. Use inheritance/composition for shared behavior
  4. Parameterize differences

Magic Numbers

Magic Numbers

LOW

Description

Using unnamed numerical constants directly in code. Reduces readability and maintainability.

Symptoms

Unexplained numbers in code
Same number repeated multiple places
No context for what number represents

Refactoring Path

  1. Extract constants with meaningful names
  2. Use Replace Magic Number with Symbolic Constant refactoring
  3. Group related constants (enums or static classes)

    def send_email(self, user, message): pass

class UserRepository:
    def update_profile(self, user, data): pass
    def delete_account(self, user): pass

class ReportGenerator:
    def generate_report(self, user): pass

Spaghetti Code - Python

❌ Spaghetti Code Anti-Pattern

# ❌ HIGH: Deeply nested conditionals
def process_order(order):
    if order.items:
        if order.customer:
            if order.customer.is_active:
                if order.total > 0:
                    if order.payment_method:
                        if order.payment_method.is_valid:
                            if order.shipping_address:
                                # ... deeply nested logic
                                pass

✅ Refactored: Guard Clauses

# ✅ Guard clauses (early returns)
def process_order(order):
    if not order.items:
        raise ValueError("Order has no items")
    if not order.customer or not order.customer.is_active:
        raise ValueError("Invalid customer")
    if order.total <= 0:
        raise ValueError("Invalid order total")
    if not self._validate_payment(order):
        raise ValueError("Invalid payment")
    if not order.shipping_address:
        raise ValueError("Missing shipping address")
    
    self._charge_payment(order)
    self._ship_order(order)

def _validate_payment(self, order):
    return order.payment_method and order.payment_method.is_valid

Copy-Paste Programming - Python

❌ Copy-Paste Anti-Pattern

# ❌ MEDIUM: Duplicate validation logic
def validate_user_email(email):
    if not email:
        return False
    if '@' not in email:
        return False
    if len(email) < 5:
        return False
    return True

def validate_admin_email(email):
    if not email:
        return False
    if '@' not in email:
        return False
    if len(email) < 5:
        return False
    return True  # Same logic duplicated!

✅ Refactored: DRY Principle

# ✅ Single source of truth
def validate_email(email: str) -> bool:
    if not email:
        return False
    if '@' not in email:
        return False
    if len(email) < 5:
        return False
    return True

# Reuse in both contexts
def validate_user_email(email):
    return validate_email(email)

def validate_admin_email(email):
    return validate_email(email)

Magic Numbers - Python & C#

❌ Magic Numbers Anti-Pattern

PREMIUM_THRESHOLD = 1000
STANDARD_THRESHOLD = 500
PREMIUM_DISCOUNT = 0.15
STANDARD_DISCOUNT = 0.10
BASIC_DISCOUNT = 0.05

        return price * PREMIUM_DISCOUNT

        return price * STANDARD_DISCOUNT
    else:
        return price * BASIC_DISCOUNT

Automated Anti-Pattern Detection in CORTEX

CORTEX includes intelligent agents that automatically detect anti-patterns using code metrics, pattern matching, and architectural analysis.

Anti-Pattern Detector

# CORTEX Anti-Pattern Detection System
class AntiPatternDetector:
    def detect(self, file_path: str) -> List[AntiPattern]:
        detected = []
        
        # God Object detection
        for cls in self.parse_classes(file_path):
            if cls.method_count > 30 or cls.line_count > 500:
                detected.append(AntiPattern(
                    name="God Object",
                    severity="CRITICAL",
                    location=cls.location,
                    metrics={
                        "methods": cls.method_count,
                        "lines": cls.line_count,
                        "complexity": cls.complexity
                    },
                    suggestion="Extract separate classes for distinct responsibilities"
                ))
        
        # Spaghetti Code detection
        for method in self.parse_methods(file_path):
            if method.complexity > 20 or method.nesting_depth > 5:
                detected.append(AntiPattern(
                    name="Spaghetti Code",
                    severity="HIGH",
                    location=method.location,
                    metrics={
                        "complexity": method.complexity,
                        "nesting": method.nesting_depth
                    },
                    suggestion="Use guard clauses and extract methods"
                ))
        
        # Lava Flow detection
        commented_code = self.find_commented_code(file_path)
        old_todos = self.find_old_todos(file_path, age_months=6)
        
        if commented_code or old_todos:
            detected.append(AntiPattern(
                name="Lava Flow",
                severity="MEDIUM",
                location=file_path,
                items={
                    "commented_blocks": len(commented_code),
                    "old_todos": len(old_todos)
                },
                suggestion="Remove commented code and obsolete TODOs"
            ))
        
        # Duplicate Code detection
        duplicates = self.find_duplicates(file_path)
        if duplicates.percentage > 5:
            detected.append(AntiPattern(
                name="Copy-Paste Programming",
                severity="MEDIUM",
                location=file_path,
                metrics={"duplicate_percentage": duplicates.percentage},
                suggestion="Extract common logic to shared functions"
            ))
        
        return detected

Automated Metrics Collection

# Code Metrics Analysis
class CodeMetricsAnalyzer:
    def analyze(self, file_path: str) -> Metrics:
        return Metrics(
            cyclomatic_complexity=self.calculate_complexity(file_path),
            lines_of_code=self.count_lines(file_path),
            methods_per_class=self.count_methods(file_path),
            inheritance_depth=self.measure_inheritance_depth(file_path),
            coupling_count=self.measure_coupling(file_path),
            duplicate_percentage=self.detect_duplicates(file_path),
            comment_ratio=self.calculate_comment_ratio(file_path)
        )
    
    def flag_anti_patterns(self, metrics: Metrics) -> List[str]:
        flags = []
        
        if metrics.cyclomatic_complexity > 20:
            flags.append("God Object or Spaghetti Code")
        if metrics.lines_of_code > 500:
            flags.append("God Object")
        if metrics.methods_per_class > 30:
            flags.append("God Object or Interface Bloat")
        if metrics.inheritance_depth > 5:
            flags.append("Deep Inheritance Tree")
        if metrics.coupling_count > 10:
            flags.append("Tight Coupling")
        if metrics.duplicate_percentage > 5:
            flags.append("Copy-Paste Programming")
        
        return flags
