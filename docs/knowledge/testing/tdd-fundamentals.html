🔄 The RED-GREEN-REFACTOR Cycle

TDD follows a simple three-step cycle that ensures code correctness and design quality. This D3.js visualization shows the continuous flow of the TDD process. 

stateDiagram-v2
    [*] --> RED: Write Failing Test
    RED --> GREEN: Write Minimum Code
    GREEN --> REFACTOR: Improve Design
    REFACTOR --> RED: Add New Feature
    REFACTOR --> [*]: Feature Complete
    
    note right of RED
        • Test fails (expected)

        • Clarifies requirements
    end note
    
    note right of GREEN
        • Test passes
        • Minimal implementation
        • Proof of concept
    end note
    
    note right of REFACTOR

⚖️ TDD Benefits vs Common Pitfalls

Understanding both the advantages and common mistakes helps you maximize TDD effectiveness.

📈 TDD Benefits Timeline

✅ Key Benefits

Better Design: Test-first thinking leads to cleaner interfaces
Living Documentation: Tests describe expected behavior
Confidence: Safe refactoring with regression protection
Early Detection: Bugs caught immediately, not in production
Reduced Debugging: Less time hunting for issues
Safety Net: Prevent regressions when adding features

⚠️ Common Pitfalls

Tests After Code: Loses design benefits (not TDD!)
Testing Implementation: Brittle tests that break easily
Over-Mocking: Tests don't reflect real behavior
Skipping Refactor: Technical debt accumulates
Complex Tests: Tests harder to maintain than code
Infrequent Runs: Delayed feedback, harder debugging

🏆 TDD Challenge

Build a string reversal function using pure TDD. Requirements:

Write test first for empty string
Write test for single character
Write test for multiple characters
Handle edge cases (null, undefined)
Refactor after each passing test
# TDD Solution: String Reversal

# Test 1: Empty string
def test_reverse_empty_string():
    assert reverse("") == ""

# Implementation 1:
def reverse(s):
    return ""

# Test 2: Single character
def test_reverse_single_char():
    assert reverse("a") == "a"

# Implementation 2:
def reverse(s):
    if len(s) <= 1:
        return s
    return s

# Test 3: Multiple characters
def test_reverse_multiple_chars():
    assert reverse("abc") == "cba"

# Implementation 3:
def reverse(s):
    if len(s) <= 1:
        return s
    return s[::-1]

# Test 4: Edge cases
def test_reverse_none():
    assert reverse(None) == ""

# Final Implementation (Refactored):
def reverse(s):
    if not s:
        return ""
    return s[::-1]
