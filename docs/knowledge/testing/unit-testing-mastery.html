🔺 The Test Pyramid

The test pyramid guides the optimal distribution of tests. Unit tests form the foundation, providing fast, reliable feedback.

🎯 Arrange-Act-Assert (AAA) Pattern

The AAA pattern structures tests into three clear phases, making them easy to read and maintain. 

sequenceDiagram
    participant Test as Test Method
    participant SUT as System Under Test
    participant Dep as Dependencies
    
    Note over Test: ARRANGE Phase
    Test->>Dep: Set up test doubles
    Test->>SUT: Create instance
    Test->>Test: Prepare test data
    
    Note over Test: ACT Phase
    Test->>SUT: Call method being tested
    SUT->>Dep: Use dependencies
    SUT-->>Test: Return result
    
    Note over Test: ASSERT Phase
    Test->>Test: Verify expected outcome
    Test->>Test: Check side effects
    Test->>Dep: Verify interactions

🔧 Arrange

Set up test conditions: create objects, configure mocks, prepare test data

⚡ Act

Execute the specific behavior being tested (usually a single method call)

✅ Assert

Verify the result matches expectations and check for side effects

🎭 Test Doubles: Mocks, Stubs, Fakes & Spies

Test doubles isolate the code under test by replacing real dependencies. Each type serves a specific purpose.

✨ Unit Testing Best Practices

✅ Do This

  • F.I.R.S.T Principles: Fast, Independent, Repeatable, Self-validating, Timely
  • One Assert: Test one thing per test method
  • Descriptive Names: should_return_error_when_email_invalid()
  • Test Behavior: Focus on what, not how
  • Avoid Logic: No conditionals or loops in tests
  • Isolate Tests: No shared state between tests

❌ Avoid This

  • Test Interdependence: Tests that depend on execution order
  • Testing Privates: Test public interface only
  • Over-Mocking: Mocking everything defeats the purpose
  • Brittle Tests: Tests that break with refactoring
  • Magic Numbers: Use named constants for test data
  • Test Code Duplication: Extract common setup to helper methods

🏆 Unit Testing Challenge

Write unit tests for a UserService class that handles user registration. Requirements:

  • Test email validation (reject invalid formats)
  • Test password strength requirements (min 8 chars, uppercase, number)
  • Mock the database repository
  • Verify database save is called with correct user data
  • Test duplicate email rejection
💡 Hint 1: Test Structure

Use AAA pattern: Arrange (create UserService with mock repo), Act (call register), Assert (verify result and mock calls)

💡 Hint 2: Test Data

Create test cases: valid user, invalid email, weak password, duplicate email

💡 Hint 3: Mocking

Mock repository methods: find_by_email (returns None for new users), save (verifies correct data passed) 

import pytest
from unittest.mock import Mock, MagicMock

class TestUserService:
    def test_should_register_user_with_valid_data(self):
        # ARRANGE
        mock_repo = Mock()
        mock_repo.find_by_email.return_value = None  # No existing user
        service = UserService(mock_repo)
        
        # ACT
        result = service.register("john@example.com", "SecurePass123")
        
        # ASSERT
        assert result.success is True
        mock_repo.save.assert_called_once()
        saved_user = mock_repo.save.call_args[0][0]
        assert saved_user.email == "john@example.com"
    
    def test_should_reject_invalid_email_format(self):
        # ARRANGE
        mock_repo = Mock()
        service = UserService(mock_repo)
        
        # ACT
        result = service.register("invalid-email", "SecurePass123")
        
        # ASSERT
        assert result.success is False
        assert "invalid email" in result.error.lower()
        mock_repo.save.assert_not_called()
