📝 Gherkin Syntax: Given-When-Then

Gherkin provides a structured, human-readable language for describing application behavior that both business and technical teams understand. 

sequenceDiagram
    participant User as 👤 User
    participant System as 💻 System
    participant Backend as 🔧 Backend
    
    Note over User,Backend: GIVEN (Initial Context)
    User->>System: User is logged in
    System->>Backend: Session valid
    
    Note over User,Backend: WHEN (Action/Event)
    User->>System: Clicks "Add to Cart"
    System->>Backend: POST /cart/items
    
    Note over User,Backend: THEN (Expected Outcome)
    Backend-->>System: 201 Created
    System-->>User: Item added confirmation
    User->>User: Cart count increases
                
Feature: Shopping Cart Management
  As a customer
  I want to add products to my cart
  So that I can purchase multiple items together

  Scenario: Add product to empty cart
    Given I am logged in as "john@example.com"
    And my cart is empty
    When I add "Laptop" to my cart
    Then I should see 1 item in my cart
    And the cart total should be "$999.99"

📋 Given (Context)

Set up initial state
Preconditions that must be true
Example: "Given I am on the homepage"
Can have multiple "And" clauses

⚡ When (Action)

The specific action or event
What the user/system does
Example: "When I click the login button"
Should be a single key action

✅ Then (Outcome)

Expected observable results
What should happen after action
Example: "Then I should see my dashboard"
Can verify multiple outcomes

✨ BDD & E2E Best Practices

✅ Do This

Focus on Business Value: Test user journeys that matter
Keep Scenarios Declarative: What, not how
Use Data Tables: For multiple examples efficiently
Maintain Test Independence: Each scenario runs alone
Parallelize Tests: Speed up CI/CD pipelines
Version with Code: Tests live in source control

❌ Avoid This

Testing Too Much: E2E tests are expensive, be selective
Implementation Details: Don't test how, test what
Brittle Selectors: Use stable test IDs, not CSS classes
No Waiting Strategy: Handle async properly
Ignoring Flakiness: Fix flaky tests immediately
Missing Recovery: Tests should clean up after themselves

🏆 BDD & E2E Challenge

Write a complete BDD feature with scenarios for a user registration flow. Requirements:

Feature: User Registration
Scenario 1: Successful registration with valid data
Scenario 2: Registration fails with duplicate email
Scenario 3: Registration fails with weak password
Scenario 4: Registration succeeds and sends welcome email
Use proper Gherkin syntax (Given-When-Then)
💡 Hint 1: Feature Structure

Start with Feature description, then list multiple Scenarios. Each scenario follows Given-When-Then structure.

💡 Hint 2: Context Setup

Use "Given I am on the registration page" to set context. Add "And" clauses for additional preconditions.

💡 Hint 3: Verification

"Then" clauses verify outcomes: "Then I should see a success message", "Then I should receive a welcome email" 

Feature: User Registration
  As a new user
  I want to register for an account
  So that I can access the platform features

  Background:
    Given I am on the registration page
    And the registration form is displayed

  Scenario: Successful registration with valid credentials
    Given I have not registered before
    When I enter email "john.doe@example.com"
    And I enter password "SecurePass123!"
    And I enter password confirmation "SecurePass123!"
    And I click the "Register" button
    Then I should see a success message "Registration successful!"
    And I should be redirected to the dashboard
    And I should receive a welcome email

  Scenario: Registration fails with duplicate email
    Given a user with email "existing@example.com" already exists
    When I enter email "existing@example.com"
    And I enter password "SecurePass123!"
    And I enter password confirmation "SecurePass123!"
    And I click the "Register" button
    Then I should see an error message "Email already registered"
    And I should remain on the registration page
    And no welcome email should be sent

  Scenario: Registration fails with weak password
    When I enter email "jane@example.com"
    And I enter password "weak"
    And I enter password confirmation "weak"
    And I click the "Register" button
    Then I should see an error message "Password must be at least 8 characters"
    And I should remain on the registration page

  Scenario Outline: Password validation rules
    When I enter email "test@example.com"
    And I enter password ""
    And I click the "Register" button
    Then I should see ""

    Examples:
      | password    | error_message                           |
      | abc123      | Password must be at least 8 characters  |
      | abcdefgh    | Password must contain uppercase letter  |
      | ABCDEFGH    | Password must contain lowercase letter  |
      | AbcdEfgh    | Password must contain a number          |
