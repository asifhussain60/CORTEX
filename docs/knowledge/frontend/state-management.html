Overview

State management patterns and best practices for React applications using Redux, Context API, Zustand, and other modern solutions.

State Management Principles:
Single Source of Truth: Centralized state for predictability
Immutability: Never mutate state directly
Predictable Updates: Pure functions for state changes
Separation: UI state vs server state vs form state
Right Tool: Match solution complexity to problem size

Redux Patterns

Use Redux Toolkit for Modern Redux

HIGH

Redux Toolkit (RTK) is the official recommended approach. It includes utilities that simplify store setup, reducers, and immutable updates.

✅ Good - Redux Toolkit

import { createSlice, PayloadAction } from '@reduxjs/toolkit';

interface User {
  id: string;
  name: string;
  email: string;
}

interface UserState {
  users: User[];
  loading: boolean;
  error: string | null;
}

const initialState: UserState = {
  users: [],
  loading: false,
  error: null
};

const userSlice = createSlice({
  name: 'users',
  initialState,
  reducers: {
    fetchUsersStart: (state) => {
      // Immer allows "mutating" syntax
      state.loading = true;
      state.error = null;
    },
    fetchUsersSuccess: (state, action: PayloadAction) => {
      state.users = action.payload;
      state.loading = false;
    },
    fetchUsersFailure: (state, action: PayloadAction) => {
      state.error = action.payload;
      state.loading = false;
    },
    addUser: (state, action: PayloadAction) => {
      state.users.push(action.payload);
    }
  }
});

export const { 
  fetchUsersStart, 
  fetchUsersSuccess, 
  fetchUsersFailure,
  addUser 
} = userSlice.actions;

export default userSlice.reducer;

❌ Bad - Legacy Redux

// Action types as constants
const FETCH_USERS_START = 'FETCH_USERS_START';
const FETCH_USERS_SUCCESS = 'FETCH_USERS_SUCCESS';
const FETCH_USERS_FAILURE = 'FETCH_USERS_FAILURE';

// Action creators
const fetchUsersStart = () => ({ type: FETCH_USERS_START });
const fetchUsersSuccess = (users) => ({ 
  type: FETCH_USERS_SUCCESS, 
  payload: users 
});

// Reducer with manual immutability
const userReducer = (state = initialState, action) => {
  switch (action.type) {
    case FETCH_USERS_START:
      return { ...state, loading: true, error: null };
    case FETCH_USERS_SUCCESS:
      return { ...state, users: action.payload, loading: false };
    // Lots of boilerplate

Use RTK Query for Server State

HIGH

Don't put server data in Redux state manually. Use RTK Query for automatic caching, refetching, and optimistic updates.

✅ Good - RTK Query

import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react';

export const apiSlice = createApi({
  reducerPath: 'api',
  baseQuery: fetchBaseQuery({ baseUrl: '/api' }),
  tagTypes: ['User', 'Post'],
  endpoints: (builder) => ({
    getUsers: builder.query({
      query: () => '/users',
      providesTags: ['User']
    }),
    
    getUserById: builder.query({
      query: (id) => `/users/${id}`,
      providesTags: (result, error, id) => [{ type: 'User', id }]
    }),
    
    createUser: builder.mutation>({
      query: (newUser) => ({
        url: '/users',
        method: 'POST',
        body: newUser
      }),
      invalidatesTags: ['User']
    }),
    
    updateUser: builder.mutation }>({
      query: ({ id, updates }) => ({
        url: `/users/${id}`,
        method: 'PATCH',
        body: updates
      }),
      invalidatesTags: (result, error, { id }) => [{ type: 'User', id }]
    })
  })
});

export const { 
  useGetUsersQuery, 
  useGetUserByIdQuery,
  useCreateUserMutation,
  useUpdateUserMutation 
} = apiSlice;

// Component usage
function UserList() {
  const { data: users, isLoading, error } = useGetUsersQuery();
  const [createUser] = useCreateUserMutation();
  
  // Automatic caching, refetching, loading states
}

Normalize Complex State

MEDIUM

For nested or relational data, normalize state structure to avoid duplication and simplify updates.

✅ Good - Normalized State

import { createEntityAdapter } from '@reduxjs/toolkit';

// Entity adapter creates normalized structure
const usersAdapter = createEntityAdapter({
  selectId: (user) => user.id,
  sortComparer: (a, b) => a.name.localeCompare(b.name)
});

const userSlice = createSlice({
  name: 'users',
  initialState: usersAdapter.getInitialState(),
  reducers: {
    userAdded: usersAdapter.addOne,
    usersReceived: usersAdapter.setAll,
    userUpdated: usersAdapter.updateOne,
    userRemoved: usersAdapter.removeOne
  }
});

// State structure:
// {
//   ids: ['1', '2', '3'],
//   entities: {
//     '1': { id: '1', name: 'Alice' },
//     '2': { id: '2', name: 'Bob' },
//     '3': { id: '3', name: 'Charlie' }
//   }
// }

❌ Bad - Nested State

// Deeply nested, denormalized
const state = {
  posts: [
    {
      id: '1',
      title: 'Post 1',
      author: { id: '1', name: 'Alice' },
      comments: [
        { 
          id: '1', 
          text: 'Comment',
          author: { id: '1', name: 'Alice' } // Duplicated
        }
      ]
    }
  ]
};
// Updating Alice's name requires finding all occurrences

Context API Patterns

Split Contexts by Concern

HIGH

Create separate contexts for different domains to avoid unnecessary re-renders. Don't put everything in one giant context.

✅ Good - Split Contexts

// Auth context - changes rarely
const AuthContext = createContext(null);

export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState(null);
  
  const login = async (credentials: Credentials) => {
    const user = await authService.login(credentials);
    setUser(user);
  };
  
  const logout = () => setUser(null);
  
  return (
    
      {children}
    
  );
}

// Theme context - changes occasionally
const ThemeContext = createContext(null);

export function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState<'light' | 'dark'>('light');
  
  return (
    
      {children}
    
  );
}

// Components only re-render when their context changes

❌ Bad - Monolithic Context

// Everything in one context
const AppContext = createContext(null);

function AppProvider({ children }) {
  const [user, setUser] = useState(null);
  const [theme, setTheme] = useState('light');
  const [notifications, setNotifications] = useState([]);
  const [settings, setSettings] = useState({});
  
  // Any state change re-renders ALL consumers
  return (
    
      {children}
    
  );
}

Optimize Context with useMemo

MEDIUM

Memoize context value to prevent unnecessary re-renders of consumers when provider re-renders.

✅ Good - Memoized Context Value

function TodoProvider({ children }: { children: ReactNode }) {
  const [todos, setTodos] = useState([]);
  
  // Memoize the context value
  const value = useMemo(() => ({
    todos,
    addTodo: (text: string) => {
      setTodos(prev => [...prev, { id: Date.now(), text, done: false }]);
    },
    toggleTodo: (id: number) => {
      setTodos(prev => 
        prev.map(todo => 
          todo.id === id ? { ...todo, done: !todo.done } : todo
        )
      );
    },
    removeTodo: (id: number) => {
      setTodos(prev => prev.filter(todo => todo.id !== id));
    }
  }), [todos]); // Only recreate when todos change
  
  return (
    
      {children}
    
  );
}

Modern State Solutions

Consider Zustand for Simpler State

MEDIUM

Zustand provides Redux-like global state with less boilerplate and better TypeScript support. Great for small to medium apps.

✅ Good - Zustand Store

import { create } from 'zustand';
import { devtools, persist } from 'zustand/middleware';

interface CartState {
  items: CartItem[];
  addItem: (item: CartItem) => void;
  removeItem: (id: string) => void;
  clearCart: () => void;
  total: () => number;
}

const useCartStore = create()(
  devtools(
    persist(
      (set, get) => ({
        items: [],
        
        addItem: (item) => set((state) => ({
          items: [...state.items, item]
        })),
        
        removeItem: (id) => set((state) => ({
          items: state.items.filter(item => item.id !== id)
        })),
        
        clearCart: () => set({ items: [] }),
        
        total: () => {
          const state = get();
          return state.items.reduce((sum, item) => sum + item.price, 0);
        }
      }),
      { name: 'cart-storage' }
    )
  )
);

// Component usage - super simple
function Cart() {
  const items = useCartStore((state) => state.items);
  const removeItem = useCartStore((state) => state.removeItem);
  const total = useCartStore((state) => state.total());
  
  // Only re-renders when items change
}

Use React Query for Server State

HIGH

Don't manage server data in Redux or Context. React Query handles caching, background updates, and synchronization automatically.

✅ Good - React Query

import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';

// Query hook
function useUser(userId: string) {
  return useQuery({
    queryKey: ['user', userId],
    queryFn: () => fetchUser(userId),
    staleTime: 5 * 60 * 1000, // Consider fresh for 5 min
    cacheTime: 10 * 60 * 1000, // Keep in cache for 10 min
  });
}

// Mutation hook
function useUpdateUser() {
  const queryClient = useQueryClient();
  
  return useMutation({
    mutationFn: (user: User) => updateUser(user),
    onSuccess: (updatedUser) => {
      // Update cache
      queryClient.setQueryData(['user', updatedUser.id], updatedUser);
      // Invalidate related queries
      queryClient.invalidateQueries({ queryKey: ['users'] });
    }
  });
}

// Component
function UserProfile({ userId }: { userId: string }) {
  const { data: user, isLoading, error } = useUser(userId);
  const updateMutation = useUpdateUser();
  
  // Automatic background refetching, retry, caching
}

State Management Best Practices

Choose the Right Tool for State Type

HIGH

Different state types need different solutions. Don't use Redux for everything.

State Type Decision Matrix:
Server State: React Query, RTK Query, SWR
Global UI State: Redux Toolkit, Zustand, Jotai
URL State: React Router, Next.js router
Form State: React Hook Form, Formik
Local Component State: useState, useReducer
Derived State: useMemo, selectors
Ref State: useRef (doesn't trigger re-renders)

Colocate State When Possible

MEDIUM

Keep state as close as possible to where it's used. Don't lift state to global store unless it's truly global.

✅ Good - Colocated State

// Modal state only used in Modal component
function Modal({ children }: { children: ReactNode }) {
  const [isOpen, setIsOpen] = useState(false);
  
  return (
    <>
      
      {isOpen && (
        

          {children}
          
        

      )}
    
  );
}

// Accordion state only used in Accordion
function Accordion({ items }: { items: Item[] }) {
  const [openIndex, setOpenIndex] = useState(null);
  
  return (
    

      {items.map((item, index) => (
         setOpenIndex(index === openIndex ? null : index)}
        />
      ))}
    

  );
}

❌ Bad - Over-Globalized State

// Putting UI component state in Redux
const uiSlice = createSlice({
  name: 'ui',
  initialState: {
    modalOpen: false,
    accordionOpenIndex: null,
    tooltipVisible: false,
    // Unnecessary global state
  },
  reducers: {
    openModal: (state) => { state.modalOpen = true; },
    closeModal: (state) => { state.modalOpen = false; },
    // Too much boilerplate for simple UI state
  }
});
