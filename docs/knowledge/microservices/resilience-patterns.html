Overview

Resilience patterns help microservices handle failures gracefully, prevent cascading failures, and maintain availability under adverse conditions.

Core Resilience Principles:
Fail Fast: Detect failures quickly and respond immediately
Fail Safe: Degrade gracefully rather than complete failure
Isolation: Prevent failures from spreading across services
Recovery: Automatically recover from transient failures
Monitoring: Observe and measure resilience metrics

Circuit Breaker Pattern

Implement Circuit Breaker for External Calls

HIGH

Use circuit breaker to prevent repeated calls to a failing service. Circuit has three states: Closed (normal), Open (blocking calls), Half-Open (testing recovery).

✅ Good - Circuit Breaker Implementation

# Using Polly library in .NET
from polly import CircuitBreakerPolicy
import httpx

class PaymentService:
    def __init__(self):
        # Circuit breaks after 5 failures in 30s
        self.circuit_breaker = CircuitBreakerPolicy(
            failure_threshold=5,
            timeout_seconds=30,
            success_threshold=3,  # Half-open attempts
            min_throughput=10
        )
    
    async def process_payment(self, payment_data):
        try:
            return await self.circuit_breaker.execute(
                self._call_payment_api,
                payment_data
            )
        except CircuitBreakerOpenException:
            # Circuit is open - fail fast
            return self._use_fallback_payment(payment_data)
    
    async def _call_payment_api(self, payment_data):
        async with httpx.AsyncClient() as client:
            response = await client.post(
                "https://payment-api.example.com/charge",
                json=payment_data,
                timeout=5.0
            )
            response.raise_for_status()
            return response.json()

❌ Bad - No Circuit Breaker

# Keeps trying even when service is down
class PaymentService:
    async def process_payment(self, payment_data):
        # No circuit breaker - will keep hammering
        # a failing service, wasting resources
        async with httpx.AsyncClient() as client:
            response = await client.post(
                "https://payment-api.example.com/charge",
                json=payment_data,
                timeout=5.0  # Each call waits 5s
            )
            return response.json()
        # If payment API is down, this blocks threads
        # and degrades entire system performance
Circuit Breaker States:
Closed: Normal operation, tracking failures
Open: Fails fast without calling service (30s default)
Half-Open: Test with single call to check recovery

Configure Circuit Breaker Thresholds Appropriately

HIGH

Set failure threshold based on service SLA and traffic patterns. Too sensitive trips unnecessarily, too lenient allows cascading failures.

✅ Good - Environment-Specific Configuration

# Circuit Breaker Configuration
circuit_breakers:
  payment_service:
    failure_threshold: 5        # Open after 5 failures
    timeout_seconds: 30         # Open for 30 seconds
    success_threshold: 3        # 3 successes to close
    min_throughput: 10          # Min requests before tripping
    failure_rate_threshold: 0.5 # 50% failure rate
    
  external_api:
    failure_threshold: 10       # More lenient for flaky API
    timeout_seconds: 60
    success_threshold: 2
    min_throughput: 20
    
  critical_service:
    failure_threshold: 3        # Strict for critical path
    timeout_seconds: 15
    success_threshold: 5        # Require strong recovery signal

Retry Pattern

Implement Exponential Backoff with Jitter

HIGH

Use exponential backoff with random jitter to avoid thundering herd problem when service recovers.

✅ Good - Exponential Backoff with Jitter

import asyncio
import random

class RetryPolicy:
    def __init__(self, max_attempts=3, base_delay=1.0):
        self.max_attempts = max_attempts
        self.base_delay = base_delay
    
    async def execute_with_retry(self, func, *args, **kwargs):
        last_exception = None
        
        for attempt in range(self.max_attempts):
            try:
                return await func(*args, **kwargs)
            except Exception as e:
                last_exception = e
                
                if attempt < self.max_attempts - 1:
                    # Exponential backoff: 1s, 2s, 4s...
                    delay = self.base_delay * (2 ** attempt)
                    
                    # Add jitter: ±25% random variation
                    jitter = delay * 0.25 * random.uniform(-1, 1)
                    actual_delay = delay + jitter
                    
                    await asyncio.sleep(actual_delay)
                    
        raise last_exception

❌ Bad - Fixed Delay Retry

# Fixed delay causes thundering herd
async def call_api_with_retry(url):
    for attempt in range(3):
        try:
            return await make_request(url)
        except Exception:
            await asyncio.sleep(1)  # All clients retry at same time
            # When service recovers, all clients
            # hit it simultaneously

Only Retry Transient Failures

HIGH

Distinguish between transient (503, network timeout) and permanent failures (400, 404). Don't retry client errors.

✅ Good - Selective Retry

class SmartRetryPolicy:
    TRANSIENT_ERRORS = {
        408,  # Request Timeout
        429,  # Too Many Requests
        500,  # Internal Server Error
        502,  # Bad Gateway
        503,  # Service Unavailable
        504   # Gateway Timeout
    }
    
    async def should_retry(self, exception):
        if isinstance(exception, httpx.HTTPStatusError):
            # Retry only transient HTTP errors
            return exception.response.status_code in self.TRANSIENT_ERRORS
        
        if isinstance(exception, httpx.NetworkError):
            # Retry network errors
            return True
        
        # Don't retry client errors (400, 401, 404, etc)
        return False

Timeout Pattern

Set Explicit Timeouts for All External Calls

HIGH

Never make external calls without timeouts. Set connection timeout and read timeout separately.

✅ Good - Explicit Timeouts

import httpx

# Configure timeouts explicitly
timeout_config = httpx.Timeout(
    connect=5.0,  # 5s to establish connection
    read=10.0,    # 10s to read response
    write=5.0,    # 5s to send request
    pool=10.0     # 10s to get connection from pool
)

async with httpx.AsyncClient(timeout=timeout_config) as client:
    response = await client.get("https://api.example.com/data")
    
# Or per-request timeout
response = await client.get(
    "https://api.example.com/data",
    timeout=15.0  # Total timeout 15s
)

❌ Bad - No Timeout

# Dangerous - can hang indefinitely
async with httpx.AsyncClient() as client:
    # No timeout specified
    response = await client.get(
        "https://api.example.com/data"
    )
    # If server never responds, thread is blocked
    # forever, exhausting connection pool

Bulkhead Pattern

Isolate Resource Pools

MEDIUM

Partition resources (threads, connections) to prevent one failing component from exhausting all resources.

✅ Good - Bulkhead Isolation

import asyncio
from asyncio import Semaphore

class BulkheadExecutor:
    def __init__(self):
        # Separate semaphores for different services
        self.payment_semaphore = Semaphore(10)  # Max 10 concurrent
        self.inventory_semaphore = Semaphore(20) # Max 20 concurrent
        self.email_semaphore = Semaphore(5)     # Max 5 concurrent
    
    async def call_payment_service(self, data):
        async with self.payment_semaphore:
            # Only 10 concurrent payment calls allowed
            # If payment service is slow, it won't block
            # inventory or email calls
            return await payment_api.process(data)
    
    async def call_inventory_service(self, data):
        async with self.inventory_semaphore:
            return await inventory_api.check(data)
    
    async def call_email_service(self, data):
        async with self.email_semaphore:
            return await email_api.send(data)

Fallback Pattern

Provide Graceful Degradation

HIGH

When primary service fails, return cached data, default values, or reduced functionality rather than complete failure.

✅ Good - Fallback Strategy

class ProductService:
    def __init__(self, cache, circuit_breaker):
        self.cache = cache
        self.circuit_breaker = circuit_breaker
    
    async def get_product_details(self, product_id):
        try:
            # Try primary source
            return await self.circuit_breaker.execute(
                self._fetch_from_api, product_id
            )
        except CircuitBreakerOpenException:
            # Fallback 1: Return cached data
            cached = await self.cache.get(f"product:{product_id}")
            if cached:
                return {**cached, "source": "cache", "stale": True}
            
            # Fallback 2: Return basic data from database
            basic_data = await self.db.get_basic_product(product_id)
            if basic_data:
                return {**basic_data, "source": "database"}
            
            # Fallback 3: Return minimal safe default
            return {
                "id": product_id,
                "name": "Product information unavailable",
                "available": False,
                "source": "fallback"
            }
