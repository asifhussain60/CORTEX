What is a Vector Database?

A vector database is optimized for storing and querying high-dimensional vectors (embeddings). Unlike traditional databases that search for exact matches, vector databases find similar items using approximate nearest neighbor (ANN) algorithms.

Key Features

Similarity Search: Find nearest neighbors based on vector distance
High-Dimensional Indexing: Efficient search in 100s-1000s of dimensions
ANN Algorithms: Trade accuracy for speed (HNSW, IVF, LSH)
Metadata Filtering: Combine vector search with traditional filters

Use Cases

RAG Systems: Retrieve relevant documents for LLM context
Semantic Search: Find similar documents by meaning, not keywords
Recommendation Systems: Find similar products, content, users
Image Search: Find visually similar images
Deduplication: Identify near-duplicate content

Similarity Metrics

Choose the right distance metric for your use case.

Cosine Similarity (Recommended for Text)

MOST COMMON

Measures angle between vectors. Range: -1 (opposite) to 1 (identical).

✅ Formula & Implementation

import numpy as np

def cosine_similarity(a, b):
    """Compute cosine similarity between two vectors."""
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

# Example
vec_a = np.array([1, 2, 3])
vec_b = np.array([2, 4, 6])  # Same direction, different magnitude

similarity = cosine_similarity(vec_a, vec_b)
print(f"Cosine similarity: {similarity:.4f}")  # 1.0 (identical direction)

# Text embeddings example
query_embedding = [0.1, 0.2, ..., 0.8]      # 1536 dims
doc_embedding = [0.15, 0.25, ..., 0.75]     # 1536 dims
similarity = cosine_similarity(query_embedding, doc_embedding)

When to Use

✅ Text embeddings (OpenAI, Sentence Transformers)
✅ When direction matters more than magnitude
✅ Normalized embeddings

Euclidean Distance

SPATIAL DATA

Straight-line distance between points. Range: 0 (identical) to ∞.

✅ Implementation

def euclidean_distance(a, b):
    """Compute Euclidean distance between two vectors."""
    return np.linalg.norm(a - b)

# Example
vec_a = np.array([1, 2, 3])
vec_b = np.array([4, 5, 6])

distance = euclidean_distance(vec_a, vec_b)
print(f"Euclidean distance: {distance:.4f}")  # 5.196

When to Use

✅ Image embeddings
✅ Spatial/geographic data
✅ When magnitude matters

Dot Product

CONFIDENCE SCORES

Product of magnitudes and cosine. Range: -∞ to ∞.

✅ Implementation

def dot_product(a, b):
    """Compute dot product of two vectors."""
    return np.dot(a, b)

# Fast for similarity ranking
similarity_scores = np.dot(query_embedding, document_embeddings.T)
top_k_indices = np.argsort(similarity_scores)[::-1][:5]  # Top 5

When to Use

  • ✅ When magnitude indicates confidence
  • ✅ Fast computation (no normalization)

Vector Database Options

Pinecone (Recommended for Production)

MANAGED SERVICE

Fully managed vector database with excellent performance.

Strengths

Fully managed (no ops burden)
Fast queries (< 100ms at scale)
Auto-scaling
Metadata filtering
HNSW algorithm

✅ Python Implementation

import pinecone

# Initialize
pinecone.init(api_key="your-api-key", environment="us-west1-gcp")

# Create index
index_name = "document-embeddings"
pinecone.create_index(
    name=index_name,
    dimension=1536,  # OpenAI ada-002
    metric="cosine"
)

index = pinecone.Index(index_name)

# Upsert vectors
index.upsert(vectors=[
    ("doc1", [0.1, 0.2, ..., 0.8], {"title": "Python Guide", "category": "programming"}),
    ("doc2", [0.2, 0.3, ..., 0.7], {"title": "ML Tutorial", "category": "ai"}),
])

# Query
query_embedding = [0.15, 0.25, ..., 0.75]
results = index.query(
    vector=query_embedding,
    top_k=5,
    include_metadata=True,
    filter={"category": "programming"}  # Metadata filter
)

for match in results.matches:
    print(f"ID: {match.id}, Score: {match.score:.4f}")
    print(f"Metadata: {match.metadata}")

Weaviate

OPEN SOURCE

Open-source vector database with strong GraphQL support.

Strengths

Open source (self-host or cloud)
GraphQL API
Built-in vectorization modules
Hybrid search (vector + keyword)

✅ Python Implementation

import weaviate

client = weaviate.Client("http://localhost:8080")

# Create schema
schema = {
    "class": "Document",
    "vectorizer": "none",  # Use your own embeddings
    "properties": [
        {"name": "title", "dataType": ["text"]},
        {"name": "content", "dataType": ["text"]},
        {"name": "category", "dataType": ["text"]}
    ]
}
client.schema.create_class(schema)

# Insert documents
client.data_object.create(
    class_name="Document",
    data_object={
        "title": "Python Guide",
        "content": "Learn Python...",
        "category": "programming"
    },
    vector=[0.1, 0.2, ..., 0.8]  # Your embedding
)

# Query
result = client.query.get(
    "Document", ["title", "content"]
).with_near_vector({
    "vector": query_embedding,
    "certainty": 0.7  # Similarity threshold
}).with_where({
    "path": ["category"],
    "operator": "Equal",
    "valueText": "programming"
}).with_limit(5).do()

print(result)

ChromaDB

SIMPLEST

Lightweight, embedded vector database. Great for prototypes.

Strengths

Extremely simple API
Embedded (no server needed)
Perfect for prototypes
Persistent or in-memory

✅ Python Implementation

import chromadb

# Create client (persistent)
client = chromadb.PersistentClient(path="./chroma_data")

# Create collection
collection = client.create_collection(
    name="documents",
    metadata={"hnsw:space": "cosine"}
)

# Add documents
collection.add(
    documents=["Python is a programming language", "ML uses neural networks"],
    metadatas=[{"category": "programming"}, {"category": "ai"}],
    ids=["doc1", "doc2"]
)

# ChromaDB automatically generates embeddings or you can provide them
collection.add(
    embeddings=[[0.1, 0.2, ..., 0.8], [0.2, 0.3, ..., 0.7]],
    metadatas=[{"category": "programming"}, {"category": "ai"}],
    ids=["doc3", "doc4"]
)

# Query
results = collection.query(
    query_texts=["How to learn Python?"],
    n_results=5,
    where={"category": "programming"}
)

print(results)

When to Use

✅ Prototypes and POCs

✅ Local development

Qdrant

HIGH PERFORMANCE

Rust-based vector database with excellent performance.

Strengths

Written in Rust (fast)
Rich filtering
Payload storage
Self-host or cloud

✅ Python Implementation

from qdrant_client import QdrantClient
from qdrant_client.models import Distance, VectorParams, PointStruct

client = QdrantClient("localhost", port=6333)

# Create collection
client.create_collection(
    collection_name="documents",
    vectors_config=VectorParams(size=1536, distance=Distance.COSINE),
)

# Insert vectors
client.upsert(
    collection_name="documents",
    points=[
        PointStruct(
            id=1,
            vector=[0.1, 0.2, ..., 0.8],
            payload={"title": "Python Guide", "category": "programming"}
        ),
        PointStruct(
            id=2,
            vector=[0.2, 0.3, ..., 0.7],
            payload={"title": "ML Tutorial", "category": "ai"}
        ),
    ]
)

# Query
search_result = client.search(
    collection_name="documents",
    query_vector=query_embedding,
    limit=5,
    query_filter={
        "must": [
            {"key": "category", "match": {"value": "programming"}}
        ]
    }
)

for hit in search_result:
    print(f"Score: {hit.score:.4f}, Payload: {hit.payload}")

Implementation Patterns

Batch Upsert for Performance

HIGH PRIORITY

Insert vectors in batches for 10x+ speedup.

✅ Batch Insert

def upsert_documents_batch(documents, embeddings, batch_size=100):
    """Upsert documents in batches for better performance."""
    for i in range(0, len(documents), batch_size):
        batch_docs = documents[i:i + batch_size]
        batch_embeddings = embeddings[i:i + batch_size]
        
        vectors = [
            (f"doc_{i+j}", emb, {"text": doc})
            for j, (doc, emb) in enumerate(zip(batch_docs, batch_embeddings))
        ]
        
        index.upsert(vectors=vectors)
        print(f"Upserted batch {i//batch_size + 1}")

# Usage
documents = ["doc1", "doc2", ..., "doc10000"]  # 10K documents
embeddings = get_embeddings_batch(documents)   # Get embeddings
upsert_documents_batch(documents, embeddings, batch_size=100)
# 100 upserts instead of 10,000!

HIGH PRIORITY

Combine vector similarity with metadata filters for precise results.

# Search with metadata filters
results = index.query(
    vector=query_embedding,
    top_k=10,
    filter={
        "category": {"$eq": "programming"},
        "year": {"$gte": 2020},
        "author": {"$in": ["John", "Jane"]}
    }
)

# Only returns documents matching both:
# 1. Vector similarity to query
# 2. All metadata filter conditions

Index Tuning

MEDIUM PRIORITY

Adjust index parameters for accuracy vs speed tradeoff.

HNSW Parameters

# HNSW parameters
index_config = {
    "m": 16,           # Number of connections per layer (default: 16)
                       # Higher = more accurate, slower build, more memory
                       # Typical range: 8-64
    
    "ef_construction": 200,  # Size of dynamic candidate list (default: 200)
                             # Higher = more accurate index, slower build
                             # Typical range: 100-500
    
    "ef_search": 100,  # Search quality (query time parameter)
                       # Higher = more accurate search, slower queries
                       # Typical range: 50-500
}

# Recommendations:
# - Fast search: m=8, ef_construction=100, ef_search=50
# - Balanced: m=16, ef_construction=200, ef_search=100 (default)
# - High accuracy: m=32, ef_construction=400, ef_search=200

Query Optimization

MEDIUM PRIORITY

Optimize queries for production latency requirements.

Best Practices

Batch Queries: Query multiple vectors at once
