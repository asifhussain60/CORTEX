📦 Container Technology

Docker, Kubernetes, and Container Orchestration

🐳 Docker ☸️ Kubernetes 📅 Updated: Dec 2025

📋 Overview

Containers package applications with their dependencies into isolated, portable units that run consistently across environments. Container orchestration platforms like Kubernetes automate deployment, scaling, and management of containerized applications at scale.

Container Benefits:
  • Portability: Run anywhere - dev, test, production
  • Efficiency: Lightweight compared to VMs
  • Consistency: Eliminate "works on my machine" issues
  • Scalability: Quick startup and horizontal scaling

🐳 Docker Fundamentals

Core Concepts

📄

Images

Characteristics

  • Read-only templates
  • Layered file system
  • Built from Dockerfile
  • Stored in registries

Best Practices

  • Use official base images
  • Multi-stage builds
  • Minimize layers
  • Tag properly
📦

Containers

Characteristics

  • Running instance of image
  • Isolated process
  • Ephemeral by default
  • Lightweight and fast

Lifecycle

  • Create, Start, Stop
  • Restart, Pause, Unpause
  • Remove
🗂️

Volumes

Purpose

  • Persistent data storage
  • Share data between containers
  • Decouple data from container
  • Backup and migration

Types

  • Named volumes
  • Bind mounts
  • tmpfs mounts

Dockerfile Best Practices

🏗️

Multi-Stage Builds

Benefits

  • Smaller final images
  • Separate build/runtime deps
  • Better security
  • Reduced attack surface
⚡

Layer Optimization

Techniques

  • Order commands by change frequency
  • Combine RUN commands
  • Use .dockerignore
  • Clean up in same layer
🔒

Security

Practices

  • Run as non-root user
  • Scan for vulnerabilities
  • Use specific versions
  • Minimal base images

🔧 Kubernetes Objects

Workload Resources

📦

Pods

Characteristics

  • Smallest deployable unit
  • One or more containers
  • Shared network namespace
  • Ephemeral by nature
🔄

Deployments

Features

  • Declarative updates
  • Rolling updates
  • Rollback capability
  • Replica management
⚙️

StatefulSets

Use Cases

  • Stable network identities
  • Ordered deployment/scaling
  • Persistent storage
  • Databases, queues

Service Discovery

🌐

Services

Stable Network Endpoints

Types

  • ClusterIP: Internal only (default)
  • NodePort: Expose on node port
  • LoadBalancer: Cloud load balancer
  • ExternalName: DNS CNAME
🚪

Ingress

HTTP/HTTPS Routing

Features

  • Host-based routing
  • Path-based routing
  • TLS termination
  • Load balancing
📝

ConfigMaps & Secrets

Configuration Management

Purpose

  • Decouple config from code
  • Environment variables
  • Volume mounts
  • Secrets: base64 encoded

🎯 Orchestration Patterns

Scaling Strategies

📈

Horizontal Pod Autoscaler

Metrics

  • CPU utilization
  • Memory usage
  • Custom metrics
  • External metrics
⬆️

Vertical Pod Autoscaler

Purpose

  • Adjust resource requests
  • Right-size containers
  • Optimize resource usage
  • Reduce waste
🖥️

Cluster Autoscaler

Behavior

  • Add nodes when needed
  • Remove underutilized nodes
  • Cloud provider integration
  • Cost optimization

Health Checks

Probe Type Purpose Action on Failure
Liveness Is container running? Restart container
Readiness Can container accept traffic? Remove from service endpoints
Startup Has application started? Delay liveness checks
Kubernetes Best Practices:
  • Resource Limits: Set CPU/memory requests and limits
  • Health Probes: Always define liveness and readiness
  • Labels: Use consistent labeling strategy
  • Namespaces: Organize resources logically
  • RBAC: Implement least privilege access
  • NetworkPolicies: Control pod-to-pod communication
