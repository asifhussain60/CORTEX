Planning System

Imagine planning a complex feature in minutes instead of hours, with every acceptance criterion, test case, and implementation step automatically mapped out for you. The Planning System transforms vague feature requests into crystal-clear, executable plans—validating your requirements are complete before you write a single line of code, and automatically detecting whether your feature needs an incremental multi-phase approach or a quick skeleton implementation. It's like having an experienced architect review your plan before you commit to building.

📋 The 5-Phase Workflow

1 📋
Requirements Analysis

Parse feature request, identify stakeholders, extract acceptance criteria

2 🔍
Complexity Assessment

AUTO: HIGH→incremental, MEDIUM→conditional, LOW→skeleton

3 🏗️
Architecture Design

Component breakdown, dependencies, integration points

4 ✅
TDD Test Planning

Test cases per component, coverage targets, RED tests first

5 📄
Plan Generation

YAML/Markdown output with all phases, DoR/DoD gates

✅ DoR/DoD Compliance

📥
Definition of Ready (DoR)
Before planning begins
  • Feature description provided
  • Stakeholders identified
  • Acceptance criteria clear
  • Dependencies documented
📤
Definition of Done (DoD)
After plan completion
  • All phases documented
  • Test cases generated
  • Architecture validated
  • Plan exportable (YAML/MD)

🎚️ Auto-Complexity Detection

The Planning System automatically assesses feature complexity and adjusts the planning approach:

Complexity Detection Criteria Planning Approach
HIGH Multiple components, external integrations, >5 acceptance criteria Incremental multi-phase with gates
MEDIUM 2-3 components, internal dependencies, 3-5 criteria Conditional phases, focused tests
LOW Single component, no dependencies, 1-2 criteria Skeleton implementation, basic tests

📊 Example Plan Output

YAML 
feature:
  name: "User Authentication with OAuth2"
  complexity: HIGH
  phases: 5

phases:
  - id: 1
    name: "OAuth2 Provider Setup"
    tests:
      - "test_oauth_config_loads"
      - "test_provider_url_validation"
    acceptance:
      - "Provider credentials configured"
      - "Redirect URLs registered"
      
  - id: 2
    name: "Token Exchange Flow"
    tests:
      - "test_authorization_code_exchange"
      - "test_token_refresh"
    acceptance:
      - "Access token obtained"
      - "Refresh token stored securely"

dor_validated: true
dod_criteria: 8
tdd_coverage: 100%
