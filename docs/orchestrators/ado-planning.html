🧠 Planning System Integration

4-Tier Classification: Maps plan complexity to ADO work item hierarchy
DoR Validation: Ensures all work items meet Definition of Ready criteria
DoD Mapping: Converts Definition of Done to ADO acceptance criteria
Historical Context: Uses past patterns to improve work item estimates
TDD Integration: Links test requirements to ADO task definitions
Visual Progress: Real-time progress bars with work item metrics

🎯 Work Item Type Mapping

Epics (Tier 4)

Source: TIER 4 (COMPLEX) planning manifests

Attributes:

  • Title: Plan name with feature prefix
  • Description: Executive summary from manifest
  • Story Points: Aggregated from all child features
  • Tags: complexity-tier-4, category tags from manifest
  • State: New → Active based on plan phase

Features (Tier 3)

Source: TIER 3 (MODERATE) manifests or Tier 4 sub-features

Attributes:

  • Title: Feature name from manifest phase
  • Description: Phase objectives and deliverables
  • Acceptance Criteria: Mapped from phase DoD
  • Story Points: Sum of child user stories
  • Parent Link: Epic (if Tier 4 plan)

User Stories (Tier 2)

Source: TIER 2 (SIMPLE) manifests or Tier 3/4 tasks

Attributes:

  • Title: User story format: "As a [role], I want [goal]"
  • Description: Detailed requirements from manifest tasks
  • Acceptance Criteria: Checklist from DoD items
  • Story Points: Fibonacci scale (1/2/3/5/8/13)
  • Parent Link: Feature (if Tier 3/4 plan)

Tasks (All Tiers)

Source: Implementation subtasks from manifest

Attributes:

  • Title: Technical task description
  • Description: Implementation details, file paths
  • Remaining Work: Hours estimate from manifest
  • Activity: Development/Testing/Documentation
  • Parent Link: User Story
