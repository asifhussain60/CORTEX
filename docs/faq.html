What is CORTEX and who is it for?

How do I install CORTEX?

▼

CORTEX works within GitHub Copilot Chat. Setup is simple:

  1. Clone the repository: git clone https://github.com/asifhussain60/CORTEX.git
  2. Install dependencies: pip install -r requirements.txt
  3. Configure paths: Edit cortex.config.json with your machine-specific paths
  4. Say "help" in Copilot Chat to see available operations

Requirements: Python 3.8+, GitHub Copilot subscription

What's the difference between CORTEX and plain Copilot?

▼

Key differences:

Memory: GitHub Copilot has no persistence; CORTEX has 70-conversation FIFO working memory
Planning: Copilot provides single-turn suggestions; CORTEX creates multi-phase strategic plans
TDD: Copilot requires manual RED-GREEN-REFACTOR; CORTEX enforces TDD workflow
Architecture: Copilot has no context preservation; CORTEX uses knowledge graph + dev context
Safety: Copilot can suggest unsafe code; CORTEX has SKULL brain protection

🛡️ Governance & Safety

How does CORTEX prevent bad code suggestions?

▼

SKULL brain protection enforces safety rules at Tier 0:

TDD Enforcement: Tests must fail before implementation
Code Discovery: Search before creating (prevent duplication)
Cleanup Enforcement: Remove orphaned code during refactor

Is my data secure?

▼

Yes! All CORTEX data stays local:

No cloud uploads: Brain data stored on your machine
Git isolation: CORTEX never commits to user repos
Sanitization: Clean sensitive data before sharing
Local execution: Python commands run locally

How does Git isolation work?

▼

SKULL GIT_ISOLATION_ENFORCEMENT prevents mixing codebases:

CORTEX tests: Always in CORTEX/tests/
User app tests: Always in UserApp/tests/
Pre-commit validation: Blocks cross-contamination
Workspace detection: Auto-detects correct context

Can CORTEX delete my code?

▼

No! CORTEX has multiple safety mechanisms:

Git Checkpoints: Auto-commits before major operations
Rollback Support: Undo changes with rollback command
Dry-Run Mode: Preview changes before applying
User Confirmation: Destructive operations require approval

What are DoR and DoD requirements?

🔧 Troubleshooting

CORTEX doesn't recognize my commands

▼

Solution:

  1. Verify CORTEX is in your workspace (check .github/prompts/CORTEX.prompt.md)
  2. Say help to see available commands
  3. Check cortex.config.json paths are correct
  4. Run system maintenance to align system

Tests are failing after CORTEX changes

▼

TDD workflow ensures this shouldn't happen, but if it does:

  1. Run rollback to undo recent changes
  2. Check git history for last checkpoint
  3. Review test failures with start tdd
  4. Ensure RED phase was completed before GREEN phase

Working memory seems slow or corrupted

▼

Solution:

  1. Run system maintenance to optimize brain
  2. Check cortex-brain/conversation-context.jsonl size (should be < 10MB)
  3. Manual cleanup: Remove old conversations from JSONL file
  4. Rebuild indexes with optimize

Python import errors

▼

Solution:

# Reinstall dependencies
pip install -r requirements.txt

# Check Python version (3.8+ required)
python --version

# Run healthcheck
system maintenance

How do I reset CORTEX to default state?

▼

Full reset:

  1. Backup important data from cortex-brain/
  2. Delete cortex-brain/conversation-context.jsonl
  3. Delete cortex-brain/knowledge-graph.yaml
  4. Delete cortex-brain/development-context.yaml
  5. Run system maintenance to reinitialize

Warning: This loses all working memory and learned patterns.

What is TDD enforcement?

▼

SKULL TDD_ENFORCEMENT ensures test-driven development:

RED Phase: Write failing tests first (validated by CORTEX)
GREEN Phase: Implement minimum code to pass
REFACTOR Phase: Clean up with all tests passing
Validation: Each phase must complete before next
