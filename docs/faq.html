🚀 Getting Started

CORTEX is an AI-powered development assistant that enhances GitHub Copilot with long-term memory, strategic planning, and architectural intelligence. It's designed for:

  • Software Engineers - TDD workflows, code quality, automated testing
  • Tech Leads - Architecture reviews, planning systems, team coordination
  • Product Managers - ADO integration, progress tracking, feature planning

Learn more about CORTEX →

CORTEX works within GitHub Copilot Chat. Setup is simple:

  1. Clone the repository: git clone https://github.com/asifhussain60/CORTEX.git
  2. Install dependencies: pip install -r requirements.txt
  3. Configure paths: Edit cortex.config.json with your machine-specific paths
  4. Say "help" in Copilot Chat to see available operations

Requirements: Python 3.8+, GitHub Copilot subscription

🏗️ Architecture & Design

CORTEX organizes intelligence into 4 hierarchical tiers:

  • Tier 0: Governance - SKULL rules, brain protection, safety enforcement
  • Tier 1: Working Memory - 70-conversation FIFO queue, SQLite persistence
  • Tier 2: Knowledge Graph - Pattern learning, relationship modeling
  • Tier 3: Development Context - Metrics, hotspots, codebase intelligence

Explore Four-Tier Brain →

SKULL = Safety, Knowledge, Usability, Logic, Learning

Brain Protection rules that prevent common AI failures:

  • TDD_ENFORCEMENT: RED→GREEN→REFACTOR mandatory
  • RED_PHASE_VALIDATION: Tests must fail before implementation
  • HOLISTIC_CODE_DISCOVERY: Search before create (prevent duplication)
  • REFACTOR_CODE_CLEANUP: Remove orphaned code
  • GIT_ISOLATION: CORTEX code never in user repos

Learn about SKULL →

Tier 1 solves Copilot's "goldfish memory" with a 70-conversation FIFO queue:

  • SQLite persistence: Conversations survive restarts
  • FIFO eviction: Oldest conversations pruned automatically
  • Sub-100ms retrieval: Fast context loading
  • JSON-based capture: Full conversation history

Why 70? Balances context richness with performance (<100ms retrieval).

Say start tdd to begin enforced RED-GREEN-REFACTOR cycle:

  1. RED: Write failing test (CORTEX validates it fails)
  2. GREEN: Implement minimum code to pass
  3. REFACTOR: Clean up with tests passing

Safety features:

  • Empty test detection (rejects placeholder tests)
  • Per-layer coverage validation
  • Debugging orchestrator integration

⚙️ Operations & Best Practices

Standard workflow for feature development:

  1. Plan: plan [feature] - Get strategic plan
  2. TDD: start tdd - Begin RED-GREEN-REFACTOR
  3. Implement: Follow incremental phases
  4. Review: review - Architectural validation
  5. Maintain: system maintenance - Cleanup & optimize

Weekly ritual: System maintenance on Fridays

CORTEX follows strict TDD and Brain Protection rules:

  1. Fork & branch: Create feature branch from main
  2. TDD required: All code must have tests (RED-GREEN-REFACTOR)
  3. SKULL compliance: Pass brain protection validation
  4. Documentation: Update relevant docs in cortex-brain/documents/
  5. PR template: Use provided template with test evidence
