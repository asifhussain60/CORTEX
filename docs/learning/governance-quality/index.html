9 Governance Concepts

01

60+ YAML Rules

26 core + 34 governance rules defined in cortex-registry/. Each specifies ID, severity, description, and check trigger.

02

Priority System

P0 = hard-stop (blocks everything), P1 = must-fix before merge, P2 = advisory. Severity drives convergence loop behaviour.

03

EnforcementOrchestrator

The runtime compliance engine — validates every orchestrator invocation against active rules before AC_COMPLETE fires.

04

CORE-048 — Holistic Gate

Mandatory pre-execution validation for every IMPLEMENT, FIX, and REFACTOR. No code-modifying operation starts without this gate.

05

CORE-064 — Sweep Completeness

Every FIX, REFACTOR, and AUDIT must exhaust its full issue catalogue. No partial sweeps — the sweep catalogue must close clean.

06

CORE-068 — Convergence Gate

Detect → fix → rescan until zero P0/P1 violations (max 3 cycles). Not a single pass — guaranteed convergence before completion.

07

AC Markers

AC_START at entry, AC_COMPLETE on exit. Every orchestrator invocation is tracked. No orphaned starts — a P0 violation.

08

Meta-Audit Pipeline

CORTEX audits itself — 23+ automated checks verify the governance system's own integrity, including prompt drift and SQLite health.

09

7 SQLite Databases

Traces, RCA, audit, governance, conversations, wiring, intelligence — all activity is recorded, auditable, and has 30-day retention with VACUUM.
