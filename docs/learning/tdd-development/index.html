The TDD Cycle

Red → Green → Refactor

Write a failing test (red), make it pass with minimal code (green), then improve the design (refactor). Repeat until done.

🔴
RED

Write a failing test that describes the desired behaviour

🟢
GREEN

♻️
REFACTOR

Improve code design while keeping all tests green

5 TDD Concepts

01

CORE-008 — TDD Mandatory

Write a failing test first, then implement. No exceptions. The TDDOrchestrator enforces this for every IMPLEMENT and FIX intent.

02

TDDOrchestrator

The orchestrator that drives test-first workflows — generates test stubs, runs them to confirm red, guides implementation to green.

03

Test Quality Scoring

Tests are scored on coverage, isolation, determinism, and speed. The quality gate prevents merging if scores drop below threshold.

04

Golden Test Promotion

High-scoring tests are promoted to "golden" status — they become regression anchors that are never skipped or weakened.

05

3-Layer Acceleration

Layer 1: pytest-xdist (parallel, 3–4× faster). Layer 2: pytest-testmon (smart, only changed). Layer 3: --import-mode=importlib (cuts cold collection 17s → 7s).
