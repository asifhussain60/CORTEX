## 🚨 Problem Summary

### Initial Symptom
```
ERROR while calling tool: Tool mcp_cortex_cortex_process_request is currently disabled by the user, and cannot be called.
```

### Root Cause Analysis

**Misunderstanding of Tool Naming Convention:**
- ❌ **Incorrect:** Attempted to call `mcp_cortex_cortex_process_request`
- ✅ **Correct:** Tool name is `cortex_process_request` (no `mcp_cortex_` prefix in VS Code)

**Context:**
- The VS Code Copilot Chat exposes MCP tools WITHOUT the `mcp_cortex_` prefix
- The prefix is only used internally in Python decorators (`@mcp_tool`)
- User-facing tool names follow the pattern: `cortex_{operation}`

## ✅ Solution Implemented

### Fix 1: Use Correct Tool Names
```python
# BEFORE (incorrect)
mcp_cortex_cortex_process_request(operation="refactor", ...)

# AFTER (correct)
cortex_process_request(operation="refactor", ...)
cortex_refactor(operation="analyze", ...)
```

### Fix 2: Fallback Strategy
When MCP tools temporarily unavailable:
1. Check MCP availability via `cortex_tools_catalog`
2. If unavailable for IMPLEMENT/FIX/REFACTOR → BLOCK with fix instructions
3. If ANALYZE intent → Allow read-only native tools

### Fix 3: Documentation Update
Updated `.github/copilot-instructions.md` to clarify:
- Tool naming convention (no `mcp_cortex_` prefix in chat)
- MCP-FIRST enforcement (mandatory for IMPLEMENT/FIX/REFACTOR)
- Correct tool catalog usage

## 🎯 Key Learnings

### For AI Agents
1. **Tool Discovery First:** Always query `cortex_tools_catalog` before assuming tool names
2. **No Prefix in Chat:** MCP tools exposed to VS Code Copilot Chat use simple names (`cortex_*`)
3. **Prefix in Code:** Python decorators use `@mcp_tool(name="mcp_cortex_*")` internally
4. **MCP-FIRST Policy:** IMPLEMENT/FIX/REFACTOR intents MUST use MCP tools

### For Developers
1. **VS Code Configuration:** MCP server auto-starts when tools invoked (no manual startup)
2. **Tool Availability:** Check "Configure Tools" dialog to verify MCP server enabled
3. **Cross-Platform:** Uses `${workspaceFolder}` for portability (macOS/Windows/Linux)
4. **Debugging:** Use `.cortex/diagnose-mcp.py` for troubleshooting

## 🔄 MCP Architecture (Reference)

### How It Works
```
User Request
    ↓
VS Code Copilot Chat
    ↓
IntentRouter (classify: IMPLEMENT | FIX | REFACTOR | ANALYZE)
    ↓
MCP Gateway (tool invocation)
    ↓
MCP Server (stdio, JSON-RPC 2.0)
    ↓
TDDOrchestrator / LENSSynthesis / RefactoringOrchestrator
    ↓
Action (RED → GREEN → REFACTOR)
```

### MCP Server Startup
```json
// .vscode/settings.json (auto-generated by setup-mcp.py)
{
  "github.copilot.chat.mcpServers": {
    "cortex": {
      "command": "${workspaceFolder}/.venv/bin/python",
      "args": ["-m", "cortex.mcp"],
      "env": {
        "CORTEX_ENV": "development",
        "CORTEX_MCP_ENABLED": "true",
        "PYTHONPATH": "${workspaceFolder}"
      }
    }
  }
}
```

**Key:** VS Code auto-starts MCP server when Copilot invokes `cortex_*` tools. No manual `python -m cortex.mcp.server` required.
