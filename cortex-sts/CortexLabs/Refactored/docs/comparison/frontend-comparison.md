## API Call Pattern — Before vs After

### Before: Direct fetch() — No Error Handling

```mermaid
sequenceDiagram
    participant UI as app.ts (God Component)
    participant API as Backend API

    UI->>API: fetch(`${API_URL}/transactions`)
    Note over UI: ❌ No try/catch<br/>❌ No retry<br/>❌ No error display<br/>❌ No loading state
    API-->>UI: Response (or network error → silent crash)
    Note over UI: transactions = await response.json()<br/>❌ Type = any<br/>❌ No null check<br/>❌ Direct DOM mutation
```

### After: Typed ApiClient — Retry + Error Handling

```mermaid
sequenceDiagram
    participant UI as app.ts (thin)
    participant SVC as TransactionService
    participant CLI as ApiClient
    participant API as Backend API

    UI->>SVC: transactionService.getAll()
    SVC->>CLI: client.get<ApiResponse<Transaction>>(...)
    CLI->>API: fetch() with headers + typed response

    alt Success
        API-->>CLI: 200 + JSON
        CLI-->>SVC: ApiResponse<Transaction>
        SVC-->>UI: Typed paginated result
        Note over UI: renderTransactions(items)<br/>✅ escapeHtml() for XSS<br/>✅ formatCurrency() for display
    else Network Error (retry)
        API--xCLI: Connection refused
        Note over CLI: Attempt 1 failed<br/>Wait 500ms (exponential backoff)
        CLI->>API: Retry attempt 2
        API-->>CLI: 200 + JSON
        CLI-->>SVC: Success on retry
    else API Error
        API-->>CLI: 400/500 + ProblemDetails
        CLI-->>SVC: throw ApiRequestError
        SVC-->>UI: catch → showError(message)
        Note over UI: ✅ Error banner shown for 5s<br/>✅ No silent failure
    end
```
