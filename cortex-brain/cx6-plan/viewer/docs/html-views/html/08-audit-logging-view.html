Audit Pipeline

How logging integrates with orchestrator pipeline

sequenceDiagram
    participant R as Request
    participant L as LoggingBehavior
    participant N as NextBehavior
    participant O as Orchestrator
    participant DB as Audit DB
    
    R->>L: Enter pipeline
    L->>L: Log request
    L->>L: Assign correlation_id
    L->>N: Delegate to next behavior
    N->>O: Execute
    O->>N: Return result
    N->>L: Return response
    L->>L: Redact sensitive data
    L->>L: Log response + timing
    L->>DB: Persist to audit log
    L->>R: Return to caller
    
    Note over L,DB: Correlation ID: CX-2026-01-12-0847-abc123def

Audit Query Examples

Common audit trail queries and use cases

Find All Failures for AC-ID
audit query --ac-id AC-AUDIT-001 --level ERROR

Output

  • 2026-01-10 14:32: Test failure (pytest)
  • 2026-01-09 09:15: Schema validation failed
Trace Execution of Request
audit query --correlation-id CX-2026-01-12-0847-abc123def

Output

  • 14:32:01 - Request received
  • 14:32:02 - SKULL validation
  • 14:32:15 - Planning started
  • 14:33:45 - Planning complete
Check Governance Violations
audit query --category GOVERNANCE --level WARNING

Output

  • 2026-01-11 16:40: CORE-008 warning (low coverage)
  • 2026-01-10 11:23: CORE-019 blocked (TDD bypass)
Monitor Performance
audit query --category PERFORMANCE --last 24h

Output

  • Slow phase: Planning took 45s (>30s threshold)
  • Fast phase: TDD RED took 8s
