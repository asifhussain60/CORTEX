How 4-tier precedence system enforces immutable rules while allowing business flexibility

Conflict Resolution Algorithm

GovernanceMerger Process

1 Load All Tiers

Read rules from all 4 tiers (Tier 0 SKULL rules, Tier 1 business rules, Tier 2 practices, Tier 3 patterns)

2 Detect Conflicts

Identify contradictions where different tiers define conflicting rules (e.g., "TDD required" vs "skip tests for speed")

3 Apply Precedence

Tier 0 > Tier 1 > Tier 2 > Tier 3 (higher tier always wins)

4 Create Unified Instruction Set

Merge non-conflicting rules and apply conflict resolutions into single authoritative ruleset

5 Cache & Distribute

Cache merged rules in memory and pass to all orchestrators for enforcement

Conflict Resolution Examples

Example 1: TDD Conflict
❌ Conflict Scenario

Tier 0 (SKULL):
"CORE-008: TDD Enforcement required for all code"

Tier 3 (Knowledge):
"Performance optimization: Skip tests for utility functions to save cycles"
✅ Resolution (Tier 0 Wins)

Applied Rule:
"TDD Enforcement required (CORE-008)"

Outcome:
All code must pass RED→GREEN→REFACTOR, even utility functions. Tier 3 optimization cannot override Tier 0 protection.

Merge Strategy: Hybrid Approach

Category-Specific Merging
🔴 Tier 0 Rules (Immutable)
Always included. Cannot be modified by lower tiers. Conflicts always won by Tier 0.
🟣 Tier 1 Rules (Business)
Added if they don't conflict with Tier 0. If conflict detected, Tier 0 wins. Tier 1 rules can override Tier 2 & 3.
🔵 Tier 2 Rules (Engineering)
Added if they don't conflict with Tier 0 or Tier 1. Tier 2 can override Tier 3 only.
🟢 Tier 3 Rules (Knowledge)
Added last. Lowest precedence. Only included if no conflicts with higher tiers.

Enforcement Mechanisms

Blocking Enforcement

Operations that violate Tier 0 rules are immediately blocked:

CORE-001 Violation
CORE-008 Violation
CORE-017 Violation

Request rejected, logged as CRITICAL, requires manual intervention

Warning Enforcement

Operations that violate Tier 2/3 rules trigger warnings but proceed:

Code Style Warning
Documentation Gap
Performance Alert

Request continues, logged as WARNING, stakeholders notified

Real-World Scenario

Implementing "AC-AUDIT-001" with Competing Requirements
Request: "Implement AC-AUDIT-001 (Queryable Audit Storage) quickly to meet 3-day deadline"

Tier 1 (Business) Says: "Implement in 1 day, no time for testing"
Tier 0 (SKULL) Says: "CORE-008: TDD Enforcement - must have tests"
Tier 2 (Engineering) Says: "Follow code style guidelines (80-char lines)"
Tier 3 (Knowledge) Says: "Use SQLite for state persistence (learned pattern)"

↓ GOVERNANCE MERGE ↓

Resolution:
• TDD Required (Tier 0 blocks skipping tests)
• 1-day deadline may slip (business requirement vs Tier 0 constraint creates realistic timeline)
• 80-char lines enforced (Tier 2, no conflict)
• SQLite approved (Tier 3, no conflict)

Implementation Plan:
• RED phase: Write failing tests (1-2 hours)
• GREEN phase: Implement QueryableAudit class with SQLite (3-4 hours)
• REFACTOR phase: Optimize, add edge cases (1-2 hours)
Realistic Timeline: 5-8 hours (not 1 day)
Outcome: Tier 0 TDD enforcement wins; business deadline adjusted
