Orchestration Lifecycle

7-state machine, middleware pipeline, and correlation ID tracing for autonomous orchestrator execution

7-State Lifecycle State Machine

Every orchestrator transitions through these states, with explicit methods triggering transitions. Quarantine mechanism contains failures.

1 INIT
Orchestrator created but not yet started. Configuration loaded, dependencies verified.
start_phase() → PLANNING
Entry Hook: pre_init
Exit Hook: post_init
2 PLANNING
Breaking down AC-ID into tasks, creating execution plan, estimating resource requirements.
start_execution() → EXECUTING
Entry Hook: pre_planning
Exit Hook: post_planning
3 EXECUTING
Running tasks in dependency order. TDD cycles (RED→GREEN→REFACTOR) executed here. All operations logged to audit trail.
finish_execution() → VALIDATING
error() → FAILED
Entry Hook: pre_executing
Exit Hook: post_executing
4 VALIDATING
Running tests, verifying evidence bundles, checking acceptance criteria met. If validation fails, transitions to FAILED with details.
validation_passed() → REPORTING
validation_failed() → FAILED
Entry Hook: pre_validating
Exit Hook: post_validating
5 REPORTING
Generating evidence bundles, audit summaries, test coverage reports. Results prepared for stakeholder consumption.
complete() → COMPLETE
Entry Hook: pre_reporting
Exit Hook: post_reporting
✓ COMPLETE
Success! AC-ID fully implemented, tested, validated, and documented. Evidence bundle archived.
Final state
Entry Hook: pre_complete
Exit Hook: post_complete
✗ FAILED
Error or validation failure. Orchestrator entered QUARANTINE (see Quarantine Mechanism). Manual intervention required.
Requires restart or fix
Entry Hook: pre_failed
Exit Hook: post_failed

Middleware Pipeline (5 Layers)

Every orchestrator request flows through these middleware layers for logging, validation, transformation, security, and response formatting.

Layer 1 Request Logging
Logs all incoming requests with correlation ID, timestamp, source. Initializes audit trail.
↓
Layer 2 Governance Validation
Checks request against merged governance rules. Blocks SKULL rule violations immediately. Logs all validations.
↓
Layer 3 Request Transformation
Enriches request with domain context, dependencies, AC-ID metadata. Transforms intent into structured instruction.
↓
Layer 4 Security & Access Control
Validates user permissions, checks resource access, prevents path traversal, detects injection attacks.
↓
Layer 5 Response Formatting
Formats response according to 3-layer template architecture. Ensures consistency. Attaches evidence bundles.

Correlation ID Tracing

Every request gets a unique correlation ID that flows through all middleware layers and is logged at each step for complete traceability.

Find all audit entries for a specific request:

logger = EnterpriseAuditLogger()
trace = logger.query(
  correlation_id="CORTEX-2026-01-11-15h45m30s-ABC123",
  last=None
)

# Returns: 12 audit entries for this request, in chronological order

Quarantine Mechanism (Error Containment)

When an orchestrator fails, it enters QUARANTINE state. The orchestrator is isolated, failure logged, and manual intervention triggered.

Quarantine Entry

Triggered when:

  • Tests fail 3 times (RED phase)
  • Code quality metrics below threshold
  • Evidence bundle validation fails
  • Unhandled exception in orchestrator
  • Timeout exceeded (>1 hour)

Orchestrator STOPS all execution immediately

Manual Recovery

Engineers must:

  • Review quarantine details in audit log
  • Fix underlying issue (code, tests, environment)
  • Re-run orchestrator with same AC-ID
  • Monitor RED→GREEN→REFACTOR progress

All failures documented for learning
