## Execution Method Decision Matrix

| Operation Type | Characteristics | Execution Method | Example Operations |
|---------------|-----------------|------------------|-------------------|
| **System Operations** | File I/O, Git, System state changes | `cli_wrapper` | align, optimize, cleanup |
| **Interactive Workflows** | Multi-turn, User guidance, Planning | `copilot_chat` | planning, ado, tdd |
| **Infrastructure** | Called by other components, Not user-facing | `internal` | Orchestrators, agents |

## CLI Wrapper Invocation Path

```
User: "align"
    │
    ▼
unified_entry_point_utility.py
    │
    ├─ Match "align" → align_system operation
    ├─ execution_method: "cli_wrapper"
    ├─ cli_script: "scripts/cli_wrappers/align_wrapper.py"
    │
    ▼
invoke_cli_wrapper()
    │
    ├─ Construct command: python3 scripts/cli_wrappers/align_wrapper.py
    ├─ Execute subprocess
    ├─ Capture stdout/stderr
    │
    ▼
align_wrapper.py
    │
    ├─ Load CORTEX configuration
    ├─ Initialize AlignmentUtility
    ├─ Run alignment checks
    ├─ Generate fixes
    ├─ Apply changes to files
    ├─ Return results
    │
    ▼
Return to Copilot Chat (formatted output)
```

## Copilot Chat Flow

```
User: "plan feature X"
    │
    ▼
unified_entry_point_utility.py
    │
    ├─ Match "plan" → feature_planning operation
    ├─ execution_method: "copilot_chat"
    │
    ▼
route_operation() returns metadata
    │
    ├─ operation: "feature_planning"
    ├─ orchestrator: "PlanningOrchestrator"
    ├─ phases: [analyze, design, implement, test, document]
    │
    ▼
Copilot Chat Interface
    │
    ├─ Engage PlanningOrchestrator
    ├─ Multi-turn conversation
    ├─ Gather requirements
    ├─ Generate implementation plan
    ├─ Guide user through phases
    │
    ▼
Interactive completion
```

## Internal Operation Rejection

```
User: "run MaintenanceOrchestrator"
    │
    ▼
unified_entry_point_utility.py
    │
    ├─ Match → maintenance_orchestrator operation
    ├─ execution_method: "internal"
    │
    ▼
route_operation() rejects
    │
    └─ Return error: "This is an internal component. Use 'system maintenance' instead."
```

## Implementation Files

### Core Router
- **File:** `src/operations/utilities/unified_entry_point_utility.py`
- **Functions:**
  - `route_operation(user_request: str) -> dict`
  - `invoke_cli_wrapper(operation: dict) -> dict`
  - `get_copilot_chat_metadata(operation: dict) -> dict`

### CLI Wrappers (8 scripts)
- `scripts/cli_wrappers/align_wrapper.py`
- `scripts/cli_wrappers/healthcheck_wrapper.py`
- `scripts/cli_wrappers/optimize_wrapper.py`
- `scripts/cli_wrappers/cleanup_wrapper.py`
- `scripts/cli_wrappers/review_wrapper.py`
- `scripts/cli_wrappers/deploy_wrapper.py`
- `scripts/cli_wrappers/regenerate_prompts_wrapper.py`
- `scripts/cli_wrappers/upgrade_wrapper.py`

### Registry
- **File:** `cortex-operations.yaml`
- **Fields per operation:**
  - `execution_method`: cli_wrapper | copilot_chat | internal
  - `cli_script`: (optional) Path to wrapper script
  - `orchestrator`: (optional) Orchestrator class name

---

## Key Benefits

1. **Clear Separation:** System ops vs interactive workflows vs infrastructure
2. **Consistent Invocation:** All operations routed through single entry point
3. **Extensibility:** Easy to add new operations/wrappers
4. **User Safety:** Internal operations protected from direct invocation
