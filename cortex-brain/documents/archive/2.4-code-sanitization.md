## Transformation Rules (Phase 2)

Example mapping structure:

```yaml
# sanitization_mapping.yaml

company_terms:
  - original: "AcmeCorp"
    replacement: "Company"
    category: "company_name"
    sensitivity: "HIGH"
  
  - original: "ProprietaryAlgorithm"
    replacement: "CustomAlgorithm"
    category: "algorithm"
    sensitivity: "CRITICAL"

credentials:
  - pattern: "API_KEY_[A-Z0-9]+"
    replacement: "REDACTED_API_KEY"
    category: "credential"
    sensitivity: "CRITICAL"

urls:
  - pattern: "https://internal\\.acme\\.com"
    replacement: "https://example.com"
    category: "url"
    sensitivity: "HIGH"

domain_terms:
  - original: "customer_acquisition_cost"
    replacement: "metric_a"
    category: "business_term"
    sensitivity: "MEDIUM"
```

## Key Benefits

1. **Safe Sharing:** Remove sensitive data before sharing code
2. **Reversible:** Complete mapping for reverse transformation
3. **Validated:** Ensures functionality preserved
4. **Auditable:** Full trail of all transformations
5. **Flexible:** User-approved mapping before transformation
6. **Comprehensive:** Handles code, docs, configs
