## 🏗️ Architectural Changes

### Tiered Planning System

**Current State (v3.8.1):**
- Template-based responses (62 templates in response-templates.yaml)
- Regex routing with ~70% accuracy
- Single execution mode (manual planning for all operations)

**Target State (v3.9.0 - Planning System):**
- Intelligent LLM-based routing with 95%+ accuracy
- 4-tier execution model:
  - **Tier 1 (Instant):** CLI operations, <2s deterministic tasks
  - **Tier 2 (Lightweight):** Single file changes, inline validation
  - **Tier 3 (Documented):** Feature additions, single MD structure
  - **Tier 4 (Complex):** Architecture changes, nested MD structure
- **Proactive Intelligence Engine:** Continuous enhancement recommendations without user prompting
- **Risk Assessment System:** Pre-execution impact analysis with dedicated risk templates
- **Domain-Aware Analysis:** Adaptive scanning depth based on domain criticality
  - **CRITICAL Domains:** Security, compliance, financial calculations, business logic → Deep AST analysis
  - **STANDARD Domains:** UI components, utilities, helpers → High-level analysis
  - **SIMPLE Domains:** Documentation, configuration → Surface-level validation
- Automatic refactor cycle: code cleanup, comment updates, debug removal
- Enhanced vacuum cycle: MD consolidation, filename optimization, multi-threaded
- Centralized version management from cortex.config.json

## 🛡️ Governance Framework

### New Brain Protection Rules (SKULL System)

**FILE_ORGANIZATION_ENFORCEMENT:**
- All documents in `cortex-brain/documents/{category}/`
- Filename limit: ≤20 characters (excluding extension)
- Prohibited: Root-level files in any directory
- Enforcement: Pre-execution validation

**TIERED_PLANNING_ENFORCEMENT:**
- Tier 1-2: Direct execution, lightweight tracking
- Tier 3-4: Formal planning required
- Routing: Automatic via complexity analyzer
- Override: Manual tier specification allowed

**VACUUM_CYCLE_ENFORCEMENT:**
- Automatic phase in system maintenance
- AST-powered similarity detection
- Targets: Duplicate code, orphaned tests, unused imports
- Schedule: Post-refactor, pre-release, monthly baseline

**INCREMENTAL_PLAN_CREATION_ENFORCEMENT:**
- Protocol: main → manifest → sub-plans (sequential)
- Prohibition: Bulk file creation
- Validation: One file per operation
- Purpose: Reduce token usage, improve quality

**PROGRESS_TRACKER_ENFORCEMENT:**
- Metrics: phase_start, phase_end, actual_time, elapsed_time
- Aggregates: overall_progress, total_actual, total_elapsed
- Updates: After each phase completion
- Location: Top of main plan file

**SENIOR_DEVELOPER_ESTIMATE_ENFORCEMENT:**
- Baseline: 40 hours/week
- Multipliers: testing (1.30) × documentation (1.15) × rework (1.10) = 1.55x
- Range: minimum (base × 1.55) to maximum (base × 2.06)
- Display: In progress tracker

**BIDIRECTIONAL_LINKING_ENFORCEMENT:**
- Sub-plans: Include breadcrumb navigation to main plan
- Main plan: Link to all sub-plans in phase table
- Format: Markdown relative links
- Purpose: Easy navigation, prevent orphaned plans
