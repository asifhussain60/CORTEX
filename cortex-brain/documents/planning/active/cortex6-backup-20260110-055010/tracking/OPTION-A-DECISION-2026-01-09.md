## 🎯 Decision Summary

**User selected Option A (Integrated) over Option B (Standalone)** for the Plan Viewer Dashboard implementation.

### Option A: Integrated Dashboard (SELECTED ✅)
- **Location:** Embedded in each plan's folder structure
- **Generation:** Auto-generated by Planning Orchestrator v6
- **Structure:** `{plan-name}/dashboard/` folder with index.html, app.js, styles.css, api.py
- **Deployment:** Manual launch via `python dashboard/api.py` (or `--dashboard-launch` flag)
- **Advantages:**
  - Co-located with plan (single folder, easy to find)
  - Automatically generated (no manual setup per plan)
  - Self-contained (dashboard/ folder has all assets)
  - Easy to share (copy plan folder = copy dashboard)

### Option B: Standalone Utility (NOT SELECTED ❌)
- **Location:** Central utility at `src/dashboard/` (plan-agnostic)
- **Usage:** `cortex dashboard {plan-name}`
- **Advantages:**
  - Single dashboard for all plans
  - Can compare multiple plans side-by-side
  - No duplication (one codebase)

## 🏗️ Implementation Impact

### Planning Orchestrator v6 Modifications Required

**New Capability: Dashboard Generation**

1. **Phase Addition:** After DoR completion, Planning Orchestrator v6 generates `dashboard/` folder
2. **Folder Structure:**
   ```
   {plan-name}/
   ├── dashboard/
   │   ├── index.html       # SPA entry point (Tailwind CSS + glassmorphism)
   │   ├── app.js           # Dashboard logic (WebSocket client, chart rendering)
   │   ├── styles.css       # Custom styles (glassmorphism theme)
   │   └── api.py           # FastAPI server (REST + WebSocket)
   ├── tracking/
   │   └── progress-tracker.json  # Live data source
   ├── artifacts/
   ├── context/
   └── reports/
   ```

3. **Launch Options:**
   - **Default:** Manual launch (`python {plan-name}/dashboard/api.py`)
   - **Auto-launch:** `cortex plan {feature} --dashboard-launch` (opens browser)
   - **Daemon mode:** `cortex plan {feature} --dashboard-daemon` (background server)

4. **Data Flow:**
   - Dashboard reads from `tracking/progress-tracker.json`
   - WebSocket watches for file changes (<100ms update latency)
   - No polling (push-based updates only)
