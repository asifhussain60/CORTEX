# Onboarding Dashboard Unification Plan

**Author:** Asif Hussain  
**Date:** December 9, 2025  
**Status:** 🔴 CRITICAL - Duplicate Dashboard Systems  
**Complexity:** HIGH

---

## 🎯 Problem Statement

**Current State:** CORTEX has TWO separate dashboard systems causing confusion:

### 1. **Admin Dashboard** (Production SPA)
- **Location:** `cortex-brain/dashboards/ui/index.html`
- **URL:** `http://localhost:8080/ui/index.html?source={repo}`
- **Technology:** Pure client-side JavaScript SPA
- **Features:**
  - 10+ tabs (Executive, Overview, Tech Stack, Architecture, etc.)
  - Source selector dropdown (admin can view any repo)
  - Data loader with registry
  - D3.js visualizations
  - Adaptive visibility
- **Data Source:** `/data/repos/{repo-slug}/` (generated by `DashboardOrchestrator`)
- **Used By:** Admin operations, system monitoring

### 2. **Project Onboarding Dashboard** (Legacy Jinja2)
- **Location:** `templates/project_onboarding_dashboard.html.j2`
- **Technology:** Jinja2 server-side rendering
- **Features:**
  - 5 tabs (Overview, Architecture, Quality, Security, Recommendations)
  - Static HTML generation
  - No source selector
- **Data Source:** Embedded in template at render time
- **Used By:** `DashboardRenderer` class (Clean Architecture)
- **Status:** ⚠️ NOT USED - OnboardingOrchestrator generates data but doesn't render this template

---

## 🔍 Root Cause Analysis

### OnboardingOrchestrator Flow (Current)

```python
1. Scan user repository
2. Collect dashboard data (6 JSON files)
3. Write to: cortex-brain/dashboards/{repo-slug}/
4. Return URL: "cortex-brain/dashboards/ui/index.html?source={repo-slug}"
5. ❌ PROBLEM: Admin dashboard URL requires source in /data/repos/ not /dashboards/
```

### Path Mismatch

**OnboardingOrchestrator outputs to:**
```
cortex-brain/dashboards/{repo-slug}/
├── health-data.json
├── tech-stack.json
├── security.json
├── architecture.json
├── code-organization.json
└── vendors.json
```

**Admin dashboard expects:**
```
cortex-brain/dashboards/data/repos/{repo-slug}/
├── overview.json
├── executive-summary.json
├── health-data.json
├── tech-stack.json
├── security.json
├── architecture.json
├── code-organization.json
└── vendors.json
```

**Issues:**
1. ❌ Wrong directory structure
2. ❌ Missing files (overview.json, executive-summary.json, reconciliation.json)
3. ❌ Source selector dropdown shown to users (should be admin-only)

## 🎯 Goals

1. **Single Dashboard System:** Admin dashboard serves ALL users (admin + user mode)
2. **User Mode:** No source selector, load only their data, simplified UI
3. **Admin Mode:** Full access, source selector, all features
4. **Unified Data Path:** OnboardingOrchestrator writes to correct location
5. **Complete Data Files:** Generate all required JSON files

## 📐 Solution Architecture

### 1. **Mode Detection**

Admin dashboard detects mode from URL:

```javascript
// URL patterns:
// Admin: http://localhost:8080/ui/index.html?source=mock
// User:  http://localhost:8080/ui/index.html?user=true&source={repo-slug}
```

### 2. **UI Adaptation**

```javascript
if (userMode) {
    // Hide source selector dropdown
    document.getElementById('sourceSelect').style.display = 'none';
    
    // Hide admin-only tabs (Executive, Reconciliation)
    hideAdminTabs();
    
    // Load only user's data
    const userRepo = getUrlParam('source');
    loadDashboardData(userRepo);
}
```

### 3. **Data Path Unification**

**OnboardingOrchestrator output:**
```
cortex-brain/dashboards/data/repos/{repo-slug}/
```

**DashboardOrchestrator output:**
```
cortex-brain/dashboards/data/repos/{repo-slug}/
```

Both use same path!
