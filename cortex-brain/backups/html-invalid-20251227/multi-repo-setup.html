How CORTEX Finds Your Workspace

sequenceDiagram
    participant User

1

Initial Detection

When you open a folder in VS Code, CORTEX checks cortex.config.json for workspace_roots

{
  "cortex_root": "D:/PROJECTS/CORTEX",
  "workspace_roots": [
    "D:/PROJECTS/MyReactApp",
    "D:/PROJECTS/PythonAPI"
  ]
}
2

Tier 3 Database Creation

If workspace is new, CORTEX creates isolated Tier 3 database:

cortex-brain/tier3/
├── workspace_d_projects_myreactapp.db
├── workspace_d_projects_pythonapi.db
└── workspace_d_projects_newproject.db  ← Auto-created
3

Context Segmentation

Each workspace gets isolated context:

  • File structure and dependencies
  • Test execution history
  • Coverage metrics
  • Plan execution state
4

Auto-Registration

New workspace automatically added to cortex.config.json:

# After opening new project:
{
  "workspace_roots": [
    "D:/PROJECTS/MyReactApp",
    "D:/PROJECTS/PythonAPI",
    "D:/PROJECTS/NewProject"  ← Added automatically
  ]
}

✅ Best Practices

🔒

Git Isolation (SKULL Rule #7)

CORTEX code NEVER commits to user repos:

  • Only .github/copilot-instructions.md in user repos
  • All Python code stays in CORTEX directory
  • Tests in CORTEX/tests/, not user repos
🧹

Clean Workspace Detection

Let CORTEX auto-detect instead of manual config:

  • Leave workspace_roots: [] empty
  • Open folders naturally in VS Code
  • CORTEX registers them automatically
  • No stale workspace references
💾

Backup Tier 3 Databases

Project-specific context is valuable:

  • Include cortex-brain/tier3/*.db in backups
  • Use upgrade cortex for safe upgrades
  • Tier 3 survives CORTEX reinstalls
🚀

Team Synchronization

For teams sharing knowledge:

  • Share Tier 0-2 brain (governance + knowledge)
  • Each dev has local Tier 3 (workspace context)
  • Weekly Tier 2 sync (learned patterns)
  • Central admin manages upgrades

🔧 Troubleshooting Multi-Repo Issues

❌ Wrong workspace detected

Symptom: CORTEX applies context from different project

Solution:

# Check current workspace in Copilot Chat:
"What workspace am I in?"

# Manually refresh workspace detection:
# Edit cortex.config.json → Remove wrong path from workspace_roots
# Reload VS Code window (Ctrl+Shift+P → "Reload Window")

❌ Tier 3 database locked

Symptom: "Database is locked" errors

Solution:

# Close all VS Code windows for that workspace
# Check for orphaned Python processes:
# Windows: taskkill /IM python.exe /F
# Mac/Linux: killall python

# Restart VS Code with single workspace

❌ Knowledge not shared across projects

Symptom: Each project learns from scratch

Solution:

# Verify Tier 2 knowledge graph shared:
# Check cortex.config.json:
{
  "brain_db_path": "cortex-brain/cortex-brain.db"  ← Same for all
}

# Force knowledge graph rebuild:
# In Copilot Chat: "rebuild knowledge graph"

❌ Too many workspace_roots entries

Symptom: Stale paths from deleted projects

Solution:

# Clean up workspace_roots manually:
# Edit cortex.config.json → Remove non-existent paths

# Or reset and let CORTEX re-detect:
{
  "workspace_roots": []  # Clear all
}

# Reopen active projects → Auto-registered
