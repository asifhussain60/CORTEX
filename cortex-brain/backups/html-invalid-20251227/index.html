🏗️ Tool Architecture

Design Principles

  • Composable: Tools work standalone or chained together
  • Idempotent: Safe to run multiple times without side effects
  • Validated: Each tool has comprehensive test coverage
  • Documented: Clear docstrings and usage examples
  • Integrated: Orchestrators invoke tools automatically

Example 2: Generate Documentation

# Generate HTML docs from Markdown
python -m cortex_toolkit.generators.doc_generator \
    --input cortex-brain/documents/ \
    --output docs/ \
    --theme glassmorphism

# Output: 80+ HTML pages with unified theme

Example 3: Analyze Test Coverage

# Run tests with coverage report
python -m cortex_toolkit.testing.coverage_analyzer \
    --source src/ \
    --tests tests/ \
    --threshold 80

# Output:
# Coverage: 94% (target: 80%)
# ✅ All orchestrators >90% coverage
# ⚠️  3 modules below threshold

Example 4: Validate Code Sanitization

    --directory src/proprietary/ \
    --mapping sanitization-map.json

🔨 Developing Custom Tools

Tool Template

# cortex_toolkit/custom/my_tool.py
from cortex_toolkit.base import BaseTool

class MyCustomTool(BaseTool):
    """
    Brief description of what this tool does.
    """
    
    def __init__(self, config: dict):
        super().__init__(config)
        self.name = "My Custom Tool"
        self.version = "1.0.0"
    
    def validate_inputs(self) -> bool:
        """Validate tool inputs before execution."""
        return True
    
    def execute(self) -> dict:
        """Main tool logic."""
        results = {
            "status": "success",
            "data": {},
            "metrics": {}
        }
        return results
    
    def generate_report(self, results: dict) -> str:
        """Generate human-readable report."""
        return f"Tool execution: {results['status']}"

# Usage
if __name__ == "__main__":
    tool = MyCustomTool(config={})
    results = tool.execute()
    print(tool.generate_report(results))
