What is TDD Mastery?

TDD Mastery is CORTEX's enforced Test-Driven Development workflow that ensures every code change follows the RED→GREEN→REFACTOR cycle. Unlike traditional TDD that relies on developer discipline, CORTEX automates verification at each phase—tests must fail before implementation, pass after implementation, and maintain coverage during refactoring.

This systematic approach prevents bugs, reduces technical debt, and creates living documentation through comprehensive test coverage.

The RED→GREEN→REFACTOR Cycle

🔴

RED: Write Failing Test

Test must fail before implementation

Purpose: Define expected behavior and prove the test can detect failures.

SKULL Rule: Tests MUST fail first. If test passes without implementation, the test is invalid and must be fixed.
Enforcement:
  • Run test with pytest
  • Verify failure message
  • Confirm failure reason
  • Block GREEN phase if passes
Example: def test_parse_feature(): # Test fails: parse_feature() # doesn't exist yet assert parse_feature("x") == {...}
🟢

GREEN: Make Test Pass

Implement minimal code to pass test

Purpose: Write simplest implementation to satisfy the test—no gold-plating.

Best Practice: Focus on making the test pass. Optimization comes in REFACTOR phase.
Enforcement:
  • Implement feature code
  • Run test with pytest
  • Verify test passes
  • Confirm no other tests break
Example: def parse_feature(yaml_str): # Minimal implementation data = yaml.safe_load(yaml_str) return data["feature"]
🔵

REFACTOR: Improve Code Quality

Optimize without changing behavior

Purpose: Clean up implementation—extract methods, remove duplication, improve readability.

Safety Net: Tests must continue passing during refactoring. Any failure indicates behavioral change.
Enforcement:
  • Improve code structure
  • Run full test suite
  • Verify 100% pass rate
  • Check coverage maintained
Example: def parse_feature(yaml_str): data = _load_yaml(yaml_str) return _extract_feature(data) # Tests still pass ✅

4-Layer Test Coverage

🧪 Unit Tests

Test individual functions/methods in isolation. Fast execution (<100ms), high coverage (80%+ target).

Location: tests/unit/

🔗 Integration Tests

Test component interactions. Validates orchestrators, agents, and brain tiers working together.

Location: tests/integration/

🎯 Functional Tests

Test complete workflows end-to-end. Validates planning, execution, and maintenance operations.

Location: tests/functional/

🚀 E2E Tests

Test real-world scenarios with actual repositories. Validates CORTEX behavior in production conditions.

Location: tests/e2e/

TDD Workflow Commands

Starting TDD Cycle

# In Copilot Chat
start tdd for [feature]

Initiates RED→GREEN→REFACTOR workflow with automated phase verification.

Running Tests

# Run all tests
pytest tests/

# With coverage
pytest --cov=src tests/

Executes test suite with coverage reporting and failure details.

Verifying Phases

# In Copilot Chat
verify red phase
verify green phase
verify refactor phase

CORTEX validates each phase completion before advancing to next.

Why TDD Mastery?

🛡️ Bug Prevention

Catch bugs before they reach production. Tests define correct behavior, implementation follows.

📚 Living Documentation

Tests document expected behavior better than comments—they're always up-to-date and executable.

🔄 Fearless Refactoring

Comprehensive tests provide safety net for code improvements. Refactor confidently.

⚡ Faster Development

Catch issues immediately rather than hours debugging later. TDD saves time long-term.
