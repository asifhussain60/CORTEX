🎓 Performance Concepts

N

N+1 Query Problem

"One query for the list, then one query per item = disaster."

🛒 Analogy: Going to the store 100 times for 100 items instead of one trip with a list.

O

Big O Notation

"How does performance scale as data grows?"

📈 O(n²): 10 items = 100 operations, 100 items = 10,000 operations. Ouch!

C

Caching

"Don't compute or fetch the same thing twice."

📝 Analogy: Writing down a phone number instead of looking it up every time.

PERF-01 CRITICAL C#

N+1 Query Problem: 101 Queries for 100 Orders

N+1 Queries — Fetching a list of orders, then lazily loading customer for each one. 100 orders = 1 query for orders + 100 queries for customers = 101 total queries!

❌ BEFORE OrderService.cs (N+1) 
public async Task<List<OrderDto>> GetRecentOrdersAsync()
{
    // Query 1: Get all orders
    var orders = await _context.Orders
        .Where(o => o.Date > DateTime.UtcNow.AddDays(-30))
        .ToListAsync();
    
    var result = new List<OrderDto>();
    foreach (var order in orders)
    {
        // Query 2, 3, 4... N+1: Load customer for EACH order!
        var customer = await _context.Customers
            .FindAsync(order.CustomerId);
        
        // Query N+2, N+3... 2N+1: Load items for EACH order!
        var items = await _context.OrderItems
            .Where(i => i.OrderId == order.Id)
            .ToListAsync();
        
        result.Add(MapToDto(order, customer, items));
    }
    return result;
    // 100 orders = 201 queries! 😱
}
✅ AFTER Eager Loading 
public async Task<List<OrderDto>> GetRecentOrdersAsync()
{
    // Single query with JOINs via Include
    var orders = await _context.Orders
        .Include(o => o.Customer)          // JOIN customers
        .Include(o => o.Items)             // JOIN order_items
            .ThenInclude(i => i.Product)   // JOIN products
        .Where(o => o.Date > DateTime.UtcNow.AddDays(-30))
        .AsNoTracking()                     // Read-only optimization
        .ToListAsync();
    
    return orders.Select(o => new OrderDto
    {
        Id = o.Id,
        CustomerName = o.Customer.Name,
        Items = o.Items.Select(i => new OrderItemDto
        {
            ProductName = i.Product.Name,
            Quantity = i.Quantity
        }).ToList()
    }).ToList();
    // 100 orders = 1 query! ✓
}

PERF-02 HIGH Angular

Observable Memory Leak: Subscriptions Never Unsubscribed

Memory Leak — Subscribing to Observables without cleanup causes subscriptions to pile up as components are created/destroyed. Eventually, the browser runs out of memory.

❌ BEFORE dashboard.component.ts 
@Component({ /* ... */ })
export class DashboardComponent implements OnInit {
  data: any[];
  
  ngOnInit() {
    // LEAK: Never unsubscribed!
    this.dataService.getData().subscribe(data => {
      this.data = data;
    });
    
    // LEAK: Another orphaned subscription
    interval(1000).subscribe(() => {
      this.updateTimestamp();
    });
    
    // LEAK: WebSocket subscription
    this.socketService.messages$.subscribe(msg => {
      this.handleMessage(msg);
    });
    
    // Component destroyed? Subscriptions keep running! 💀
  }
}
✅ AFTER Proper Cleanup 
@Component({ /* ... */ })
export class DashboardComponent implements OnInit, OnDestroy {
  private destroy$ = new Subject<void>();
  
  ngOnInit() {
    // Option 1: takeUntil pattern
    this.dataService.getData()
      .pipe(takeUntil(this.destroy$))
      .subscribe(data => this.data = data);
    
    // Option 2: async pipe in template (auto-unsubscribes)
    // <div *ngFor="let item of data$ | async">
    
    interval(1000)
      .pipe(takeUntil(this.destroy$))
      .subscribe(() => this.updateTimestamp());
    
    this.socketService.messages$
      .pipe(takeUntil(this.destroy$))
      .subscribe(msg => this.handleMessage(msg));
  }
  
  ngOnDestroy() {
    this.destroy$.next();
    this.destroy$.complete(); // Clean up all subscriptions!
  }
}

PERF-03 HIGH C#

Blocking I/O: Thread Pool Starvation

Sync-over-Async — Using synchronous file/network I/O blocks threads. Under load, all threads get blocked waiting for I/O, and the app becomes unresponsive.

❌ BEFORE FileService.cs 
public class FileService
{
    public string ReadConfig(string path)
    {
        // BLOCKING: Thread waits for disk I/O
        return File.ReadAllText(path);
    }
    
    public void ProcessFiles(string[] paths)
    {
        foreach (var path in paths)
        {
            // Each read blocks the thread
            var content = File.ReadAllText(path);
            var processed = ProcessContent(content);
            // Blocking write
            File.WriteAllText(path + ".out", processed);
        }
        // 100 files = thread blocked for entire duration
    }
    
    public byte[] DownloadFile(string url)
    {
        using var client = new WebClient();
        // BLOCKING: Thread waits for network
        return client.DownloadData(url);
    }
}
✅ AFTER Async I/O 
public class FileService
{
    public async Task<string> ReadConfigAsync(string path)
    {
        // NON-BLOCKING: Thread released during I/O
        return await File.ReadAllTextAsync(path);
    }
    
    public async Task ProcessFilesAsync(string[] paths)
    {
        // Process multiple files concurrently!
        var tasks = paths.Select(async path =>
        {
            var content = await File.ReadAllTextAsync(path);
            var processed = ProcessContent(content);
            await File.WriteAllTextAsync(path + ".out", processed);
        });
        
        await Task.WhenAll(tasks);
        // 100 files processed in parallel, threads not blocked
    }
    
    public async Task<byte[]> DownloadFileAsync(string url)
    {
        using var client = new HttpClient();
        return await client.GetByteArrayAsync(url);
    }
}
CORTEX Capability: System Refinement → Async conversion
PERF-04 MEDIUM Angular

Change Detection Overload: Re-rendering Everything

Default Change Detection — Angular's default strategy checks every component on every event. With large lists or complex trees, this causes visible lag and jank.

❌ BEFORE product-list.component.ts 
@Component({
  selector: 'app-product-list',
  template: `
    <div *ngFor="let product of products">
      <app-product-card [product]="product"></app-product-card>
    </div>
  `
  // Default change detection - checks ALL 1000 products
  // on EVERY click, scroll, or timer tick!
})
export class ProductListComponent {
  products: Product[] = [];  // 1000+ items
  
  // Expensive computation in template
  getDiscountedPrice(product: Product): number {
    // Called 1000+ times per change detection cycle!
    return this.calculateDiscount(product);
  }
}
✅ AFTER OnPush + TrackBy 
@Component({
  selector: 'app-product-list',
  template: `
    <cdk-virtual-scroll-viewport itemSize="50">
      <app-product-card 
        *cdkVirtualFor="let product of products; trackBy: trackById"
        [product]="product">
      </app-product-card>
    </cdk-virtual-scroll-viewport>
  `,
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class ProductListComponent {
  products$: Observable<Product[]>;
  
  // trackBy prevents re-creating DOM elements
  trackById(index: number, product: Product): number {
    return product.id;
  }
}

// Product card also uses OnPush
@Component({
  selector: 'app-product-card',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class ProductCardComponent {
  @Input() product: Product;
  // Only re-renders when product reference changes
}

TypeScript General
